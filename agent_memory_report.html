问题（Question）

LLM/VLM 智能体如何构建有效的记忆系统，使其能够在长期交互中积累经验、检索相关知识、并动态更新认知？不同记忆架构（工作记忆、长期记忆、情景记忆、语义记忆、程序记忆）各有何优劣？RAG 式、参数化、混合式记忆方案如何选择？具身智能场景下的空间-时序记忆有何特殊需求？

本报告从两个维度展开：

  1. 学术前沿：Agent Memory 领域核心论文与方法分类（MemGPT、HippoRAG、A-MEM、CoALA 等）
  2. 项目实现：三个具身导航/视觉记忆项目（Qiuchen/VimRAG、JanusVLN、Uni-NaVid）的算法设计、代码实现与评估效果

背景与动机（Background & Motivation）

大语言模型（LLM）的上下文窗口有限，无法天然支持跨会话的长期记忆。随着 LLM Agent 在复杂任务中的应用日益广泛——从多轮对话、代码生成到具身导航——记忆系统成为决定 Agent 能力上限的关键模块。

认知科学基础

人类认知科学将记忆分为多种类型，这一分类为 Agent 记忆系统设计提供了重要的理论框架：

  • 工作记忆（Working Memory）：前额叶皮层负责的短期信息保持，容量约 7±2 个组块（chunk）。对应 Agent 的上下文窗口。
  • 情景记忆（Episodic Memory）：海马体编码的具体经历与事件，带有时间-空间标签。对应 Agent 的交互轨迹记录。
  • 语义记忆（Semantic Memory）：新皮层存储的抽象知识与概念。对应 Agent 的知识库/知识图谱。
  • 程序记忆（Procedural Memory）：基底神经节编码的技能与操作流程。对应 Agent 的工具使用模板/SOP。

2023 年以来，Agent Memory 领域涌现大量工作，从 Stanford 的 Generative Agents 开创性地引入记忆流（Memory Stream）+ 反思（Reflection）机制，到 MemGPT 将操作系统虚拟内存概念引入 LLM，再到 HippoRAG 借鉴海马体索引理论构建知识图谱增强的 RAG，该领域正在快速发展。

具身智能中的记忆挑战

具身导航（Embodied Navigation）场景对记忆系统提出了额外要求：

  • 时空关联：记忆不仅有语义内容，还需绑定 3D 位置坐标和时间戳
  • 多模态融合：视觉帧、深度图、语言指令需要统一表示
  • 实时性约束：导航决策需要在毫秒级完成记忆检索
  • 长序列压缩：数百帧的观察历史需要高效压缩而不丢失关键信息

核心论文详解（Key Papers）

1. Generative Agents: Interactive Simulacra of Human Behavior (2023)

基本信息

  • 作者：Joon Sung Park, Joseph C. O'Brien, Carrie J. Cai, Meredith Ringel Morris, Percy Liang, Michael S. Bernstein
  • 机构：Stanford University, Google Research
  • 发表：UIST 2023 (ACM Symposium on User Interface Software and Technology)
  • 链接：arXiv:2304.03442

核心思想

本文是 Agent Memory 领域的开创性工作。作者构建了一个包含 25 个生成式智能体的沙盒小镇（Smallville），每个 Agent 拥有完整的记忆架构，能够自主规划日常活动、进行社交互动、形成观点并记住过往经历。

记忆架构

系统包含三个核心组件：

  1. 记忆流（Memory Stream）：以自然语言形式完整记录 Agent 的所有观察与经历，每条记忆附带时间戳和重要性评分（importance score, 1-10）
  2. 反思（Reflection）：Agent 定期对记忆流进行高层次抽象总结，生成更抽象的"反思"记忆节点，形成层次化记忆结构
  3. 规划（Planning）：基于记忆流和反思生成未来行动计划，计划本身也存入记忆流

检索机制

记忆检索基于三个因素的加权组合：

\[ \text{score}(m) = \alpha \cdot \text{recency}(m) + \beta \cdot \text{importance}(m) + \gamma \cdot \text{relevance}(m) \]

其中 recency 为指数时间衰减函数，importance 为 LLM 评估的重要性分数（1-10），relevance 为与当前查询的余弦相似度。

伪代码：反思机制

def reflect(agent, memory_stream):
    # 当累积重要性超过阈值时触发反思
    recent_memories = memory_stream.get_recent(n=100)
    total_importance = sum(m.importance for m in recent_memories)

    if total_importance > REFLECTION_THRESHOLD:
        # LLM 生成高层次洞察
        questions = llm.generate_questions(recent_memories)
        for q in questions:
            relevant = retrieve(memory_stream, query=q)
            insight = llm.synthesize(relevant)
            # 反思本身也存入记忆流，形成层次结构
            memory_stream.add(Memory(
                content=insight,
                type="reflection",
                importance=llm.rate_importance(insight)
            ))

关键结果

消融实验表明：移除反思机制后 Agent 行为可信度显著下降；移除记忆检索后 Agent 无法维持一致性人格。该工作证明了 LLM + 结构化记忆可以产生涌现的社会行为。

2. MemGPT: Towards LLMs as Operating Systems (2023)

基本信息

  • 作者：Charles Packer, Sarah Wooders, Kevin Lin, Vivian Fang, Shishir G. Patil, Ion Stoica, Joseph E. Gonzalez
  • 机构：UC Berkeley (Sky Computing Lab / BAIR)
  • 发表：arXiv 2023.10, 后续被 ICLR 2024 接收；团队创立 Letta 公司
  • 链接：arXiv:2310.08560

核心思想

将操作系统的虚拟内存管理概念引入 LLM，通过分层内存 + 自主内存管理函数调用，突破上下文窗口限制。LLM 被赋予"管理自身记忆"的能力，类似 OS 管理进程的虚拟地址空间。

记忆架构

┌─────────────────────────────────────────────┐ │ Main Context (RAM) │ │ ┌──────────┐ ┌──────────┐ ┌─────────────┐ │ │ │ System │ │ Core │ │ Conversation│ │ │ │ Prompt │ │ Memory │ │ Buffer │ │ │ └──────────┘ └──────────┘ └─────────────┘ │ ├─────────────────────────────────────────────┤ │ External Context (Disk) │ │ ┌──────────────┐ ┌────────────────────┐ │ │ │ Recall │ │ Archival Storage │ │ │ │ Storage │ │ (Vector DB) │ │ │ │ (对话全文索引)│ │ (长期知识库) │ │ │ └──────────────┘ └────────────────────┘ │ └─────────────────────────────────────────────┘ Agent 通过 function calling 自主执行: archival_memory_insert(content) archival_memory_search(query) conversation_search(query) core_memory_replace(old, new)

MemGPT 定义了类似 OS 的多级存储层次：

  1. 主上下文（Main Context）：类比 RAM，即 LLM 当前可见的 token 窗口，包含系统指令、对话历史摘要、工作数据
  2. 外部上下文（External Context）：类比磁盘，分为：
    • 回忆存储（Recall Storage）：完整对话历史的搜索索引
    • 归档存储（Archival Storage）：长期知识库，支持向量检索

存储/检索/更新机制

  • 存储：Agent 通过函数调用（function calling）主动将信息写入 archival/recall storage
  • 检索：Agent 自主决定何时从外部存储检索信息，通过 archival_memory_search、conversation_search 等函数
  • 更新：Agent 可修改 main context 中的 "core memory" 区域（如用户偏好），实现持久化人格/知识更新
  • 中断机制：类似 OS 中断，当 context 接近满时触发压缩/换出操作

关键结果

在文档分析任务中，MemGPT 能处理超出原生窗口的长文档；在多会话对话中，Agent 能跨会话记住用户信息并动态演化。该工作催生了 Letta 框架（开源 Agent 开发平台）。

3. CoALA: Cognitive Architectures for Language Agents (2023)

基本信息

  • 作者：Theodore R. Sumers, Shunyu Yao, Karthik Narasimhan, Thomas L. Griffiths
  • 机构：Princeton University
  • 发表：arXiv 2023.09（TMLR 2024 接收）
  • 链接：arXiv:2309.02427

核心思想

CoALA 是一个概念性框架（非具体系统），旨在系统化地组织 LLM Agent 的设计空间。它借鉴认知科学中的认知架构（Cognitive Architecture）传统（如 ACT-R、Soar），为语言智能体提供统一的描述语言。

记忆架构

CoALA 将 Agent 记忆分为：

  1. 工作记忆（Working Memory）：当前活跃的信息，对应 LLM 上下文窗口中的内容
  2. 长期记忆（Long-term Memory）：
    • 情景记忆（Episodic）：过去经历的具体记录（如交互日志）
    • 语义记忆（Semantic）：抽象知识与事实（如知识库、文档）
    • 程序记忆（Procedural）：行动策略与技能（如代码库、工具使用模板）

动作空间

CoALA 定义了两类动作：

  • 内部动作：对记忆的读/写操作（检索、存储、推理）
  • 外部动作：与环境交互（工具调用、API 请求、物理动作）

贡献

CoALA 为后续工作提供了统一的分析框架，使得不同 Agent 系统可以在同一维度下比较。其记忆分类体系被广泛引用。

4. HippoRAG: Neurobiologically Inspired Long-Term Memory for LLMs (2024)

基本信息

  • 作者：Bernal Jiménez Gutiérrez, Yiheng Shu, Yu Gu, Michihiro Yasunaga, Yu Su
  • 机构：Ohio State University (OSU NLP Group)
  • 发表：NeurIPS 2024
  • 链接：arXiv:2405.14831 | GitHub

核心思想

受海马体索引理论（Hippocampal Indexing Theory）启发，HippoRAG 模拟人类长期记忆的神经生物学机制。在人脑中，海马体作为"索引器"将分散在新皮层各区域的记忆片段关联起来；HippoRAG 用知识图谱（KG）模拟这一索引功能。

记忆架构

系统由三个组件模拟大脑结构：

  1. LLM（模拟新皮层处理）：负责从文档中提取开放信息（Open IE），生成知识三元组
  2. 知识图谱（模拟海马体索引）：无模式 KG 存储实体与关系，作为记忆的关联索引
  3. 个性化 PageRank（模拟记忆检索中的模式补全）：从查询实体出发，在 KG 上执行 Personalized PageRank 算法，找到相关的记忆片段

检索算法伪代码

def hipporag_retrieve(query, kg, passages):
    # 1. 从查询中提取实体（模拟海马体模式分离）
    query_entities = llm.extract_entities(query)

    # 2. 在 KG 中定位种子节点
    seed_nodes = kg.match_entities(query_entities)

    # 3. Personalized PageRank 扩散（模拟模式补全）
    personalization = {node: 1.0/len(seed_nodes) for node in seed_nodes}
    ppr_scores = pagerank(kg, personalization=personalization, alpha=0.5)

    # 4. 将节点分数映射回段落
    passage_scores = aggregate_node_scores_to_passages(ppr_scores)
    return top_k(passage_scores, k=5)

存储/检索/更新机制

  • 离线索引：对语料库进行 Open IE → 构建 KG → 建立实体到段落的映射
  • 在线检索：查询 → 实体识别 → KG 上 PPR 扩散 → 检索相关段落
  • 持续学习：新文档可增量加入 KG，无需重建整个索引

关键结果

在多跳问答（multi-hop QA）任务上显著优于标准 RAG 方法（如 ColBERT、Contriever）。HippoRAG 2（ICML 2025）进一步增强了段落集成和在线 LLM 使用效果。

5. A-MEM: Agentic Memory for LLM Agents (2025)

基本信息

  • 作者：Wujiang Xu, Zujie Liang, Kai Mei, Hang Gao, Juntao Tan, Yongfeng Zhang
  • 机构：Rutgers University 等
  • 发表：arXiv 2025.02（NeurIPS 2025 接收）
  • 链接：arXiv:2502.12110

核心思想

受卡片盒笔记法（Zettelkasten Method）启发，A-MEM 让 Agent 以"智能体方式"自主组织记忆。不同于被动存储，A-MEM 中的记忆是动态互联的知识网络，新记忆的加入会触发对已有记忆的更新与重组。

记忆架构

  1. 结构化笔记生成：每条记忆被组织为包含上下文描述、关键词、标签的结构化笔记
  2. 关联链接：新记忆加入时，系统自动识别与已有记忆的相关性并建立双向链接
  3. 记忆演化（Memory Evolution）：新记忆的整合可触发对历史记忆的上下文表示和属性的更新，使记忆网络持续精炼其理解

记忆演化伪代码

def add_memory(new_info, memory_graph):
    # 1. 生成结构化笔记
    note = Note(
        content=new_info,
        keywords=llm.extract_keywords(new_info),
        tags=llm.generate_tags(new_info),
        summary=llm.summarize(new_info)
    )

    # 2. 查找相关已有记忆
    related = memory_graph.search(note.keywords + note.tags)

    # 3. 建立双向链接
    for existing_note in related:
        memory_graph.add_link(note, existing_note)

    # 4. 记忆演化：更新相关旧记忆的表示
    for existing_note in related:
        existing_note.context = llm.update_context(
            existing_note, new_context=note
        )

    memory_graph.add(note)

存储/检索/更新机制

  • 存储：Agent 自主决定何时创建新记忆笔记，并自动生成元数据（关键词、标签、摘要）
  • 检索：基于关键词匹配 + 语义相似度 + 图结构遍历的多路检索
  • 更新：记忆演化机制——新信息可修改旧记忆的表示，实现知识的持续整合

关键结果

在 6 个基础模型上的测试表明，A-MEM 在记忆检索准确率和任务完成率上优于现有基线方法（如简单向量存储、摘要式记忆）。

6. Memory³: Language Modeling with Explicit Memory (2024)

基本信息

  • 作者：Hongkang Yang, Zehao Lin, Wenjin Wang, Hao Wu, Zhiyu Li, Bo Tang 等 16 位作者
  • 发表：Journal of Machine Learning, 3(2024), 300-346
  • 链接：arXiv:2407.01178

核心思想

Memory³ 提出 LLM 中存在三种记忆形式：

  1. 隐式记忆（Implicit Memory）：模型参数中编码的知识
  2. 工作记忆（Working Memory）：上下文中的 Key-Value 缓存
  3. 显式记忆（Explicit Memory）：本文新引入的第三种形式——外部化的知识片段，成本介于参数存储和 RAG 文本检索之间

记忆架构

  • 显式记忆格式：将知识编码为紧凑的向量表示（非原始文本），存储成本低于 RAG 的全文存储
  • 记忆电路理论（Memory Circuitry Theory）：解释显式记忆如何与模型参数交互
  • 稀疏化机制：使大规模记忆存储在计算上可行
  • 两阶段预训练：先训练基础模型，再训练记忆读取能力

关键结果

一个 2.4B 参数的 Memory³ 模型在性能上超越了更大的 LLM 和 RAG 模型，同时保持比 RAG 更高的解码速度。这表明显式记忆是一种高效的知识外部化方案。

7. ENGRAM: Effective, Lightweight Memory Orchestration (2025)

基本信息

  • 作者：Daivik Patel, Shrenik Patel
  • 发表：arXiv 2025.11
  • 链接：arXiv:2511.12960

核心思想

ENGRAM 证明了简单但精心设计的记忆分类 + 密集检索即可实现强大的长期记忆管理，无需复杂的知识图谱或多阶段检索管线。

记忆架构

将对话组织为三种规范记忆类型：

  • 情景记忆（Episodic）：具体事件与交互记录
  • 语义记忆（Semantic）：从对话中提取的事实与知识
  • 程序记忆（Procedural）：用户偏好的操作方式与流程

每条记忆通过单一路由器（Router）分类，使用标准化 schema 和 embedding 存入数据库。检索时对每种类型取 top-k 近邻，通过集合运算合并结果。

关键结果

在 LoCoMo（多会话对话 QA）基准上达到 SOTA；在 LongMemEval 上超越全上下文基线 15 分，同时仅消耗约 1% 的 token。

8. All-Mem: Agentic Lifelong Memory via Dynamic Topology Evolution (2026)

基本信息

  • 作者：Can Lv, Heng Chang, Yuchen Guo, Shengyu Tao, Shiji Zhou
  • 发表：arXiv 2026.03
  • 链接：arXiv:2603.19595

核心思想

解决长期交互中记忆退化问题。通过拓扑结构化记忆库和显式、非破坏性的记忆整合，避免摘要化带来的不可逆信息损失。

记忆架构

  • 三种记忆编辑算子：SPLIT（拆分）、MERGE（合并）、UPDATE（更新）
  • 保留编辑证据以支持可追溯性
  • 查询时通过类型化链接从活跃锚点进行有界扩展，控制检索延迟

三种检索模态的算法设计

1. 文本语义检索（Semantic Edge）

def search_by_text(query: str, memory_store, top_k=5):
    """
    语义检索：基于 caption 的向量相似度搜索
    创建 "Semantic Edge" 连接查询与记忆实体
    """
    query_embedding = encoder.encode(query)
    scores = []
    for entity in memory_store:
        caption_embedding = encoder.encode(entity["caption"])
        sim = cosine_similarity(query_embedding, caption_embedding)
        scores.append((entity, sim))
    return sorted(scores, key=lambda x: x[1], reverse=True)[:top_k]

2. 位置空间检索（Position Edge）

def search_by_position(position: List[float], memory_store, radius=5.0):
    """
    空间检索：基于 3D 欧氏距离的近邻搜索
    创建 "Position Edge" 用于拓扑推理
    """
    results = []
    query_pos = np.array(position)  # [x, y, z]
    for entity in memory_store:
        entity_pos = np.array(entity["position"])
        distance = np.linalg.norm(query_pos - entity_pos)
        if distance <= radius:
            results.append((entity, distance))
    return sorted(results, key=lambda x: x[1])

3. 时间检索（Time Edge）

def search_by_time(timestamp: float, memory_store, window=10.0):
    """
    时间检索：查找指定时间窗口内的记忆
    创建 "Time Edge" 用于时序推理
    """
    results = []
    for entity in memory_store:
        time_diff = abs(entity["time"] - timestamp)
        if time_diff <= window:
            results.append((entity, time_diff))
    return sorted(results, key=lambda x: x[1])

class VimRAGAgent(BaseAgent):
    """
    VimRAG: 构建动态 DAG（有向无环图）
    节点类型: root → intermediate → answer
    边类型: Semantic Edge / Position Edge / Time Edge
    """
    async def agent_rollout(self, query, memory_store):
        # 初始化 DAG
        dag = ActionGraph()
        root = dag.add_node(type="root", content=query)

        for step in range(self.max_steps):
            # 基于当前 DAG 状态决定下一步
            current_state = dag.serialize()
            response = await self.llm_client.generate(
                system_prompt=VIMRAG_SYSTEM_PROMPT,
                context=current_state
            )

            if is_answer_node(response):
                answer_node = dag.add_node(type="answer", content=response)
                dag.add_edge(dag.current, answer_node)
                return answer_node.content

            # 添加中间推理节点
            tool_name, tool_args = parse_action(response)
            result = await self.call_tool(tool_name, tool_args, memory_store)

            # 创建带类型的边
            edge_type = get_edge_type(tool_name)  # semantic/position/time
            intermediate = dag.add_node(
                type="intermediate",
                content=result,
                frames=extract_frames_base64(result)  # 多模态证据
            )
            dag.add_edge(dag.current, intermediate, edge_type=edge_type)

        return dag.best_path_answer()

核心算法：双记忆融合

数学形式

设第 \(t\) 步的视觉观察为 \(I_t\)，语义特征为 \(\mathbf{h}_t^{sem}\)，空间特征为 \(\mathbf{h}_t^{spa}\)，则融合表示为：

\[ \mathbf{h}_t = \mathbf{h}_t^{sem} + \lambda \cdot \text{VGGTMerger}(\mathbf{h}_t^{spa}) \]

其中 \(\lambda = 0.2\)，VGGTMerger 是一个两层 MLP：

\[ \text{VGGTMerger}(\mathbf{x}) = W_2 \cdot \text{GELU}(W_1 \cdot \text{RMSNorm}(\mathbf{x})) \]

输入维度 \(2048 \times 4 = 8192\)（spatial_merge_size=2 导致 4 个 patch 拼接），隐藏层 4096，输出 8192（匹配 LLM hidden_size）。

VGGTMerger 网络结构（src/qwen_vl/model/modeling_qwen2_5_vl.py, Line 149-164）

class VGGTMerger(nn.Module):
    """
    将 VGGT 空间特征投影到 LLM 隐藏空间
    Input:  2048 * (spatial_merge_size^2) = 8192
    Hidden: 4096
    Output: 8192 (LLM hidden_size)
    """
    def __init__(self, output_dim, hidden_dim, context_dim, spatial_merge_size=2):
        super().__init__()
        self.input_dim = context_dim * (spatial_merge_size ** 2)  # 2048*4=8192
        self.hidden_dim = hidden_dim   # 4096
        self.output_dim = output_dim   # 8192
        self.ln_q = Qwen2RMSNorm(context_dim, eps=1e-6)
        self.mlp = nn.Sequential(
            nn.Linear(self.input_dim, self.hidden_dim),
            nn.GELU(),
            nn.Linear(self.hidden_dim, self.output_dim),
        )

    def forward(self, x):
        x = self.ln_q(x)                    # RMSNorm 归一化
        x = x.view(-1, self.input_dim)       # 展平 patch 组
        return self.mlp(x)                   # MLP 投影

VGGT 通过 KV-Cache 实现时序记忆的高效管理。关键设计是 StartRecentKVCache 策略（src/qwen_vl/model/modeling_qwen2_5_vl.py, Line 1676-1681）：

class StartRecentKVCache:
    """
    保留最早的 start_size 帧 + 最近的 recent_size 帧
    丢弃中间帧，实现固定大小的时序记忆窗口

    设计直觉：
    - 起始帧提供参考坐标系（"我从哪里出发"）
    - 最近帧提供当��上下文（"我刚刚经过了什么"）
    - 中间帧可以被压缩/丢弃（信息冗余度高）
    """
    def __init__(self, start_size=8, recent_size=48, k_seq_dim=2, v_seq_dim=2):
        self.start_size = start_size
        self.recent_size = recent_size

    def __call__(self, past_key_values):
        """裁剪 KV-Cache 到固定大小"""
        pruned = []
        for kv in past_key_values:
            k, v = kv
            seq_len = k.shape[self.k_seq_dim]
            if seq_len <= self.start_size + self.recent_size:
                pruned.append((k, v))
            else:
                # 保留前 start_size + 后 recent_size
                k_pruned = torch.cat([
                    k[:, :, :self.start_size, :],
                    k[:, :, -self.recent_size:, :]
                ], dim=self.k_seq_dim)
                v_pruned = torch.cat([
                    v[:, :, :self.start_size, :],
                    v[:, :, -self.recent_size:, :]
                ], dim=self.v_seq_dim)
                pruned.append((k_pruned, v_pruned))
        return pruned

    def act(self, obs):
        current_frame = obs["rgb"]
        instruction = obs["instruction"]["text"]
        self.rgb_list.append(current_frame)

        # 均匀采样历史帧（最多 8 帧）
        history = self.rgb_list[:-1]
        if len(history) <= 8:
            images = history + [current_frame]
        else:
            # 线性插值选取 8 个均匀分布的历史帧
            indices = np.linspace(0, len(history) - 1, 8, dtype=int)
            images = [history[i] for i in indices] + [current_frame]

        action_text = self.model.call_model(images, instruction, self.step_id)
        return {"action": self.actions2idx[action_text]}

DAgger（Dataset Aggregation）是一种迭代式模仿学习算法，用于缓解分布偏移（distribution shift）问题：

# src/dagger.py - DAgger 数据收集流程伪代码
def dagger_collection(model, environments, oracle):
    """
    DAgger 迭代：
    1. 用当前模型收集轨迹
    2. 在轨迹上标注 oracle（最短路径）动作
    3. 将新数据加入训练集
    4. 重新训练模型
    """
    for iteration in range(num_iterations):
        trajectories = []
        for env in environments:
            obs = env.reset()
            while not done:
                action = model.predict(obs)
                obs, done = env.step(action)
                oracle_action = oracle.get_action(env.current_state)
                trajectories.append((obs, oracle_action))
        dataset.extend(trajectories)
        model.train(dataset)

Token 合并基础概念

Token 合并（Token Merging）是一种视觉 Transformer 加速技术，核心思想是：

  • 观察：视频中相邻帧的视觉 token 高度相似（尤其是静止或缓慢移动场景）
  • 方法：将相似的 token 合并为一个，用加权平均表示
  • 效果：减少序列长度，降低注意力计算的 \(O(n^2)\) 复杂度
  • 关键参数：相似度阈值（threshold）控制合并激进程度

核心算法：在线 Token 合并

数学形式

设帧序列 \(\{f_1, f_2, \ldots, f_T\}\)，每帧的 token 表示为 \(\mathbf{v}_i \in \mathbb{R}^{k \times d}\)（k 个 token，d 维）。

帧级均值表示：\(\bar{\mathbf{v}}_i = \frac{1}{k}\sum_{j=1}^k \mathbf{v}_i^{(j)}\)

合并判据：\(\cos(\bar{\mathbf{v}}_i, \bar{\mathbf{v}}_{i-1}) = \frac{\bar{\mathbf{v}}_i \cdot \bar{\mathbf{v}}_{i-1}}{|\bar{\mathbf{v}}_i| \cdot |\bar{\mathbf{v}}_{i-1}|} > \tau\)，其中 \(\tau = 0.985\)

加权合并：若合并，新表示为 \(\bar{\mathbf{v}}_{merged} = \frac{w_{old} \cdot \bar{\mathbf{v}}_{old} + \bar{\mathbf{v}}_{new}}{w_{old} + 1}\)，权重 \(w\) 记录已合并的帧数。

def process_tensor(self, tensor, length_threshold, similarity_threshold=0.985):
    """
    离线 Token 合并（训练时使用）
    将视频帧序列压缩为更短的表示

    Args:
        tensor: (n, k*nav_size, t) - n批次, k帧*每帧token数, 特征维度t
        length_threshold: 保留最近多少帧不压缩
        similarity_threshold: 合并阈值 (默认 0.985)
    """
    n, total, t = tensor.shape
    nav_size = self.nav_token_size  # 每帧 token 数
    k = total // nav_size           # 总帧数

    # 将 tensor 重塑为 (batch, frames, tokens_per_frame, feature_dim)
    split_tensors = tensor.view(n, k, nav_size, t)

    # 只对旧帧（前 k-length_threshold 帧）进行合并
    old_frames = split_tensors[:, :k - length_threshold, :, :]
    means_tensor = old_frames.mean(dim=2)  # 帧级均值: (n, old_k, t)

    cos = torch.nn.CosineSimilarity(dim=2)
    means = [means_tensor[:, 0:1, :]]  # 初始化：第一帧
    weights = [1]

    for i in range(1, k - length_threshold):
        last_mean = means[-1]
        current_tensor = means_tensor[:, i:i+1, :]
        similarity = cos(last_mean, current_tensor).mean(dim=0)

        if similarity > similarity_threshold:
            # 合并：加权平均
            new_weight = weights[-1] + 1
            new_mean = (last_mean * weights[-1] + current_tensor) / new_weight
            means[-1] = new_mean
            weights[-1] = new_weight
        else:
            # 不合并：保留为新的独立帧
            means.append(current_tensor)
            weights.append(1)

在线推理版本（uninavid_arch.py, Line 113-163）

def online_process_tensor(self, tensor, similarity_threshold=0.985):
    """
    在线 Token 合并（推理时使用）
    维护短期记忆（recent frames）和长期记忆��compressed history）

    与离线版本的区别：
    - 增量处理：每次只处理新到的一帧
    - 维护状态：self.long_term_memory, self.merge_weight
    - 实时性：单帧处理延迟低
    """
    current_frame_mean = tensor.mean(dim=1, keepdim=True)

    if self.long_term_memory is None:
        self.long_term_memory = current_frame_mean
        self.merge_weight = 1
    else:
        cos_sim = F.cosine_similarity(
            self.long_term_memory[:, -1:, :],
            current_frame_mean,
            dim=2
        ).mean()

        if cos_sim > similarity_threshold:
            # 合并到最后一个长期记忆条目
            w = self.merge_weight
            self.long_term_memory[:, -1:, :] = (
                self.long_term_memory[:, -1:, :] * w + current_frame_mean
            ) / (w + 1)
            self.merge_weight = w + 1
        else:
            # 创建新的长期记忆条目
            self.long_term_memory = torch.cat(
                [self.long_term_memory, current_frame_mean], dim=1
            )
            self.merge_weight = 1

视觉编码与网格压缩（uninavid_arch.py, Line 357-398）

def token_generation(self, vis_embed, image_counts=None, navigation=False):
    """
    视觉 token 生成：
    - 历史帧: grid:2 → 每帧 4 个 token (2x2 平均池化)
    - 当前帧: grid:8 → 每帧 64 个 token (保持高分辨率)

    设计理由：
    - 历史帧只需要粗粒度语义（"经过了什么"）
    - 当前帧需要细粒度感知（"现在看到什么"）
    """
    def process_grid(vis_embed, grid_size):
        cur_shape = int(vis_embed.shape[1] ** 0.5)  # 16 (256 patches = 16x16)
        vis_embed = vis_embed.reshape(
            vis_embed.shape[0], cur_shape, cur_shape, -1
        )
        grid_stride = cur_shape // grid_size
        vis_embed = F.avg_pool2d(
            vis_embed.permute(0, 3, 1, 2),
            kernel_size=grid_stride,
            stride=grid_stride
        )
        return vis_embed.permute(0, 2, 3, 1).flatten(1, 2)

    grid_size = int(self.config.compress_type.split('grid:')[-1])

    if navigation:
        vis_embed_nav = vis_embed[-1:]                    # 当前帧
        vis_embed_nav = process_grid(vis_embed_nav, 8)    # 8x8 = 64 tokens
        vis_embed = process_grid(vis_embed[:-1], grid_size)  # 历史: 2x2 = 4 tokens
    else:
        vis_embed = process_grid(vis_embed, grid_size)

    vis_embed = self.get_model().mm_projector(vis_embed)
    vis_embed_nav = self.get_model().mm_projector(vis_embed_nav) if navigation else None
    return vis_embed, vis_embed_nav

关键设计维度

设计 Agent Memory 系统时需考虑的核心权衡：

  • 容量 vs 延迟：存储越多检索越慢；需要分层/索引策略
  • 精确性 vs 泛化：原始记录 vs 摘要/抽象；摘要会丢失细节但提高泛化
  • 主动 vs 被动：Agent 自主管理记忆（MemGPT）vs 系统自动管理（ENGRAM）
  • 结构化 vs 非结构化：KG/图（HippoRAG）vs 纯文本/向量（标准 RAG）
  • 显式 vs 隐式：外部数据库（Qiuchen）vs 神经网络内部（JanusVLN/Uni-NaVid）
  • 固定窗口 vs 动态压缩：实现简单（JanusVLN KV-Cache）vs 信息保留（Uni-NaVid Token Merging）
