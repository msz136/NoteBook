Agent 轨迹奖励模型设计：从 Sandbox 评估到可微分 RL 损失的完整方案

技术报告 · 2026-05-28 · 具身机器人导航 Agent · 奖励模型 · 强化学习

1. 问题（Question）

在具身机器人导航 Agent 的训练中，我们面临两个核心问题：

  1. 如何为多轮工具调用轨迹设计奖励模型？ 机器人导航 Agent 在执行任务时会产生包含多次工具调用（如 move_forward、turn_left、check_obstacle 等）的轨迹序列。现有的 sandbox.score_trace() 函数通过六个维度的加权规则对轨迹打分，但这种规则式评估无法泛化到训练集之外的场景，也无法捕捉语义层面的质量差异。
  2. 如何将奖励信号接入可微分 RL 训练？ 规则式 loss 产出的是离散或稀疏信号，难以直接用于 GRPO、PPO 等策略梯度方法的训练。我们需要一套从 sandbox 评估到可学习奖励模型、再到可微分 RL 损失的完整方案。

本报告系统梳理奖励模型（Reward Model）的分类与设计方法，结合 sandbox 的六维度评估体系，提出针对具身导航 Agent 的混合奖励模型架构，并给出与 GRPO/PPO/MT-GRPO/GAGPO 等 RL 算法的接入方案。

2. 背景与动机（Background & Motivation）

2.1 Sandbox 评估体系：score_trace 的六维度加权 Loss

当前 server/agent/sandbox.py 中的 score_trace() 函数对 Agent 轨迹进行六个维度的规则式评估，最终输出一个加权综合分数：

# sandbox.py 中 score_trace 的核心逻辑（简化示意）
def score_trace(trajectory, reference):
    scores = {}

    # 1. sequence_loss (权重 0.35-0.40)：工具调用序列匹配
    #    检测缺失的工具调用（missing calls）和多余的工具调用（extra calls）
    scores['sequence_loss'] = compute_sequence_loss(
        trajectory.tool_calls, reference.expected_calls
    )

    # 2. arg_loss (权重 0.25-0.30)：参数匹配精度
    #    对每次工具调用的参数进行精确匹配或模糊匹配
    scores['arg_loss'] = compute_arg_loss(
        trajectory.tool_args, reference.expected_args
    )

    # 3. forbidden_loss (权重 0.15)：禁止工具使用惩罚
    #    检测是否调用了被禁止的工具（如危险操作）
    scores['forbidden_loss'] = compute_forbidden_loss(
        trajectory.tool_calls, reference.forbidden_tools
    )

    # 4. final_text_loss (权重 0.05)：最终响应内容质量
    #    评估 Agent 最终输出文本与参考答案的相似度
    scores['final_text_loss'] = compute_text_loss(
        trajectory.final_text, reference.expected_text
    )

    # 5. state_loss (权重 0.10)：机器人状态检查
    #    验证轨迹执行后机器人的状态是否符合预期
    scores['state_loss'] = compute_state_loss(
        trajectory.final_state, reference.expected_state
    )

    # 6. behavior_loss (权重 0.10)：行为序列检查
    #    检查行为的顺序约束是否满足（如先探测再移动）
    scores['behavior_loss'] = compute_behavior_loss(
        trajectory.behavior_sequence, reference.behavior_constraints
    )

    # 加权综合
    total = (0.375 * scores['sequence_loss'] +
             0.275 * scores['arg_loss'] +
             0.150 * scores['forbidden_loss'] +
             0.050 * scores['final_text_loss'] +
             0.100 * scores['state_loss'] +
             0.100 * scores['behavior_loss'])
    return total, scores

六个维度的详细说明如下：

维度权重评估内容信号类型
sequence_loss0.35–0.40工具调用序列的完整性：缺失调用（漏掉必要步骤）和多余调用（冗余操作）稀疏，基于集合匹配
arg_loss0.25–0.30每次工具调用的参数精度：数值参数的误差、字符串参数的精确匹配连续，可计算 MSE
forbidden_loss0.15是否调用了被明确禁止的工具（安全约束）二值，硬约束
final_text_loss0.05最终输出文本与参考答案的语义相似度连续，BLEU/BERTScore
state_loss0.10轨迹执行后机器人物理状态（位置、朝向、电量等）是否符合预期连续，状态向量距离
behavior_loss0.10行为序列的顺序约束（如"先感知再行动"的时序规则）稀疏，顺序约束检查

2.2 规则式 Loss 的局限性

尽管 score_trace 提供了结构化的评估框架，但规则式方法存在三个根本性局限：

  1. 泛化能力不足：规则基于预定义的参考轨迹，无法处理"不同但同样正确"的轨迹。例如，机器人可以通过不同路径到达同一目标，但规则式评估会惩罚偏离参考路径的行为。
  2. 梯度信号稀疏：sequence_loss 和 forbidden_loss 本质上是离散的集合操作，无法直接对 LLM 参数求梯度。即使使用 REINFORCE 估计梯度，方差也极高。
  3. 语义质量盲区：规则式评估无法捕捉"虽然工具调用序列不完全匹配，但 Agent 展现出了合理的推理过程"这类语义层面的质量差异。

2.3 与可微分 RL Loss 的关系

在 LLM Agent 的 RL 训练框架中，奖励模型（Reward Model, RM）产出的标量奖励 \( r \) 通过策略梯度方法反传到 LLM 参数。以 GRPO 为例：

\[ \mathcal{L}_{\text{GRPO}}(\theta) = -\mathbb{E}_{\tau \sim \pi_\theta} \left[ \sum_{t=1}^{T} \hat{A}_t \log \pi_\theta(a_t | s_t) - \beta \cdot \text{KL}(\pi_\theta \| \pi_{\text{ref}}) \right] \]

其中优势估计 \( \hat{A}_t \) 依赖于奖励模型的输出质量。规则式 score_trace 只能提供轨迹级的稀疏奖励，而神经奖励模型可以提供：

  • 密集奖励（Dense Reward）：每步工具调用后立即给出反馈，降低信用分配难度
  • 语义奖励：捕捉参考轨迹之外的合理行为
  • 可微分奖励：通过 Gumbel-Softmax 等技术实现端到端梯度传播

3. 奖励模型分类与选型

针对 Agent 轨迹评估，奖励模型可分为四大类：结果奖励模型（ORM）、过程奖励模型（PRM）、轨迹级偏好奖励模型，以及可微分奖励模型。以下逐一介绍其数学形式、训练方法及与 sandbox 的关系。

3.1 结果奖励模型（Outcome Reward Model, ORM）

定义与数学形式

结果奖励模型（ORM）对完整轨迹 \( \tau = (s_0, a_1, o_1, a_2, o_2, \ldots, a_T, y) \) 打一个标量分数：

\[ r_\theta(\tau) \in [0, 1] \]

其中 \( s_0 \) 为初始状态，\( a_t \) 为第 \( t \) 步的工具调用动作，\( o_t \) 为工具返回的观测，\( y \) 为最终文本输出。ORM 通常以 LLM 为骨干，在序列末尾添加一个线性头（value head）输出标量。

训练：Bradley-Terry 偏好模型

给定同一任务的两条轨迹 \( \tau^+ \)（好轨迹）和 \( \tau^- \)（差轨迹），Bradley-Terry 模型定义偏好概率：

\[ P(\tau^+ \succ \tau^-) = \frac{\exp(r_\theta(\tau^+))}{\exp(r_\theta(\tau^+)) + \exp(r_\theta(\tau^-))} = \sigma(r_\theta(\tau^+) - r_\theta(\tau^-)) \]

对比损失（Contrastive Loss）为：

\[ \mathcal{L}_{\text{BT}}(\theta) = -\mathbb{E}_{(\tau^+, \tau^-) \sim \mathcal{D}} \left[ \log \sigma(r_\theta(\tau^+) - r_\theta(\tau^-)) \right] \]

其中 \( \mathcal{D} \) 为偏好对数据集，可由 sandbox 的 score_trace 自动构造：score 高的轨迹作为 \( \tau^+ \)，score 低的轨迹作为 \( \tau^- \)。

与 sandbox score_trace 的关系

score_trace 本质上是一个规则式 ORM：它对完整轨迹输出一个 \([0,1]\) 的综合分数。这意味着我们可以直接用 score_trace 的输出作为标注信号，训练神经 ORM：

  • 运行 \( N \) 条轨迹，用 score_trace 自动标注得分
  • 构造偏好对：同一任务中，score 差异 \( > 0.3 \) 的轨迹对作为训练样本
  • 神经 ORM 学习泛化 score_trace 的评估逻辑到未见场景

代表性工作

WebRL（arXiv:2411.02337）提出自进化课程 ORM（Self-Evolving Curriculum ORM），通过迭代式数据收集不断扩充偏好对，使 ORM 随 policy 的提升而同步进化，避免奖励过时（reward staleness）问题。

ToolRM（arXiv:2509.11963）专门针对工具调用场景设计 ORM，将工具调用的正确性（tool correctness）和参数质量（argument quality）纳入奖励建模，在工具调用 Agent 的评估上显著优于通用 ORM。

3.2 过程奖励模型（Process Reward Model, PRM）

定义与数学形式

过程奖励模型（PRM）对轨迹中的每一步工具调用 \( (s_t, a_t, o_t) \) 单独打分：

\[ r_\theta^{\text{PRM}}(s_t, a_t, o_t) \in \mathbb{R}, \quad t = 1, 2, \ldots, T \]

PRM 提供密集奖励（Dense Reward），解决了 ORM 中信用分配（Credit Assignment）困难的问题。轨迹级综合分数可通过以下方式聚合：

  • 乘积聚合（Math-Shepherd 风格）：\( R(\tau) = \prod_{t=1}^{T} r_t \)，强调每步都必须正确
  • 最小值聚合：\( R(\tau) = \min_t r_t \)，关注最薄弱环节
  • 加权求和：\( R(\tau) = \sum_{t=1}^{T} \gamma^{T-t} r_t \)，时间折扣强调近期步骤

训练：蒙特卡洛 Rollout 标注

PRM 的训练标签难以直接获取（人工标注每步代价高昂）。Math-Shepherd（arXiv:2312.08935）提出用蒙特卡洛 rollout 自动标注：对轨迹中的每个中间状态 \( s_t \)，从该状态出发采样 \( K \) 条完整轨迹，用最终结果的成功率作为该步的 PRM 标签：

\[ \hat{r}_t = \frac{1}{K} \sum_{k=1}^{K} \mathbf{1}[\text{rollout}_k \text{ 成功}] \]

在 sandbox 环境中，"成功"可定义为 score_trace 超过阈值（如 \( > 0.7 \)）。

与 sandbox 的关系

sandbox 的 sequence_loss 和 arg_loss 天然具有步骤级（step-level）的结构：每次工具调用都可以独立评估其正确性。因此，这两个维度可以直接分解为 PRM 的训练信号：

  • sequence_loss → 工具选择正确性（tool selection score）：该步是否调用了正确的工具
  • arg_loss → 参数质量分数（argument quality score）：该步的参数是否正确
  • behavior_loss → 行为顺序分数（behavior ordering score）：该步是否满足顺序约束

代表性工作

AgentPRM（arXiv:2502.10325, arXiv:2511.08325）提出双维度 PRM 框架，同时建模前瞻承诺（Forward-Looking Commitment）和回顾进展（Backward-Looking Progress）：

\[ r_t^{\text{AgentPRM}} = \alpha \cdot \underbrace{P(\text{success} | s_t)}_{\text{前瞻承诺}} + (1-\alpha) \cdot \underbrace{\frac{P(\text{success}|s_t) - P(\text{success}|s_{t-1})}{1 - P(\text{success}|s_{t-1})}}_{\text{回顾进展}} \]

前瞻承诺衡量从当前状态出发的成功概率，回顾进展衡量该步相对于上一步的改善幅度。

Web-Shepherd（arXiv:2505.15277）专门针对网页导航 Agent 设计 PRM，将网页操作（点击、输入、滚动）的每一步分解为可独立评估的子任务，在 WebArena 等基准上取得 SOTA 性能。其核心创新是引入操作可行性评估（Action Feasibility Assessment），判断当前步骤在当前页面状态下是否可执行。

3.3 轨迹级偏好奖励模型

DPO/IPO 框架下的轨迹偏好学习

直接偏好优化（Direct Preference Optimization, DPO）将奖励模型隐式地编码在 policy 中，避免了显式训练 RM 的开销。对于轨迹偏好对 \( (\tau^+, \tau^-) \)，DPO 损失为：

\[ \mathcal{L}_{\text{DPO}}(\theta) = -\mathbb{E} \left[ \log \sigma \left( \beta \log \frac{\pi_\theta(\tau^+)}{\pi_{\text{ref}}(\tau^+)} - \beta \log \frac{\pi_\theta(\tau^-)}{\pi_{\text{ref}}(\tau^-)} \right) \right] \]

其中 \( \pi_\theta(\tau) = \prod_{t} \pi_\theta(a_t | s_t, \text{context}) \) 为轨迹的对数概率之和，\( \beta \) 控制与参考策略的偏离程度。

IPO（Identity Preference Optimization）在 DPO 基础上增加正则项，避免 policy 对偏好对过拟合：

\[ \mathcal{L}_{\text{IPO}}(\theta) = \mathbb{E} \left[ \left( \log \frac{\pi_\theta(\tau^+)}{\pi_{\text{ref}}(\tau^+)} - \log \frac{\pi_\theta(\tau^-)}{\pi_{\text{ref}}(\tau^-)} - \frac{1}{2\beta} \right)^2 \right] \]

BranPO：对比分支采样

BranPO（arXiv:2602.03719）针对多轮 Agent 轨迹提出分支对比采样（Branch Contrastive Sampling）策略。在轨迹的关键决策点（branching point）处，同时采样多条分支轨迹，构造细粒度的偏好对：

\[ \mathcal{L}_{\text{BranPO}} = -\sum_{b \in \mathcal{B}} \log \sigma \left( r_\theta(\tau^+_b) - r_\theta(\tau^-_b) \right) \]

其中 \( \mathcal{B} \) 为所有分支点的集合，\( \tau^+_b \) 和 \( \tau^-_b \) 为从分支点 \( b \) 出发的好/差轨迹。这种方法能精确定位导致轨迹质量差异的关键步骤。

用 sandbox 生成偏好对

sandbox 的 score_trace 为自动构造偏好对提供了天然的标注工具：

  1. 对同一导航任务，用不同温度参数采样多条轨迹
  2. 用 score_trace 对每条轨迹打分
  3. 构造偏好对：score 差异 \( > 0.3 \) 的轨迹对 \( (\tau_{\text{high}}, \tau_{\text{low}}) \)
  4. 数据格式：(prompt, trajectory_tokens_pos, trajectory_tokens_neg, score_diff)

3.4 可微分奖励模型

标准奖励模型产出的标量奖励通过 REINFORCE 估计梯度，方差高、样本效率低。可微分奖励模型通过松弛离散操作，实现奖励信号对 policy 参数的直接梯度传播。

GRADE：Gumbel-Softmax 松弛

GRADE（arXiv:2601.11574）使用 Gumbel-Softmax 技术将离散 token 选择松弛为连续操作，使奖励模型的梯度可以直接传回 policy：

\[ \tilde{a}_t = \text{Gumbel-Softmax}\left(\frac{\log \pi_\theta(\cdot | s_t)}{\tau}\right) \] \[ \mathcal{L}_{\text{GRADE}} = -r_\theta\left(\tau(\tilde{a}_{1:T})\right) \]

其中 \( \tau \) 为温度参数（随训练退火降低），\( \tilde{a}_t \) 为软化的动作表示。当 \( \tau \to 0 \) 时，Gumbel-Softmax 退化为 argmax（离散采样）；当 \( \tau \) 较大时，梯度可以顺畅传播。

ABPT：部分可微分奖励的修正反传

ABPT（Approximate Backpropagation Through, arXiv:2501.14513）针对奖励函数中存在不可微分组件（如规则检查、外部 API 调用）的情况，提出修正反传策略：

\[ \frac{\partial \mathcal{L}}{\partial \theta} \approx \frac{\partial r_{\text{diff}}}{\partial \theta} + \lambda \cdot \frac{\partial r_{\text{rule}}}{\partial \theta}\bigg|_{\text{STE}} \]

其中 \( r_{\text{diff}} \) 为可微分部分（如神经 ORM），\( r_{\text{rule}} \) 为规则部分（如 forbidden_loss），STE 表示直通估计器（Straight-Through Estimator）。这种方法特别适合 sandbox 场景：forbidden_loss 保留为硬约束，其余维度使用可微分神经网络建模。

TLCR：Token 级连续奖励

TLCR（Token-Level Continuous Reward, arXiv:2407.16574）将轨迹级奖励分解到每个 token 上，提供最细粒度的密集奖励信号：

\[ r_t^{\text{token}} = r_\theta(x_{1:t}) - r_\theta(x_{1:t-1}) \]

即第 \( t \) 个 token 的奖励为生成该 token 前后奖励模型输出的差值（奖励增量）。这种方法将轨迹级 ORM 转化为 token 级 PRM，无需额外的步骤级标注。

在 sandbox 场景中，TLCR 可以将 score_trace 的六维度综合分数分解到每个工具调用 token 上，为 GRPO/PPO 提供密集的 token 级奖励。

4. 针对 Sandbox Agent 的奖励模型设计方案

4.1 数据生成策略

利用现有 sandbox 环境，可以低成本地生成大规模标注数据：

轨迹采样与自动标注

  1. 多样化采样：对每个导航任务，使用不同温度参数（\( T \in \{0.3, 0.7, 1.0, 1.3\} \)）各采样 \( K \) 条轨迹，确保覆盖好/差轨迹的分布
  2. 自动标注：对每条轨迹运行 score_trace()，获得六维度分数和综合分数
  3. 数据过滤：保留综合分数 \( < 0.2 \)（差轨迹）和 \( > 0.6 \)（好轨迹）的样本，丢弃中间区域的模糊样本

偏好对构造

对同一导航任务的轨迹集合，按以下规则构造偏好对：

def construct_preference_pairs(trajectories_by_task, score_threshold=0.3):
    pairs = []
    for task_id, traj_scores in trajectories_by_task.items():
        sorted_trajs = sorted(traj_scores, key=lambda x: x[1], reverse=True)
        for i, (tau_pos, score_pos) in enumerate(sorted_trajs):
            for tau_neg, score_neg in sorted_trajs[i+1:]:
                if score_pos - score_neg >= score_threshold:
                    pairs.append({
                        "prompt": task_id,
                        "trajectory_pos": tau_pos,
                        "trajectory_neg": tau_neg,
                        "score_diff": score_pos - score_neg,
                        "step_scores_pos": tau_pos.step_scores,
                        "step_scores_neg": tau_neg.step_scores,
                    })
    return pairs

4.2 推荐架构：混合 ORM + PRM

针对具身导航 Agent 的特点（多轮工具调用、状态依赖、顺序约束），推荐采用混合 ORM + PRM 架构：

class HybridRewardModel(nn.Module):
    def __init__(self, base_model, hidden_dim=768):
        super().__init__()
        self.encoder = base_model  # 共享 LLM 骨干（如 Qwen2.5-7B）
        # PRM 头：对每步工具调用打分
        self.prm_head = nn.Sequential(
            nn.Linear(hidden_dim, 256), nn.ReLU(),
            nn.Linear(256, 1), nn.Sigmoid()
        )
        # ORM 头：对完整轨迹打分
        self.orm_head = nn.Sequential(
            nn.Linear(hidden_dim, 256), nn.ReLU(),
            nn.Linear(256, 1), nn.Sigmoid()
        )

    def forward(self, trajectory_tokens, step_boundaries):
        """
        trajectory_tokens: 完整轨迹的 token 序列
        step_boundaries: 每步工具调用结束位置的 token 索引列表
        """
        hidden_states = self.encoder(trajectory_tokens).last_hidden_state
        # PRM：提取每步工具调用结束位置的隐状态
        step_rewards = []
        for boundary_idx in step_boundaries:
            step_hidden = hidden_states[:, boundary_idx, :]
            step_rewards.append(self.prm_head(step_hidden))
        # ORM：使用序列末尾的隐状态
        r_episode = self.orm_head(hidden_states[:, -1, :])
        return r_episode, step_rewards

    def compute_combined_reward(self, trajectory_tokens, step_boundaries,
                                 alpha=0.5, beta=0.5, gamma=0.9):
        r_episode, step_rewards = self.forward(trajectory_tokens, step_boundaries)
        T = len(step_rewards)
        discounted = sum((gamma**(T-t-1)) * step_rewards[t] for t in range(T))
        R = alpha * r_episode + beta * discounted
        return R, r_episode, step_rewards

混合奖励的数学形式：

\[ R(\tau) = \alpha \cdot r_{\text{episode}}(\tau) + \beta \cdot \sum_{t=1}^{T} \gamma^{T-t} \cdot r_{\text{step}}(s_t, a_t, o_t) \]

其中 \( \alpha + \beta = 1 \)，推荐初始值 \( \alpha = 0.5, \beta = 0.5, \gamma = 0.9 \)。随着训练进行，可逐渐增大 \( \alpha \)（更依赖 ORM 的全局判断）。

4.3 与 Sandbox 六维度的对应关系

Sandbox 维度权重奖励模型组件建模方式说明
sequence_loss0.35–0.40PRM：工具选择分数神经 PRM，步骤级每步工具调用是否选择了正确的工具类型
arg_loss0.25–0.30PRM：参数质量分数神经 PRM，步骤级工具调用参数的精度，可用连续值建模
forbidden_loss0.15硬约束（保留规则式）规则检查，二值安全约束，不应被神经网络软化
final_text_loss0.05ORM：语义完成分数神经 ORM，轨迹级最终输出的语义质量，需要全局上下文
state_loss0.10ORM：状态一致性分数神经 ORM，轨迹级最终状态是否符合预期，依赖完整轨迹
behavior_loss0.10PRM：行为顺序分数神经 PRM，步骤级顺序约束可在每步后立即检查
设计原则：forbidden_loss 保留为规则式硬约束，因为安全约束不应被神经网络"学习绕过"。其余五个维度均可用神经网络建模，以获得更好的泛化能力。

4.4 可微分接入 GRPO/PPO

混合奖励模型可通过三种方案接入 RL 训练，适用于不同的场景需求：

方案 A：ORM 作为 Verifier，接入标准 GRPO

ORM 产出 \([0,1]\) 的连续分数，通过组内归一化转为优势估计，接入标准 GRPO：

def grpo_with_orm(policy, orm, prompts, group_size=8, beta=0.01):
    """方案 A：ORM 作为 Verifier 接入 GRPO，适合短轨迹（<10 turns）"""
    all_losses = []
    for prompt in prompts:
        trajectories = [policy.generate(prompt) for _ in range(group_size)]
        rewards = torch.tensor([orm(tau) for tau in trajectories])
        # 组内归一化（GRPO 核心）
        normalized = (rewards - rewards.mean()) / (rewards.std() + 1e-8)
        for tau, A_hat in zip(trajectories, normalized):
            log_probs = policy.log_prob(tau, prompt)
            ref_log_probs = policy.ref_log_prob(tau, prompt)
            kl = (log_probs - ref_log_probs).sum()
            all_losses.append(-(A_hat * log_probs.sum()) + beta * kl)
    return torch.stack(all_losses).mean()

方案 B：PRM 产出 Dense Reward，接入 MT-GRPO

PRM 为每个 turn 提供步骤级奖励，接入 MT-GRPO（Multi-Turn GRPO）的 turn-level advantage 计算：

def mt_grpo_with_prm(policy, prm, orm, prompts, group_size=8,
                      alpha=0.5, beta_kl=0.01, gamma=0.9):
    """方案 B：PRM Dense Reward 接入 MT-GRPO，适合长轨迹（10-30 turns）"""
    all_losses = []
    for prompt in prompts:
        trajectories = [policy.generate_multiturn(prompt) for _ in range(group_size)]
        for tau in trajectories:
            T = len(tau.turns)
            step_rewards = [prm(tau, t) for t in range(T)]
            episode_reward = orm(tau)
            combined = [alpha * episode_reward + (1-alpha) * step_rewards[t]
                        for t in range(T)]
            advantages = compute_gae(combined, gamma=gamma, lam=0.95)
            for t, (turn, A_t) in enumerate(zip(tau.turns, advantages)):
                log_probs = policy.log_prob_turn(turn, tau.context_up_to(t))
                ref_log_probs = policy.ref_log_prob_turn(turn, tau.context_up_to(t))
                kl = (log_probs - ref_log_probs).sum()
                all_losses.append(-(A_t * log_probs.sum()) + beta_kl * kl)
    return torch.stack(all_losses).mean()

def compute_gae(rewards, gamma=0.9, lam=0.95):
    """广义优势估计（Generalized Advantage Estimation, GAE）"""
    T = len(rewards)
    advantages, gae = [0.0]*T, 0.0
    for t in reversed(range(T)):
        next_val = rewards[t+1] if t < T-1 else 0
        delta = rewards[t] + gamma * next_val - rewards[t]
        gae = delta + gamma * lam * gae
        advantages[t] = gae
    return advantages

方案 C：GRADE 可微分奖励，端到端梯度传播

使用 Gumbel-Softmax 松弛，实现奖励模型梯度直接传回 policy 参数：

def grade_differentiable_reward(policy, reward_model, prompts,
                                  temperature=1.0, beta_kl=0.01):
    """方案 C：GRADE 可微分奖励，适合端到端联合训练"""
    all_losses = []
    for prompt in prompts:
        logits_seq = policy.forward(prompt)  # shape: (T, vocab_size)
        soft_tokens = []
        for logits in logits_seq:
            # Gumbel-Softmax 松弛（保持可微分）
            gumbel = -torch.log(-torch.log(torch.rand_like(logits) + 1e-20) + 1e-20)
            soft_tokens.append(F.softmax((logits + gumbel) / temperature, dim=-1))
        # 软化 token 嵌入
        soft_embs = [(s.unsqueeze(0) @ reward_model.embedding_matrix)
                     for s in soft_tokens]
        soft_traj = torch.cat(soft_embs, dim=1)
        reward = reward_model.score(soft_traj)  # 梯度可传回 logits
        with torch.no_grad():
            hard_tokens = logits_seq.argmax(dim=-1)
        kl = (policy.log_prob(hard_tokens, prompt)
              - policy.ref_log_prob(hard_tokens, prompt)).sum()
        all_losses.append(-reward + beta_kl * kl)
    return torch.stack(all_losses).mean()
方案梯度质量实现复杂度适用轨迹长度奖励信号密度
方案 A：ORM + GRPO中（REINFORCE 估计）低短（<10 turns）稀疏（轨迹级）
方案 B：PRM + MT-GRPO高（turn-level advantage）中中长（10-30 turns）密集（步骤级）
方案 C：GRADE 可微分最高（直接梯度）高任意密集（token 级）

5. 完整训练流程设计

5.1 离线阶段：奖励模型训练

奖励模型的训练分为数据生成、ORM 训练和 PRM 训练三个步骤：

步骤 1：用 Sandbox 生成训练数据

def generate_training_data(sandbox, policy, num_tasks=1000, samples_per_task=10):
    """
    离线数据生成流程
    目标：生成 10k+ 条标注轨迹用于奖励模型训练
    """
    all_trajectories = []

    for task in sandbox.get_tasks(num_tasks):
        task_trajectories = []

        # 多温度采样，确保轨迹多样性
        for temperature in [0.3, 0.7, 1.0, 1.3]:
            for _ in range(samples_per_task // 4):
                tau = policy.generate(task.prompt, temperature=temperature)

                # sandbox 自动标注
                total_score, dim_scores = sandbox.score_trace(tau, task.reference)

                # 步骤级标注（MC rollout）
                step_labels = compute_step_labels_mc(
                    sandbox, policy, tau, task, num_rollouts=5
                )

                task_trajectories.append({
                    "trajectory": tau,
                    "total_score": total_score,
                    "dim_scores": dim_scores,
                    "step_labels": step_labels,
                })

        all_trajectories.extend(task_trajectories)

    return all_trajectories


def compute_step_labels_mc(sandbox, policy, tau, task, num_rollouts=5):
    """
    蒙特卡洛 rollout 标注步骤级奖励（类 Math-Shepherd）
    对轨迹中每个中间状态，从该状态出发采样 K 条完整轨迹
    用最终成功率作为该步的 PRM 标签
    """
    step_labels = []
    for t in range(len(tau.steps)):
        # 从第 t 步的状态出发，继续采样
        partial_context = tau.get_context_up_to(t)
        success_count = 0
        for _ in range(num_rollouts):
            completion = policy.generate_from_context(partial_context, task.prompt)
            full_tau = tau.steps[:t] + completion.steps
            score, _ = sandbox.score_trace(full_tau, task.reference)
            if score > 0.7:  # 成功阈值
                success_count += 1
        step_labels.append(success_count / num_rollouts)
    return step_labels

步骤 2：训练 ORM（Bradley-Terry 对比损失）

def train_orm(orm_model, preference_pairs, num_epochs=3, lr=1e-5):
    """
    ORM 训练：Bradley-Terry 偏好模型
    输入：偏好对列表 [(tau_pos, tau_neg)]
    """
    optimizer = torch.optim.AdamW(orm_model.parameters(), lr=lr)

    for epoch in range(num_epochs):
        total_loss = 0
        for batch in DataLoader(preference_pairs, batch_size=16, shuffle=True):
            tau_pos = batch["trajectory_pos"]
            tau_neg = batch["trajectory_neg"]

            # 前向传播
            r_pos = orm_model(tau_pos)  # shape: (batch,)
            r_neg = orm_model(tau_neg)  # shape: (batch,)

            # Bradley-Terry 损失
            # L = -E[log sigma(r_pos - r_neg)]
            loss = -F.logsigmoid(r_pos - r_neg).mean()

            # 可选：加入分数差异加权
            score_diff = batch["score_diff"]
            loss = -(score_diff * F.logsigmoid(r_pos - r_neg)).mean()

            optimizer.zero_grad()
            loss.backward()
            torch.nn.utils.clip_grad_norm_(orm_model.parameters(), 1.0)
            optimizer.step()
            total_loss += loss.item()

        print(f"Epoch {epoch+1}: ORM Loss = {total_loss:.4f}")

    return orm_model

步骤 3：训练 PRM（步骤级回归损失）

def train_prm(prm_model, step_labeled_data, num_epochs=3, lr=1e-5):
    """
    PRM 训练：步骤级 MSE 回归
    输入：带步骤标签的轨迹数据
    """
    optimizer = torch.optim.AdamW(prm_model.parameters(), lr=lr)

    for epoch in range(num_epochs):
        total_loss = 0
        for batch in DataLoader(step_labeled_data, batch_size=8, shuffle=True):
            trajectory_tokens = batch["trajectory_tokens"]
            step_boundaries = batch["step_boundaries"]
            step_labels = batch["step_labels"]  # shape: (batch, T)

            # 前向传播
            _, step_rewards = prm_model(trajectory_tokens, step_boundaries)
            step_rewards_tensor = torch.stack(step_rewards, dim=1)  # (batch, T)

            # MSE 损失（也可用 BCE）
            loss = F.mse_loss(step_rewards_tensor.squeeze(-1), step_labels)

            optimizer.zero_grad()
            loss.backward()
            torch.nn.utils.clip_grad_norm_(prm_model.parameters(), 1.0)
            optimizer.step()
            total_loss += loss.item()

        print(f"Epoch {epoch+1}: PRM Loss = {total_loss:.4f}")

    return prm_model

步骤 4：验证奖励模型质量

用 Spearman 相关系数验证神经奖励模型与 score_trace 的一致性：

from scipy.stats import spearmanr

def validate_reward_model(orm_model, test_trajectories, sandbox):
    orm_scores = [orm_model(tau).item() for tau in test_trajectories]
    sandbox_scores = [sandbox.score_trace(tau, ref)[0]
                      for tau, ref in test_trajectories]
    corr, p_value = spearmanr(orm_scores, sandbox_scores)
    print(f"Spearman correlation: {corr:.4f} (p={p_value:.4f})")
    # 目标：corr > 0.8 表示奖励模型与 sandbox 高度一致
    return corr

5.2 在线阶段：RL 训练

根据轨迹长度和计算资源，选择不同的 RL 算法：

短轨迹（< 10 turns）：GRPO with ORM Reward

标准 GRPO 适合短轨迹场景，实现简单，计算开销低：

\[ \mathcal{L}_{\text{GRPO}} = -\frac{1}{G} \sum_{i=1}^{G} \hat{A}_i \log \pi_\theta(\tau_i | x) + \beta \cdot \text{KL}(\pi_\theta \| \pi_{\text{ref}}) \] \[ \hat{A}_i = \frac{r_{\text{ORM}}(\tau_i) - \mu_r}{\sigma_r}, \quad \mu_r = \frac{1}{G}\sum_j r_j, \quad \sigma_r = \sqrt{\frac{1}{G}\sum_j (r_j - \mu_r)^2} \]

中长轨迹（10-30 turns）：MT-GRPO with PRM Reward

MT-GRPO（Multi-Turn GRPO，arXiv:2505.11821）在每个 turn 计算独立的优势估计，解决长轨迹中的信用分配问题：

\[ \mathcal{L}_{\text{MT-GRPO}} = -\sum_{t=1}^{T} \hat{A}_t^{\text{turn}} \log \pi_\theta(a_t | s_t, c_t) + \beta \cdot \text{KL}_t \]

其中 \( \hat{A}_t^{\text{turn}} \) 为第 \( t \) 个 turn 的优势估计，由 PRM 的步骤级奖励通过 GAE 计算得到。

长序列（> 30 turns）：GAGPO with Dense PRM

GAGPO（Group Advantage Guided Policy Optimization）通过组内对比和密集 PRM 奖励，在长序列场景下取得最优性能：

\[ \mathcal{L}_{\text{GAGPO}} = -\sum_{t=1}^{T} \min\left(\rho_t \hat{A}_t, \text{clip}(\rho_t, 1-\epsilon, 1+\epsilon) \hat{A}_t\right) + \beta \cdot \text{KL} \]

其中 \( \rho_t = \pi_\theta(a_t) / \pi_{\text{old}}(a_t) \) 为重要性采样比，\( \epsilon \) 为 PPO clip 参数。

训练流程总览

def full_rl_training_pipeline(policy, orm, prm, sandbox,
                               num_iterations=100, trajectory_length_threshold=10):
    """
    完整 RL 训练流程
    自动根据轨迹长度选择合适的 RL 算法
    """
    for iteration in range(num_iterations):
        # 1. 采样轨迹
        prompts = sandbox.sample_tasks(batch_size=32)
        trajectories = [policy.generate_multiturn(p) for p in prompts]

        # 2. 计算奖励
        rewards = []
        for tau in trajectories:
            r_episode = orm(tau)
            r_steps = [prm(tau, t) for t in range(len(tau.turns))]
            # forbidden_loss 保留为规则式硬约束
            forbidden_penalty = sandbox.check_forbidden(tau)
            r_combined = 0.5 * r_episode + 0.5 * sum(r_steps) / len(r_steps)
            r_final = r_combined * (1 - forbidden_penalty)  # 违规则清零
            rewards.append(r_final)

        # 3. 根据轨迹长度选择 RL 算法
        avg_length = sum(len(tau.turns) for tau in trajectories) / len(trajectories)
        if avg_length < trajectory_length_threshold:
            loss = grpo_with_orm(policy, orm, prompts)
        else:
            loss = mt_grpo_with_prm(policy, prm, orm, prompts)

        # 4. 反向传播
        loss.backward()
        optimizer.step()
        optimizer.zero_grad()

        # 5. 定期更新奖励模型（自进化课程，参考 WebRL）
        if iteration % 10 == 0:
            new_data = generate_training_data(sandbox, policy, num_tasks=100)
            orm = train_orm(orm, construct_preference_pairs(new_data))
            prm = train_prm(prm, new_data)

        print(f"Iter {iteration}: loss={loss.item():.4f}, avg_reward={sum(rewards)/len(rewards):.4f}")

5.3 奖励 Hacking 防御

奖励 Hacking（Reward Hacking）是 RL 训练中的核心风险：policy 学会欺骗奖励模型而非真正完成任务。以下三种防御策略可组合使用：

KL 惩罚

在 RL 目标中加入与参考策略的 KL 散度惩罚，防止 policy 过度偏离预训练分布：

\[ \mathcal{L}_{\text{total}} = \mathcal{L}_{\text{RL}} + \beta \cdot \text{KL}(\pi_\theta \| \pi_{\text{ref}}) \]

推荐 \( \beta \in [0.01, 0.05] \)。\( \beta \) 过大会限制 policy 的探索能力，\( \beta \) 过小则无法防止奖励 hacking。

PRIME：隐式 PRM（避免奖励过拟合）

PRIME（arXiv:2502.01456）提出用语言模型本身的 token 概率作为隐式 PRM，避免显式训练 PRM 带来的过拟合风险：

\[ r_t^{\text{PRIME}} = \log \frac{\pi_{\text{ref}}(a_t | s_t)}{\pi_{\text{base}}(a_t | s_t)} \]

其中 \( \pi_{\text{ref}} \) 为经过 SFT 的参考策略，\( \pi_{\text{base}} \) 为预训练基础模型。这个比值衡量了 SFT 训练对该 token 的"偏好程度"，可作为步骤级奖励信号，无需额外训练 PRM。

DataPRM：三元奖励（区分探索性试错）

DataPRM（arXiv:2604.24198）提出三元奖励标签，区分三种步骤类型：

  • 正确步骤（+1）：直接推进任务完成的步骤
  • 探索性试错（0）：虽然不是最优路径，但展现了合理的探索行为
  • 错误步骤（-1）：导致任务失败或违反约束的步骤

三元标签避免了将"探索性试错"惩罚为"错误"，鼓励 Agent 在不确定情况下进行合理探索。在 sandbox 场景中，可以通过分析步骤的最终影响来自动分配三元标签：

def assign_ternary_label(step, trajectory, sandbox, task):
    """
    DataPRM 三元标签分配
    +1: 正确步骤（该步后成功率显著提升）
     0: 探索性试错（该步后成功率未变或轻微下降，但步骤本身合理）
    -1: 错误步骤（该步后成功率显著下降，或违反约束）
    """
    # 计算该步前后的成功率变化
    success_before = estimate_success_rate(sandbox, trajectory[:step], task)
    success_after = estimate_success_rate(sandbox, trajectory[:step+1], task)
    delta = success_after - success_before

    # 检查是否违反约束
    if sandbox.check_forbidden_at_step(trajectory[step]):
        return -1  # 违反安全约束，直接标为错误

    if delta > 0.1:
        return 1   # 显著提升，正确步骤
    elif delta > -0.1:
        return 0   # 轻微变化，探索性试错
    else:
        return -1  # 显著下降，错误步骤

6. 方法对比与选择建议

针对具身机器人导航 Agent 的不同训练阶段和资源约束，以下表格对四种主要奖励模型方案进行系统对比：

方案 适用场景 数据需求 梯度质量 实现复杂度 推荐 Loss 组合
仅 ORM 短轨迹（<10 turns），快速验证阶段 中（需要轨迹级偏好对，约 5k 对） 中（REINFORCE 估计，方差高） 低（单头 LLM + BT 损失） BT Loss + GRPO + KL 惩罚
仅 PRM 步骤可独立评估的任务，信用分配困难场景 高（需要步骤级标注，MC rollout 成本高） 高（密集奖励，低方差） 中（MC rollout 标注 + 步骤级训练） MSE/BCE Loss + MT-GRPO + GAE
ORM + PRM 混合（推荐） 中长轨迹（10-30 turns），生产环境 高（需要两种标注，但可共享骨干模型） 高（密集 + 全局信号互补） 中（双头架构，联合训练） BT + MSE + MT-GRPO/GAGPO + KL
可微分 RM（GRADE） 端到端优化，RM 与 policy 联合训练 低（无需显式标注，直接优化） 最高（直接梯度传播） 高（Gumbel-Softmax + 联合训练） GRADE Loss + 直接梯度 + KL

6.1 针对 Sandbox 场景的具体建议

阶段一：快速验证（1-2 周）

使用仅 ORM + 标准 GRPO方案：

  1. 用 sandbox 生成 5k 条轨迹，score_trace 自动标注
  2. 构造 2k 偏好对，训练 ORM（Qwen2.5-7B 骨干，Bradley-Terry 损失）
  3. 验证 ORM 与 score_trace 的 Spearman 相关性（目标 > 0.75）
  4. 接入 GRPO 训练，观察 policy 在 sandbox 上的分数提升

阶段二：性能提升（3-4 周）

升级为混合 ORM + PRM + MT-GRPO方案：

  1. 在阶段一数据基础上，增加 MC rollout 步骤级标注（每条轨迹 5 次 rollout）
  2. 训练 PRM（与 ORM 共享骨干，双头架构）
  3. 切换到 MT-GRPO，使用 turn-level advantage
  4. 加入 PRIME 隐式 PRM 作为辅助奖励，防止奖励 hacking

阶段三：长序列优化（5-8 周）

针对 30+ turns 的复杂导航任务，升级为GAGPO + DataPRM方案：

  1. 引入 DataPRM 三元标签，区分探索性试错和真正错误
  2. 使用 GAGPO 的 clip 机制处理长序列的梯度稳定性
  3. 实现 WebRL 风格的自进化课程：每 10 次迭代更新奖励模型
  4. 可选：引入 BranPO 的分支对比采样，精确定位关键决策点

6.2 关键超参数建议

超参数推荐值说明
ORM 权重 \( \alpha \)0.4–0.6初始 0.5，随训练进行逐渐增大

Gumbel 温度（GRADE）从 1.0 退火到 0.1训练初期高温保证梯度流动，后期低温接近离散采样
