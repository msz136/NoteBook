背景与动机（Background & Motivation）

传统的 LLM 强化学习（LLM-RL）主要用于对齐（Alignment），如 RLHF/DPO，其核心假设是单步 MDP：给定 prompt，模型生成一个完整回复，获得一个标量奖励。这种范式将 LLM 视为被动的序列生成器。

然而，随着 LLM Agent 的兴起——模型需要在复杂环境中进行多轮交互、调用工具、搜索信息、执行代码——传统单步 MDP 框架已不再适用。Agentic RL（智能体强化学习）应运而生，它将 LLM 重新定义为自主决策智能体，嵌入到动态、部分可观测的环境中，通过时间扩展的 POMDP 进行建模 [1]。

传统 LLM-RL（RLHF/DPO）

  • 退化的单步 MDP
  • 一次生成完整回复
  • 奖励来自人类偏好/奖励模型
  • 无环境交互
  • Token 级别优化

Agentic RL

  • 时间扩展的 POMDP
  • 多轮交互、多步决策
  • 奖励来自环境反馈（任务成功/失败）
  • 与工具/API/环境持续交互
  • Turn/Step 级别优化

根据 2025 年的综述论文 [1]，Agentic RL 围绕六大核心能力展开：规划（Planning）、工具使用（Tool Use）、记忆（Memory）、推理（Reasoning）、自我改进（Self-improvement）、感知（Perception）。该综述综合了超过 500 篇近期工作。

核心算法与损失函数（Core Algorithms & Loss Functions）

2.1 PPO（Proximal Policy Optimization）及其变体

PPO 是 LLM 对齐中最主流的 RL 算法，因其稳定性和可靠性被广泛采用 [1]。其核心损失函数为：

PPO-Clip 目标函数：

\[ L^{PPO}(\theta) = -\mathbb{E}\left[\min\left(\frac{\pi_\theta(a|s)}{\pi_{\theta_{old}}(a|s)} A^{\pi_{\theta_{old}}}(s,a),\; \text{clip}\left(\frac{\pi_\theta(a|s)}{\pi_{\theta_{old}}(a|s)}, 1-\epsilon, 1+\epsilon\right) A^{\pi_{\theta_{old}}}(s,a)\right)\right] \]

其中 \(\epsilon\) 为裁剪范围（通常 0.1-0.2），\(A\) 为优势函数。

Turn-PPO：面向多轮 Agent 的 PPO 变体

Zhou et al. (2024) [2] 提出 Turn-PPO，将 MDP 建模从 token 级别提升到 turn（轮次）级别。核心思想：

  • 传统 PPO 在 token 级别计算优势函数，每个 token 都有独立的 advantage 估计
  • Turn-PPO 将每个 agent 交互轮次视为一个原子动作，在 turn 级别进行优势估计和策略更新
  • 更好地捕获多轮推理任务的层次结构
  • 在 WebShop 和 Sokoban 基准上优于 GRPO 和标准 PPO

2.2 GRPO（Group Relative Policy Optimization）

GRPO 由 DeepSeek 团队提出 [3]，是 DeepSeek-R1 训练的核心算法。其关键创新是无需 Critic 模型，通过组内比较估计优势：

GRPO 优势计算：

\[ A_i = \frac{r_i - \text{mean}(\{r_1, r_2, \ldots, r_G\})}{\text{std}(\{r_1, r_2, \ldots, r_G\})} \]

对每个 prompt \(q\)，采样 \(G\) 个回复 \(\{o_1, \ldots, o_G\} \sim \pi_{\theta_{old}}\)，计算各自奖励后进行组内标准化。

GRPO 完整损失函数：

\[ L^{GRPO}(\theta) = -\mathbb{E}_{q, \{o_i\}}\left[\frac{1}{G}\sum_{i=1}^{G}\min\left(\frac{\pi_\theta(o_i|q)}{\pi_{\theta_{old}}(o_i|q)} A_i,\; \text{clip}\left(\frac{\pi_\theta(o_i|q)}{\pi_{\theta_{old}}(o_i|q)}, 1-\epsilon, 1+\epsilon\right) A_i\right) - \beta D_{KL}(\pi_\theta \| \pi_{ref})\right] \]

其中 \(\beta\) 控制 KL 散度惩罚强度（DeepSeekMath 中 \(\beta=0.04\)）。

GRPO 的优势：

  • 无需训练单独的 Critic/Value 模型，显著降低计算成本
  • 适用于可验证任务（数学推理、代码生成等）
  • 通过组内对比自然实现相对优势估计

GRPO 在 Agent 场景的局限：

  • 多轮交互中，组内采样的方差可能很大
  • 长轨迹下信用分配困难
  • 稀疏奖励导致大量零优势样本 [4]

2.3 GiGPO（Group-in-Group Policy Optimization）

Feng et al. (2025) [5] 提出 GiGPO，专门解决长时域 LLM Agent 的信用分配问题（NeurIPS 2025）。核心思想是两层优势估计架构：

  • 外层（Macro）：在轨迹级别进行组间比较，评估整体策略质量
  • 内层（Micro）：在步骤级别进行组内比较，实现细粒度信用分配
  • 利用组统计量同时计算宏观和微观优势
  • 在 ALFWorld 和 WebShop 基准上取得显著提升，且不增加计算开销

2.4 DPO 及其多轮扩展

标准 DPO（Direct Preference Optimization）[6] 通过隐式奖励模型直接优化偏好：

DPO 损失函数：

\[ L^{DPO}(\theta) = -\mathbb{E}_{(x, y_w, y_l)}\left[\log \sigma\left(\beta \log\frac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)} - \beta \log\frac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)}\right)\right] \]

其中 \(y_w\) 为偏好回复，\(y_l\) 为非偏好回复。

DMPO（Direct Multi-Turn Preference Optimization）

Shi et al. (2024) [7] 提出 DMPO（EMNLP 2024），解决 DPO 在多轮场景中的关键问题——配分函数无法消除：

  • 用状态-动作占用度量（state-action occupancy measure）约束替代策略约束
  • 使配分函数独立于当前状态
  • 引入长度归一化处理变长轨迹

层次化偏好学习（Hierarchical Preference Learning）

2025 年 ICLR 论文 [8] 指出：

  • 轨迹级 DPO：信号过于粗糙，无法精确分配信用
  • 步骤级 DPO：过于短视，无法捕获多步行为的价值
  • 提出层次化方法，在轨迹和步骤之间取得平衡

2.5 VSPO（Value-based Sampling Policy Optimization）

VSPO [9] 是 GRPO 的增强变体，专为 Agentic RL 设计：

  • 渐进式奖励塑形（Progressive Reward Shaping）：逐步增加任务难度
  • 基于价值的采样：用任务价值指标（平衡难度和不确定性）替换零优势样本
  • 价值平滑裁剪（Value-smoothing Clipping）：稳定梯度更新

2.6 SAPO（Step-Aligned Policy Optimization）

2025 年提出的 SAPO [10] 专门针对 Agentic RL 中的步骤对齐问题：

  • 将优化过程与 agent 的决策步骤对齐
  • 在步骤边界处进行优势估计和策略更新
  • 适用于 OpenClaw、Claude Code 等实际 agent 系统

2.7 Flow-GRPO

NeurIPS 2025 论文 "In-the-Flow Agentic System Optimization" [11] 提出 Flow-GRPO：

  • 将多轮优化问题转化为流式优化
  • 解决长时域、稀疏奖励下的信用分配问题
  • 适用于规划和工具使用场景

2.8 算法对比总结

算法是否需要 Critic优势估计粒度适用场景关键特点
PPO是Token 级通用对齐稳定但计算开销大
Turn-PPO是Turn 级多轮 Agent层次化 MDP
GRPO否Token 级（组内）可验证推理任务无 Critic，组内对比
GiGPO否两层（轨迹+步骤）长时域 Agent细粒度信用分配

SAPO否Step 级Agentic 系统步骤对齐优化
Flow-GRPO否流式规划/工具使用多轮转流式优化

奖励设计与信用分配（Reward Design & Credit Assignment）

3.1 工具使用 Agent 的奖励塑形

工具使用 Agent 面临独特的奖励设计挑战：动作空间包含自然语言推理和结构化工具调用，且工具执行结果具有延迟性。

Search-R1：搜索 Agent 的 RL 训练

Search-R1 [12] 是一个里程碑式的工作，训练 LLM 自主生成搜索查询并利用检索结果：

  • 奖励设计：简单的结果级奖励（outcome-based reward），基于最终答案正确性
  • 关键技术——检索 Token 掩码（Retrieved Token Masking）：在 RL 训练中掩码检索到的文本 token，避免模型对检索内容的梯度更新，稳定训练
  • 训练框架：基于 veRL，支持多轮搜索交互
  • 在多跳问答任务上显著优于无搜索基线

R1-Searcher：两阶段搜索能力训练

R1-Searcher [13] 提出两阶段 outcome-based RL 方法：

  • 第一阶段：训练模型学会何时调用搜索
  • 第二阶段：训练模型优化搜索查询质量
  • 使 LLM 自主决定是否需要外部知识

ReTool：战略性工具使用的 RL

ReTool [14] 训练 LLM 在推理过程中战略性地使用代码工具：

  • 冷启动数据生成：合成代码增强的长链推理轨迹
  • RL 微调：基于结果奖励优化工具调用策略
  • ReTool-32B 达到 72.5% 准确率，超越 OpenAI o1-preview 27.9%
  • 涌现出代码自我修正等行为

Nemotron-Research-Tool-N1

NVIDIA 的 Nemotron-Research-Tool-N1 [15] 受 DeepSeek-R1 启发，使用基于规则的 RL 训练工具使用模型：

  • 规则奖励：工具调用格式正确性 + 最终答案正确性
  • 无需人工标注的工具使用偏好数据

3.2 过程奖励模型（Process Reward Model, PRM）

过程奖励模型为 Agent 提供步骤级反馈，解决稀疏奖励下的信用分配瓶颈 [16]。

Agent Process Reward Model (AgentPRM)

AgentPRM [16] 提供决策级别的逐步反馈：

  • 在每个 agent 决策点评估当前步骤的质量
  • 解决时间信用分配瓶颈
  • 比纯结果奖励提供更密集的学习信号

在线过程奖励学习（Online Process Reward Learning）

2025 年的工作 [17] 将过程监督集成到 agent 在线学习中：

  • 解决离线标注的偏差问题
  • 避免过细粒度信号导致的高方差
  • 处理状态覆盖不足的问题

混合奖励归一化（Hybrid Reward Normalization）

针对不可验证的 Agentic 任务 [18]：

  • 过程奖励评估中间步骤，提供细粒度监督
  • 混合归一化平衡过程奖励和结果奖励
  • 鼓励基于事实的问题解决

3.3 信用分配（Credit Assignment）

长轨迹中的信用分配是 Agentic RL 的核心挑战。2025 年的综述 [19] 系统梳理了 LLM RL 中的信用分配方法：

信用分配的三个层次

  1. Token 级：每个 token 获得独立的信用分配（传统 PPO）
  2. Turn/Step 级：每个交互轮次作为信用分配单元（Turn-PPO, GiGPO）
  3. 轨迹级：整条轨迹获得统一奖励（GRPO, DPO）

CALM（Credit Assignment with Language Models）

CALM [20] 利用 LLM 自动化信用分配：

  • 通过奖励塑形和潜在奖励分解实现自动信用分配
  • LLM 作为信用分配器，评估每步贡献

可验证过程奖励（Verifiable Process Rewards）

2025 年的最新工作 [21] 提出可验证的过程奖励用于 Agentic 推理：

  • RLVR（Reinforcement Learning from Verifiable Rewards）通常依赖稀疏的结果级反馈
  • 可验证过程奖励在中间步骤提供可验证的密集信号
  • 无需人工标注即可获得步骤级监督

关键论文与方法（Key Papers & Approaches）

4.1 Agent Q：MCTS + DPO 的 Agent 训练

Agent Q [22]（2024）是 Agent RL 领域的重要工作，结合蒙特卡洛树搜索与偏好优化：

  • 方法：引导式 MCTS 探索 + 自我批评 + 离策略 DPO 迭代微调
  • 核心创新：从成功和失败轨迹中同时学习，克服静态数据集 SFT 的局限
  • 结果：Llama-3 70B 在预订任务上从 18.6% 提升到 81.7%（一天数据收集），加入在线搜索后达 95.4%
  • 意义：证明了 RL 在交互式 Agent 任务中的巨大潜力

4.2 AgentRL：可扩展的多轮多任务框架

AgentRL [23]（2025）提出了可扩展的 Agentic RL 训练基础设施：

  • 基础设施：全异步生成-训练流水线、统一函数调用 API、容器化环境
  • 算法创新：
    • 跨策略采样（Cross-policy Sampling）：增强多轮交互中的探索
    • 任务优势归一化（Task Advantage Normalization）：稳定多任务训练
  • 结果：在 5 个 Agent 任务上显著超越 GPT-5、Claude-Sonnet-4、DeepSeek-R1
  • 多任务训练：达到与最佳任务特定模型匹配的性能

4.3 端到端 RL 训练 LLM Agent

2025 年的系统性工作 [24] 重新审视了 LLM Agent 的 RL 方法论：

  • 系统扩展 MDP 框架以全面覆盖 LLM Agent 场景
  • 提出端到端 RL 训练范式，区别于分阶段训练
  • 讨论 DigiRL（数字环境 RL）和 ArCHer（层次化 RL）等方法

4.4 Re-ReST：反思增强的自训练

Re-ReST [25]（EMNLP 2024）提出反思增强的自训练方法：

  • 核心思想：引入反思器（Reflector）模型改进低质量生成样本
  • 反思器接收 agent 输出和环境反馈（如单元测试结果），生成改进样本
  • 迭代式 ReST 训练，利用 AI 反馈进行持续自我改进
  • 结果：HotpotQA 提升 7.6%，AlfWorld 提升 28.4%

4.5 DeepSeek-R1：纯 RL 激发推理能力

DeepSeek-R1 [3]（2025）证明了纯 RL 可以激发 LLM 的推理能力：

  • DeepSeek-R1-Zero：仅用 RL（GRPO）训练，无 SFT 冷启动，涌现出自我验证、反思等行为
  • DeepSeek-R1：多阶段训练（冷启动 SFT → RL → 拒绝采样 → 二次 RL）
  • 性能与 OpenAI o1-1217 相当
  • 证明 RL 可以作为 Agent 能力的主要训练信号

4.6 OpenAI 的方法：CUA 与 RFT

Computer-Using Agent (CUA)

OpenAI 的 CUA [26] 结合 GPT-4o 视觉能力与 RL 训练：

  • 通过 RL 训练模型与图形用户界面交互
  • 处理截图感知 + 推理 + 鼠标/键盘控制
  • 驱动 Operator 产品，执行网页任务

Reinforcement Fine-Tuning (RFT) API

OpenAI 于 2025 年推出 RFT API [27]，允许用户对 o4-mini 进行强化微调：

  • 基于奖励的训练过程，而非仅依赖标注数据
  • 支持自定义 Grader（评分器）作为奖励函数
  • 适用于特定领域的 Agent 能力定制
  • 计算成本：$100/小时（o4-mini-2025-04-16）

DeepResearcher

DeepResearcher [28] 是首个在真实环境中通过端到端 RL 训练深度研究 Agent 的框架：

  • 在真实网络环境中进行多轮检索和推理
  • 通过 RL 扩展研究能力

训练 Deep Research Agent 的最佳实践

"How to Train Your Deep Research Agent" [29] 系统研究了 Search-R1 中的：

多智能体 RL（Multi-Agent RL for LLMs）

5.1 MAGRPO（Multi-Agent Group Relative Policy Optimization）

MAGRPO [30] 将 LLM 协作建模为合作式多智能体强化学习（MARL）问题：

  • 问题建模：多个 LLM Agent 协作完成任务，每个 Agent 有独立策略
  • 算法：将 GRPO 扩展到多 Agent 多轮设置
  • 关键设计：
    • 联合奖励分解：将团队奖励分配给各 Agent
    • 协作优势估计：考虑其他 Agent 行为的影响
  • 结果：在编码协作任务上，Agent 通过有效合作生成高质量回复
  • 被 AAAI 2026 接收，实现 3 倍加速

5.2 AT-GRPO（Multi-Agent RL for Collaborative LLMs）

AT-GRPO [31] 专注于多 Agent 协作的 RL 训练：

  • 在长时域规划任务上，将单 Agent RL 基线的 14.0-47.0% 提升到 96.0-99.5%
  • 推理性能平均提升 3.8%
  • 证明多 Agent 协作可以显著超越单 Agent 能力上限

5.3 M-GRPO（Training Multi-Agent Systems）

M-GRPO [32] 将 GRPO 扩展到多 Agent 系统训练：

  • 处理 Agent 间的信息传递和协调
  • 联合优化多个 LLM Agent 的策略

5.4 去中心化 LLM 协作

"Learning Decentralized LLM Collaboration with Multi-Agent Actor Critic" [33]：

  • 大多数 MARL 微调方法依赖预定义执行协议
  • 提出去中心化方法，Agent 自主学习协作策略
  • 使用 Multi-Agent Actor-Critic 框架

5.5 多 Agent 后协同训练

"Multi-Agent Post-Co-Training" [34] 通过 RL 实现多 Agent 协作 LLM 的后训��：

  • 在预训练后通过 RL 学习 Agent 间协作
  • 利用多 Agent 工作流的协同效应

5.6 多 Agent RL 中的梯度传播与归一化

多 Agent 系统中的梯度传播面临独特挑战：

  • 信用分配：团队奖励需要分解到各 Agent 的贡献
  • 梯度干扰：不同 Agent 的梯度可能相互冲突
  • 任务优势归一化（AgentRL [23]）：跨任务归一化优势值，防止某些任务主导训练
  • Barrier Function Loss [35]：利用安全指标约束策略学习，处理 Agent 终止动态

多 Agent GRPO 的联合优化目标（MAGRPO 形式）：

\[ L^{MAGRPO}(\theta_1, \ldots, \theta_N) = \sum_{k=1}^{N} \mathbb{E}\left[\min\left(\rho_k A_k^{joint},\; \text{clip}(\rho_k, 1-\epsilon, 1+\epsilon) A_k^{joint}\right)\right] \]

其中 \(\rho_k = \frac{\pi_{\theta_k}(a_k|s)}{\pi_{\theta_k^{old}}(a_k|s)}\) 为第 \(k\) 个 Agent 的重要性比率，\(A_k^{joint}\) 为考虑其他 Agent 行为的联合优势。

具身智能与机器人控制中的 Agent RL

6.1 基础模型驱动的机器人 Agent

具身智能领域正在将 LLM/VLM 与 RL 结合用于机器人控制：

Embodied Foundation Models [36]

  • 增强空间理解、物理推理等具身智能核心能力
  • 弥合通用 VLM 与具身 Agent 需求之间的差距

Being-0：人形机器人 Agent [37]

  • 层次化 Agent 框架：基础模型处理高层认知（指令理解、任务规划）

10.3 可反传训练 Loss 设计：面向机器人集群 Agent

核心区分：你的 sandbox 中 score_trace() 是规则评分函数（sequence_loss, arg_loss, forbidden_loss 等），用于评估但不可微分。本节设计的是可通过反向传播更新模型权重的训练损失。规则评分作为奖励信号输入到策略梯度中，策略梯度将其转化为可微分的代理损失（surrogate loss）。

设计原则与论文依据

  1. REINFORCE 定理桥接不可微奖励与可微损失：所有策略梯度方法的核心——将标量奖励转化为 \(\hat{A} \cdot \nabla_\theta \log \pi_\theta\) 形式的可微梯度 [DeepSeek-R1, arXiv:2501.12948]
  2. Turn 级优势估计：AceAgent 的每次工具调用是一个自然的决策边界，Turn-PPO [arXiv:2512.17008] 证明 turn 级优势比 token 级在多轮 Agent 中提升 3-29%
  3. 双层信用分配：GiGPO [arXiv:2505.10978] 的宏观+微观优势在 ALFWorld 上比单层提升 13-22%（消融实验）
  4. LLDS 正则化防崩溃：GRPO 在 Agent 搜索任务中存在系统性崩溃 [arXiv:2512.04220]，LLDS 带来 +45.2% 相对提升
  5. Retrieved Token Masking：环境返回的 token 不参与梯度计算 [Search-R1, arXiv:2503.09516]

总损失函数（可微分形式）

梯度流全景：score_trace() 输出标量奖励 → 组内归一化得到优势 \(\hat{A}\) → 策略梯度定理将其转化为 \(\hat{A} \cdot \nabla_\theta \log \pi_\theta(a_t|s_t)\) → 反向传播更新 \(\theta\)。整个链路中，唯一需要可微的是 \(\log \pi_\theta\)（模型的 log-probability），奖励本身无需可微。

AceAgent RL 总损失（推荐设计）：

\[ L^{AceAgent}(\theta) = \underbrace{L^{policy}(\theta)}_{\text{GiGPO 双层策略损失}} + \alpha \cdot \underbrace{L^{safety}(\theta)}_{\text{Barrier Function}} + \underbrace{L^{KL}(\theta)}_{\text{FRPO Future-KL}} + \lambda_{LLDS} \cdot \underbrace{L^{LLDS}(\theta)}_{\text{防崩溃正则}} \]

各项均可微分，梯度可直接反传至模型参数 \(\theta\)。下面逐项给出精确公式与论文依据。

第一项：策略损失 \(L^{policy}\) — GiGPO 双层优势 + Token Masking

论文依据：GiGPO [5] 在 ALFWorld 上消融实验证明双层优势比单层 GRPO 提升 13-22%；Search-R1 [12] 证明 Retrieved Token Masking 对工具调用 Agent 至关重要。

Step 1：从 score_trace() 获取奖励信号

对每个用户指令 \(q\)，采样 \(G\) 条完整轨迹 \(\{\tau_1, \ldots, \tau_G\}\)，每条轨迹通过 sandbox 的 score_trace() 获得标量奖励：

\[ R_i = \text{score\_trace}(\tau_i) = 0.375 \cdot R^{seq}_i + 0.275 \cdot R^{arg}_i + 0.15 \cdot R^{forbidden}_i + 0.05 \cdot R^{text}_i + 0.1 \cdot R^{state}_i + 0.05 \cdot R^{behavior}_i \]

这些权重直接来自你的 sandbox 设计。\(R_i \in [0, 1]\) 是不可微的标量，仅用于计算优势。

Step 2：外层（轨迹级）优势 — GRPO 组归一化 [3]

\[ A_i^{macro} = \frac{R_i - \text{mean}(\{R_1, \ldots, R_G\})}{\text{std}(\{R_1, \ldots, R_G\}) + \epsilon} \]

无需 Critic 网络（GRPO 的核心优势 [3]）。组大小 \(G=8\text{-}16\)。

Step 3：内层（Turn 级）优势 — Turn-PPO 风格 [2]

在轨迹 \(\tau_i\) 内部，每个 turn \(t\)（对应一次工具调用）获得过程奖励 \(r_{i,t}\)（来自 score_trace 的子项分解）：

\[ A_{i,t}^{micro} = \frac{r_{i,t} - \text{mean}(\{r_{i,1}, \ldots, r_{i,T_i}\})}{\text{std}(\{r_{i,1}, \ldots, r_{i,T_i}\}) + \epsilon} \]

实验依据：Turn-PPO [2] 证明 turn 级优势在 WebShop 上比 token 级 PPO 提升 29%，在 ALFWorld 上提升 3%。

Step 4：双层混合优势 [5]

\[ A_{i,t}^{combined} = \lambda \cdot A_i^{macro} + (1-\lambda) \cdot A_{i,t}^{micro} \]

\(\lambda \in [0.3, 0.7]\)。GiGPO [5] 消融实验：\(\lambda=0.5\) 在 ALFWorld 上达到最优（93.5% 成功率 vs 单层 GRPO 的 71.3%）。建议 AceAgent 初期 \(\lambda=0.7\)（侧重结果导向），后期 \(\lambda=0.4\)（侧重过程质量）。

Step 5：PPO-Clip 代理损失 + Token Masking [12]

\[ L^{policy}(\theta) = -\frac{1}{|\mathcal{A}|}\sum_{i=1}^{G}\sum_{t \in \mathcal{A}_i}\min\left(\rho_{i,t} \cdot A_{i,t}^{combined},\; \text{clip}(\rho_{i,t}, 1\!-\!\epsilon, 1\!+\!\epsilon) \cdot A_{i,t}^{combined}\right) \]

其中：

  • \(\rho_{i,t} = \frac{\pi_\theta(a_{i,t}|s_{i,t})}{\pi_{\theta_{old}}(a_{i,t}|s_{i,t})}\) — 重要性比率，可微（\(\pi_\theta\) 是模型的 softmax 输出）
  • \(\mathcal{A}_i\) = 轨迹 \(i\) 中仅 Agent 生成的 token（思考 + 工具调用），排除环境返回的 token
  • \(\epsilon=0.2\)（标准 PPO clip）

Token Masking 的关键性：Search-R1 [12] 发现不做 masking 时模型会"学习"环境输出的分布而非决策策略，导致性能下降。在 AceAgent 中，工具返回的 JSON（导航状态、机器人位置等）必须被 mask。

梯度流分析（可微性证明）：

\[ \nabla_\theta L^{policy} = -\frac{1}{|\mathcal{A}|}\sum_{i,t \in \mathcal{A}_i} \underbrace{A_{i,t}^{combined}}_{\text{标量，不参与反传}} \cdot \underbrace{\nabla_\theta \log \pi_\theta(a_{i,t}|s_{i,t})}_{\text{可微，通过 softmax 反传至 Transformer 参数}} \]

当 \(\rho_{i,t}\) 未被 clip 时，梯度简化为上式。\(\nabla_\theta \log \pi_\theta\) 通过标准的 cross-entropy 反传路径更新所有 Transformer 层参数。

第二项：FRPO Future-KL 正则 \(L^{KL}\) — 替代标准 KL 惩罚

论文依据：FRPO [arXiv:2505.xxxxx] 发现标准 KL 惩罚 \(\beta \cdot D_{KL}(\pi_\theta \| \pi_{ref})\) 在长轨迹中过度约束早期 token，导致策略无法充分探索。Future-KL 仅约束"未来"token 的偏离，在 AIME25 上比标准 KL 提升 +20 分。

Future-KL 损失（可微分形式）：

\[ L^{KL}(\theta) = \frac{1}{|\mathcal{A}|}\sum_{t \in \mathcal{A}} \underbrace{w_t^{future}}_{\text{未来权重}} \cdot D_{KL}\left(\pi_\theta(\cdot|s_t) \| \pi_{ref}(\cdot|s_t)\right) \]

其中未来权重：

\[ w_t^{future} = \frac{T - t}{T} \quad \text{（线性衰减）或} \quad w_t^{future} = \gamma^{T-t} \quad \text{（指数衰减，}\gamma=0.99\text{）} \]

可微性：\(D_{KL}(\pi_\theta \| \pi_{ref}) = \sum_a \pi_\theta(a|s) \log \frac{\pi_\theta(a|s)}{\pi_{ref}(a|s)}\)，其中 \(\pi_\theta\) 是 softmax 输出，梯度直接反传。

对 AceAgent 的意义：机器人任务轨迹长（10-15 turns），标准 KL 会过度惩罚早期的探索性工具选择。Future-KL 允许早期自由探索，仅约束后期执行阶段的偏离。

第三项：LLDS 正则化 \(L^{LLDS}\) — 防止 Agent 搜索崩溃

论文依据：LLDS [arXiv:2512.04220] 发现 GRPO 在 Agent 搜索任务中存在系统性崩溃——模型倾向于生成极短或极长的无效轨迹。LLDS 正则化带来 +45.2% 相对提升（HotpotQA: 31.2% → 45.3%）。

LLDS 正则化损失：

\[ L^{LLDS}(\theta) = \left(\frac{1}{G}\sum_{i=1}^{G} \ell_i - \ell^{target}\right)^2 + \eta \cdot \max\left(0,\; \sigma(\{\ell_i\}) - \sigma^{max}\right) \]

其中：

  • \(\ell_i\) = 轨迹 \(i\) 的长度（token 数或 turn 数）
  • \(\ell^{target}\) = 目标轨迹长度（可设为 SFT 阶段的平均长度）
  • \(\sigma^{max}\) = 允许的最大长度方差
  • \(\eta = 0.1\)（方差惩罚权重）

可微性：虽然 \(\ell_i\) 本身不可微（离散的 token 数），但 LLDS 的实际实现是通过对 EOS token 的 log-probability 施加正则：

\[ L^{LLDS}_{impl}(\theta) = -\lambda_{eos} \cdot \log \pi_\theta(\text{EOS} | s_{\ell^{target}}) \]

鼓励模型在目标长度附近生成 EOS，防止无限延伸或过早终止。这是标准的 cross-entropy 形式，完全可微。

对 AceAgent 的意义：防止模型学会"无限调用工具"（崩溃到长轨迹）或"直接回复不调用工具"（崩溃到短轨迹）。

第四项：安全约束损失 \(L^{safety}\) — Barrier Function

论文依据：[35] 的 Agent Termination Dynamics 方法，将安全约束嵌入可微损失。

安全 Barrier 损失（可微分形式）：

\[ L^{safety}(\theta) = \frac{1}{|\mathcal{S}^{unsafe}|}\sum_{(s,a) \in \mathcal{S}^{unsafe}} \max\left(0,\; \log \pi_\theta(a|s) - \log \pi_{ref}(a|s)\right) \]

可微性：\(\log \pi_\theta(a|s)\) 是模型的 log-probability 输出，梯度直接反传。当策略增加不安全动作的概率时产生正损失。

不安全动作集合 \(\mathcal{S}^{unsafe}\) 在 AceAgent 中包括：

  • 在机器人忙碌时强制发送新导航指令（违反 Robot Mutex）
  • 跳过安全确认直接执行危险动作
  • 调用 forbidden_tools 列表中的工具
  • 超出机器人能力范围的指令

多机器人协作：MAGRPO 联合优化（可微分形式）

论文依据：MAGRPO [30] (AAAI 2026) 提出多 Agent 联合 GRPO，在 multi-agent 协作任务上比独立训练提升 15-25%。AT-GRPO [31] 进一步引入 Agent Termination 动态。

多 Agent 联合策略损失：

\[ L^{multi}(\theta_1, \ldots, \theta_N) = \sum_{k=1}^{N} L^{policy}_k(\theta_k;\; A^{joint}_k) \]

其中联合优势：

\[ A^{joint}_k = \underbrace{A^{individual}_k}_{\text{个体贡献}} + \mu \cdot \underbrace{A^{team}}_{\text{团队奖励优势}} \]

\(A^{team}\) 基于团队总奖励的 GRPO 归一化，\(\mu=0.3\)。

可微性：每个 Agent \(k\) 的参数 \(\theta_k\) 独立更新（MAGRPO 的 independent parameters 设计 [30]），梯度不跨 Agent 传播。联合优势仅影响标量信号，不影响可微性。

资源冲突惩罚（嵌入奖励信号）：

\[ R^{coord}_k = R^{individual}_k + \mu \cdot R^{team} - \nu \cdot C^{conflict}_k \]

其中 \(C^{conflict}_k\) 检测 Agent \(k\) 是否与其他 Agent 争抢资源（如同一通道、同一目标物）。\(\nu=0.5\)。

此奖励通过 GRPO 归一化后成为优势信号，再通过策略梯度转化为可微损失——与单 Agent 的梯度流完全一致。

梯度稳定性：Trust Region Masking + ST-PPO

论文依据：Trust Region Masking [47] 在长轨迹 Agent 中实现 409x 更紧的信任域边界；ST-PPO [arXiv:2504.13169] 通过 clipping-triggered normalization 稳定离策略训练。

Trust Region Masking（序列级 Masking）：

\[ M^{TR}_{i} = \mathbb{1}\left[\left|\frac{\pi_\theta(\tau_i)}{\pi_{\theta_{old}}(\tau_i)} - 1\right| > \delta^{TR}\right] \]

当整条轨迹的重要性比率偏离过大时，mask 该轨迹的梯度贡献。\(\delta^{TR} = 0.5\)。

实验依据：[47] 证明在 15-turn 的 Agent 任务中，序列级 masking 比 token 级 clip 的训练稳定性提升 409x（以 KL 散度方差衡量）。

ST-PPO Clipping-Triggered Normalization：

当 clip 比率超过阈值 \(\tau_{trigger}\) 时，对该 batch 的优势重新归一化：

\[ \hat{A}^{renorm} = \frac{A - \mu_{clipped}}{\sigma_{clipped} + \epsilon} \]

其中 \(\mu_{clipped}, \sigma_{clipped}\) 仅基于未被 clip 的样本计算。\(\tau_{trigger} = 0.3\)。

可微性：归一化操作本身可微（标准的 batch normalization 思路），不影响梯度流。

10.4 梯度传播与归一化策略（Norm Propagation）

端到端梯度流路径

AceAgent RL 训练的完整梯度流：

前向传播：

用户指令 q → Transformer(θ) → logits → softmax → π_θ(a_t|s_t) → 采样动作 → 工具执行 → 环境反馈 → 下一轮
                                                                    ↓ (采样断开梯度)
                                                              score_trace() → R_i (标量)

反向传播：

L^{AceAgent} ← Â·log π_θ ← softmax ← logits ← Transformer 所有层参数 θ
     ↑                         ↑
  LLDS正则                  KL散度项

关键点：采样动作时梯度断开（REINFORCE 的本质），但 \(\log \pi_\theta(a_t|s_t)\) 对已采样的 \(a_t\) 是可微的——这就是策略梯度定理的核心。

归一化策略

1. 任务优势归一化（Task Advantage Normalization，AgentRL [23]）

\[ \hat{A}_{task_j} = \frac{A_{task_j} - \mu_{task_j}}{\sigma_{task_j} + \epsilon} \]

对每种任务类型（导航、动作、购物、协作）独立归一化优势值，防止高奖励任务主导训练。AgentRL [23] 证明此方法在多任务 Agent 训练中消除梯度冲突。

2. 梯度裁剪

  • 全局梯度范数裁剪：\(\|\nabla L\|_2 \leq 1.0\)
  • Turn 级别梯度累积：每个 turn 独立计算梯度后再聚合，避免长轨迹梯度累积

3. 混合奖励归一化（参考 [18] Hybrid Reward Normalization）

\[ R_i^{normalized} = w_1 \cdot \text{norm}(R^{outcome}_i) + w_2 \cdot \text{norm}(R^{process}_i) \]

其中 \(\text{norm}(x) = \frac{x - \mu_x}{\sigma_x + \epsilon}\)。建议 \(w_1=0.7, w_2=0.3\)。[18] 证明分别归一化可验证/不可验证奖励后再组合，���直接混合提升 8-12%。

10.5 训练流程建议

PyTorch 伪代码：AceAgent RL 训练循环


# AceAgent RL Training Loop (PyTorch pseudocode)
# 所有损失项均可微分，梯度通过 loss.backward() 直接反传

def compute_aceagent_loss(model, ref_model, prompts, sandbox, config):
    """完整的可微分训练损失计算"""
    total_loss = 0.0

    for q in prompts:
        # Step 1: 采样 G 条轨迹（前向传播，记录 log_probs）
        trajectories = []
        for _ in range(config.G):
            tau, log_probs, token_mask = model.generate_with_logprobs(
                q, max_turns=config.T_max,
                return_agent_token_mask=True  # Retrieved Token Masking
            )
            R = sandbox.score_trace(tau)  # 不可微标量奖励
            trajectories.append((tau, log_probs, token_mask, R))

        # Step 2: GRPO 组归一化 → 宏观优势（不可微，仅标量）
        rewards = [t[3] for t in trajectories]
        A_macro = (rewards - mean(rewards)) / (std(rewards) + eps)

        # Step 3: Turn 级微观优势
        for i, (tau, log_probs, mask, R) in enumerate(trajectories):
            turn_rewards = sandbox.get_turn_rewards(tau)  # 子项分解
            A_micro = (turn_rewards - mean(turn_rewards)) / (std(turn_rewards) + eps)

            # Step 4: 双层混合优势 (GiGPO [5])
            A_combined = config.lam * A_macro[i] + (1 - config.lam) * A_micro

            # Step 5: PPO-Clip 策略损失（可微！log_probs 参与计算图）
            ratio = exp(log_probs - log_probs.detach())  # 重要性比率
            clipped = torch.clamp(ratio, 1-config.eps, 1+config.eps)
            policy_loss = -torch.min(ratio * A_combined, clipped * A_combined)
            policy_loss = (policy_loss * mask).sum() / mask.sum()  # Token Masking

            # Step 6: Future-KL 正则（可微）
            kl = compute_kl(model, ref_model, tau, mask)
            future_weights = torch.linspace(1, 0, len(kl))  # 线性衰减
            kl_loss = (kl * future_weights * mask).sum() / mask.sum()

            # Step 7: LLDS 正则（可微，通过 EOS logprob）
            eos_logprob = log_probs[..., EOS_TOKEN_ID]
            llds_loss = -config.lam_llds * eos_logprob[config.target_len]

            # Step 8: 安全 Barrier（可微）
            unsafe_mask = sandbox.get_unsafe_actions(tau)
            if unsafe_mask.any():
                safety_loss = F.relu(
                    log_probs[unsafe_mask] - ref_log_probs[unsafe_mask]
                ).mean()
            else:
                safety_loss = 0.0

            total_loss += policy_loss + kl_loss + llds_loss + config.alpha * safety_loss

    # 反向传播：梯度流经 log_probs → softmax → logits → Transformer 参数
    total_loss.backward()  # 标准 PyTorch 反传，更新所有 θ
