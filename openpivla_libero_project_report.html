核心结论

官方 baseline：OpenPI 官方 LIBERO README 给出的 π0.5 finetune baseline 为 Spatial 98.8、Object 98.2、Goal 98.0、LIBERO 10 92.4、平均 96.85，checkpoint 为 gs://openpi-assets/checkpoints/pi05_libero/，训练 config 为 pi05_libero。这是本报告中“官方 baseline”的主参照。

项目主线：本地项目不是简单复现官方 π0.5-LIBERO，而是在 OpenPI/PiZero 框架中把 LIBERO 接入 Qwen-VL/Qwen3-VL 风格的 VLA backbone，并把 LIBERO 的 7 维末端执行器动作适配进本地更通用的 72 维统一动作空间。这样做的目的，是让同一套 QwenVLA/AGX/XE 模型接口能服务 LIBERO、AGILEX、Galaxea、DROID、Aloha 等多种 embodiment（具身形态），同时在 LIBERO eval 时只输出环境需要的 7 维动作。

关键改造：官方路径是 image + wrist_image + state(8) + prompt 输入，输出 actions[:, :7]。本地最终路径是 global_image / left_image / right_image + 72 维 state/action 结构 + prompt 输入，Qwen-VL 处理文本和图像，fast vision / joint model / action expert 处理动作 token，输出 72 维 action chunk，再通过 action_mask_step 与 XELiberoOutputs 抽取 ee_pos(3) + ee_rot(3) + gripper(1) 给 LIBERO 执行。

本地结果：2026-06-21 代表 run 中，h4b_x_new_10000 四套 suite 合计 362/800 = 0.4525，明显好于 image-only 与早期 8B 代表 run。2026-06-28/07-02 核对的最新 8B run debug_224_8b...x_new/15000 达到 LIBERO 10 0.4750、Goal 0.1300、Object 0.8650、Spatial 0.7550，若每套 200 episodes 等权，约为 445/800 = 0.55625。它相比 4B x_new 在 Object、Spatial、LIBERO 10 和 Goal 上均有改善，但距离官方 π0.5 平均 0.9685 仍很远。

背景与动机（Background & Motivation）

LIBERO 任务模式

LIBERO（Lifelong Robot Learning Benchmark，终身机器人学习基准）用于研究机器人在顺序任务、分布迁移和知识迁移中的表现。官方仓库描述其包含 130 个语言条件机器人操作任务，分为 LIBERO-Spatial、LIBERO-Object、LIBERO-Goal 和 LIBERO-100；其中 LIBERO-100 又拆为 LIBERO-90 与 LIBERO-10。LeRobot 文档把可用 suite 标成 libero_spatial、libero_object、libero_goal、libero_90 和 libero_10。这些任务用 MuJoCo/robosuite 风格环境执行，输入包括第三视角图像、腕部图像、机械臂状态和自然语言任务描述。

对本项目而言，LIBERO 的困难不是单步预测 loss，而是闭环控制：模型每隔若干步输出一段 action chunk（动作块），环境执行其中前几步，新的视觉和 proprioception（本体感知）再进入模型。一个很小的动作维度顺序错误、归一化错误、相机翻转错误或 gripper 方向错误，都可能让离线 loss 看起来不错但在线 success rate 很差。

基础概念与术语

VLA 与 action chunk

视觉-语言-动作模型（Vision-Language-Action model, VLA）把图像、语言指令、机器人状态映射到动作。与只输出文本的视觉语言模型（Vision-Language Model, VLM）不同，VLA 的输出必须能被控制器直接执行，通常是连续动作向量或离散动作 token。π0 论文将 VLM 语义能力接入 flow matching action expert，使模型能输出连续机器人动作。

动作块（action chunk）表示模型一次预测未来 \(H\) 步动作：

\[ A_{t:t+H-1} = \left[a_t, a_{t+1}, \ldots, a_{t+H-1}\right], \quad a_t \in \mathbb{R}^{D_a}. \]

变量解释：\(H\) 是 action_horizon，本地 LIBERO 常见值为 10；\(D_a\) 是动作维度，官方 LIBERO 为 7，本地 QwenVLA 统一空间为 72。实现映射：eval 端通过 replan_steps 只执行前若干步，然后重新向 policy server 查询新的 action chunk。

末端执行器动作与本体状态

LIBERO 环境使用末端执行器（end-effector, EE）动作，典型 7 维为位置增量 \(x,y,z\)、旋转增量或轴角/欧拉表示 \(r_x,r_y,r_z\)、夹爪 \(g\)。官方 eval 端从环境观测构造 8 维 state：EEF position 3 维、EEF quaternion 转 axis-angle 3 维、gripper qpos 2 维。本地 XE/AGX 表示则把双臂 joints、gripper、EE position、EE rotation 放进更大的通用空间。

Flow matching

流匹配（Flow Matching）学习一个向量场，把噪声样本连续推向数据样本。对机器人动作而言，它的直觉是：模型不直接一次性“回归动作”，而是在随机时间 \(t\) 看到一个被噪声污染的动作 \(x_t\)，预测应该朝真实动作 \(a\) 走的速度。

为什么要做这些改造

改造直接效果设计思想风险
从 7 维 LIBERO action 转到 72 维统一动作空间 同一模型头可服务多平台、多机械臂、多状态字段。 把 LIBERO 当作统一 VLA 系统中的一个 embodiment，而不是孤立 benchmark。 维度顺序、mask、归一化任何一处错，都会在线崩掉。
Qwen-VL 接入 用 Qwen 处理图像和语言 token，替换或扩展 PaliGemma/原 OpenPI VLM 路径。 借 Qwen3-VL 的视觉理解、空间推理和文本能力，支持更丰富任务语义。 Qwen token 长度、图像 token、position id、causal mask 需要与动作流精确对齐。
right wrist zero fix / mask_pad_image / drop_right_camera 缺失相机用黑图和 mask 控制，不让 padding 图像被模型当作有效证据。 训练和 eval 的相机存在性必须一致。LIBERO 常只有第三视角和左腕视角。 若 mask 与图像 key 不一致，会造成 attention 读到假图像。
no discrete state input 关闭把连续状态离散化拼进文本 prompt 的路径。 减少文本上下文膨胀和训练/推理不一致，逼迫连续 proprio head 承担状态信息。 若 proprio 编码不足，Goal 类任务可能仍缺精确状态条件。

action stream fp32 / action expert fp32 关键动作路径用 FP32 保持数值稳定。 连续控制对小数值误差敏感，flow ODE 多步积分会放大误差。 显存压力更大，448 输入容易 OOM。

训练目标、Loss 与数学表达

动作 flow matching 目标

令 \(a \in \mathbb{R}^{H \times D_a}\) 表示真实动作块（action chunk），\(\epsilon \sim \mathcal{N}(0, I)\) 表示噪声，\(t \in [0,1]\) 表示随机采样的 flow time，\(x_t\) 表示噪声与真实动作之间的插值：

\[ x_t = (1-t)\epsilon + t a, \qquad u_t = a - \epsilon . \]

变量解释：\(x_t\) 是模型在训练时看到的 noisy action；\(u_t\) 是从噪声走向真实动作的目标速度。实现映射：train_pytorch_qwen3_fast_zhi.py 的 DataCollator 会采样 flow matching time；pizero_qwenvl_fast_fortrainer.py 中 action_decoder 解码 v_t，再与目标速度做平方差。

带 mask 的动作损失可写为：

\[ \mathcal{L}_{action} = \frac{1}{H} \sum_{h=1}^{H} \frac{ \sum_{d=1}^{D_a} m_{h,d}\left\|\hat{u}_{\theta,h,d} - u_{h,d}\right\|_2^2 }{ \sum_{d=1}^{D_a} m_{h,d} + \varepsilon } . \]

变量解释：\(m_{h,d}\) 是 action mask，决定第 \(h\) 步第 \(d\) 维是否计入 loss；\(\hat{u}_{\theta}\) 是模型预测 velocity；\(\varepsilon\) 防止分母为 0。实现映射：本地 fortrainer 中 mask_f = action_mask.to(diff2.dtype)，并对每步有效维做归一化；action_mask_step 在 serve/eval 时只保留 LIBERO 所需维度。

总 loss 组合

训练脚本支持动作 loss、VLM cross entropy（视觉语言 CE）和可选在线 distillation（蒸馏）：

\[ \mathcal{L} = \mathcal{L}_{action} + \lambda_{ce}\mathcal{L}_{VLM} + \lambda_{kd}\mathcal{L}_{KD}. \]

变量解释：\(\lambda_{ce}\) 对应 lambda_fast_ce，\(\lambda_{kd}\) 对应 ONLINE_DISTILL_PI05_LAMBDA；\(\mathcal{L}_{KD}\) 是 student velocity 与 PI05 teacher velocity 的 MSE。实现映射：LIBERO shell 中 --lambda_fast_ce 0，因此这些 run 的主训练目标是 action flow matching；在线蒸馏代码存在，但本地 evidence 未发现已用于报告中列出的 LIBERO eval run。

Success rate 指标

LIBERO eval 的主指标是 success rate：

\[ \mathrm{SR} = \frac{1}{N} \sum_{i=1}^{N} \mathbf{1}\left[\mathrm{done}_i = \mathrm{true}\right]. \]

变量解释：\(N\) 是 episode 总数；\(\mathbf{1}[\cdot]\) 是指示函数；done 来自 LIBERO 环境是否完成任务。实现映射：examples/libero/main.py 在每个 episode 中执行 env.step(action)，若 done 为真则计一次 success；并将 suite 级 success 写入 success_rate.txt。

Pipeline 与伪代码

训练 step

def train_step(raw_batch):
    # 1. Repack LIBERO/XE fields into model-facing keys.
    batch = repack_transform(raw_batch)
    # batch has images, state.*, action.*, and prompt/task.

    # 2. Convert dataset fields to OpenPI/QwenVLA observation and action tensors.
    obs = XELiberoInputs(batch)
    # obs["image"] contains base_0_rgb / left_wrist_0_rgb / right_wrist_0_rgb.
    # obs["state"] and obs["actions"] are padded/masked into the unified layout.

    # 3. Build action input stream.
    if config.model.empty_action_inputs:
        # Prevent the action stream from seeing ground-truth actions as input.
        obs["actions_for_input"] = INVALID_MIN_ACTION_VALUE

    # 4. Encode image/text/proprio/action tokens with QwenVLA processor and joint model.
    model_inputs = data_collator(obs, sample_fm_time=True, mask_pad_image=True)

    # 5. Predict flow velocity for the action chunk and compute masked loss.
    loss_action, loss_vlm = model(**model_inputs)
    loss = loss_action + config.lambda_fast_ce * loss_vlm

    # 6. Backpropagate and save/evaluate at configured intervals.
    loss.backward()
    optimizer.step()
    optimizer.zero_grad()
    return loss

LIBERO eval / online rollout

def libero_rollout(env, policy_client, task_description, init_state):
    # 1. Reset simulator and wait for objects to settle.
    obs = env.set_init_state(init_state)
    for _ in range(num_steps_wait):
        obs, reward, done, info = env.step(LIBERO_DUMMY_ACTION)

    action_plan = deque()
    while t < max_steps:
        if len(action_plan) == 0:
            # 2. Build model observation from current environment state.
            image = rotate_180(obs["agentview_image"])
            wrist = rotate_180(obs["robot0_eye_in_hand_image"])
            state = concat(eef_pos, quat_to_axis_angle(eef_quat), gripper_qpos)

            # 3. Send a single observation and task prompt to the websocket policy server.
            element = {
                "observation/image": image,
                "observation/wrist_image": wrist,
                "observation/state": state,
                "prompt": task_description,
            }
            action_chunk = policy_client.infer(element)["actions"]

            # 4. Execute only the first few actions, then replan from fresh images.
            action_plan.extend(action_chunk[:replan_steps])

        # 5. Step LIBERO with a 7-dim action.
        action = action_plan.popleft()
        obs, reward, done, info = env.step(action.tolist())
        if done:
            return True
    return False

Bridge/Simpler 风格 online rollout

def bridge_online_rollout(env, env_adapter, client, instruction):
    # 1. Convert environment-specific observation to policy input.
    inputs = env_adapter.preprocess(env, obs, instruction)

    # 2. Query remote policy server for an action chunk.
    action_chunk = client.infer(inputs)["actions"]

    # 3. Convert policy action to environment controller action.
    env_actions = env_adapter.postprocess(action_chunk)

    # 4. Execute the first act_steps actions, record reward/success/video, then re-query.
    for action in env_actions[:act_steps]:
        obs, reward, done, info = env.step(action)
        if done:
            break

第三段伪代码对应本地 eval_client_bridge.py 的在线闭环思路：环境 adapter 负责把不同平台观测转换成 policy 输入，policy server 只暴露 client.infer(inputs)["actions"]，postprocess 再把 action 转回控制器坐标。

逐 Run 详细记录

阶段 0：官方 π0.5-LIBERO recipe

目标与参考来源：官方 OpenPI 将 LIBERO 作为 fine-tuning 教程，展示如何把 RLDS 数据转成 LeRobot，再用 pi05_libero config 微调 π0.5。官方 baseline 的意义是告诉我们，在标准 7/8 维 LIBERO 接口和官方 checkpoint 下，benchmark 可以达到约 96.85 平均 success rate。

输入输出：旧模型吸收 image、wrist_image、state(8)、prompt；训练目标为 actions(7)；eval 时 policy server 返回 action chunk，LiberoOutputs 取前 7 维。

设计结论：官方 recipe 的设计很窄但稳定：它完全围绕 LIBERO 单臂 EEF control 写输入输出。若目标只是 LIBERO 分数，它是强 baseline；若目标是统一多平台 QwenVLA，则需要本地后续改造。

阶段 1：Qwen-VL 进入官方式 LIBERO

目标与参考来源：pi05_libero_qwen_vl 将 vl_backbone="qwen"、qwen_model_name="Qwen/Qwen3-VL-2B-Instruct" 写入 config。这个阶段的核心是先替换 VLM backbone，而不是大改动作空间。

为什么这样做：Qwen3-VL 模型卡强调文本理解、视觉感知、空间/视频动态理解和 agent interaction 能力。对 LIBERO 这种语言条件视觉操作任务，接入 Qwen 的动机是让模型从更强 VLM 获得语义 grounding。

不足：本地 evidence 没有找到该 config 对应的完整训练 loss 和 success_rate，因此该阶段只能作为架构路线证据，不能作为结果结论。

阶段 2：XE/QwenVLA 72 维统一接口

目标与参考来源：pi05_agx_qwenvl_libero_ft 是本地最关键的项目 config。它将 qwen_vl=True、proprio_dim=72、action_dim=72、action_horizon=10 和 LeRobotXELiberoDataConfig 组合起来。

改进内容：把 LIBERO 数据变成本地统一格式：三相机字段、状态拆分字段、动作拆分字段、task prompt。训练时通过 padding/mask 处理无关维，eval 时通过 action_mask_step 只让 left gripper、left EE pos、left EE rot 参与采样和输出。

为什么这样做：这不是为了 LIBERO 本身最简化，而是为了让模型成为跨 embodiment 的 VLA。LIBERO 的 7 维动作只是统一 72 维空间中的一个投影：

\[ a^{libero} = P_{libero} a^{72}, \quad P_{libero} = \left[ P_{ee\_pos}; P_{ee\_rot}; P_{gripper} \right]. \]

变量解释：\(a^{72}\) 是模型输出的统一动作向量，\(P_{libero}\) 是由 XELiberoOutputs 和 action_mask_step 实现的投影/抽取算子。实现映射：代码中并没有显式矩阵，而是通过 slice 抽取 EE pos、EE rot 和 gripper。

阶段 3：448 输入与预训练对比

目标：尝试更高分辨率视觉输入和预训练 checkpoint，以提升细粒度视觉定位和长程任务表现。

记录：448_wo_pretrain_15000_exact 是 exact exp name match，但训练在 step 0/2 附近 OOM，loss 1.3211，不能说明模型有效学习。448_pretrain_15000_candidate 有 step 55500、loss 0.0450、checkpoint 55000 的 candidate evidence，但与 eval dir 不是 exact match。

原因分析：448 输入会显著增加视觉 token 和显存压力；QwenVL、fast vision、action stream FP32、bidirectional attention 叠加后，OOM 是合理风险。预训练 candidate 的低 loss 暗示初始化重要，但本报告不把它当成精确可复现结论。

阶段 4：224 h10 稳定化、right wrist fix、no discrete state

目标：从 448 回到 224，提高训练稳定性；同时修复缺失右腕图像、关闭离散 state prompt、使用 bidirectional action attention 和 action stream FP32。

训练命令证据：train_sf_libero_cyx_bidirectional_fix_zero_right_wrist_no_discrete_state_vlm.sh 使用 torchrun --nproc_per_node=8、pi05_agx_qwenvl_libero_ft、batch 512、--mask_pad_image、--data.use_eef_pos_only、--model.action_horizon 10、--model.slowfast=2、--model.no_discrete_state_input、--model.bidirectional_action_attention、--lambda_fast_ce 0、80k steps、224 input。

结果证据：W&B requested summary 中 224_h10_40000_candidate 在 step 10800 summary loss / flow matching loss 为 0.0300，checkpoint 10000 后 OOM。项目根 README 记录 224 h10/40k 有强 LIBERO 成绩：Goal 0.99、Object 0.995、Spatial 0.98、LIBERO10 0.93。

⚠️ 该阶段的 loss summary 与 40k eval 成绩之间，本地 evidence 只能做到 candidate 级关联。报告把它写作“强结果记录存在，但完整对应关系待核实”。

阶段 5：4B x_new 与 image-only 对照

目标：比较完整 XE/QwenVLA x_new 与 image-only、image-a5、早期 8B variant 的实际闭环效果。

评估结果：h4b_x_new_10000 四套 suite 合计 362/800 = 0.4525；而 h4b_image_x_40000 为 0.1613、h4b_image_x_a5_40000 为 0.0850、h8b_x_10000 为 0.0988。

原因分析：image-only 结果显著差，说明在 LIBERO 闭环控制中，proprio/action schema、状态到动作的维度对齐、归一化 stats 和 action mask 比“只看图像”更关键。早期 8B 差于 4B x_new 也说明模型参数量不是主因，输入输出适配和训练稳定性更关键。

阶段 6：最新 8B x_new / 15000 结果

目标：在 x_new 路线基础上引入 8B 路径、pretrain、224 input、slowfast2、bidirectional、zero right wrist fix，并用 2026-06-28/07-02 evidence 重新核对。

结果：debug_224_8b_maskpadimage_libero_eefpose_1e-4_2.5e-5_sf2_pretrain_bidirectional_fix_zero_right_wrist_x_new/15000 的 success rate 为：LIBERO10 0.4750、Goal 0.1300、Object 0.8650、Spatial 0.7550。假设四套 suite 各 200 episodes，则为 \(95+26+173+151=445\) successes，平均 0.55625。

原因分析：Object 和 Spatial 高，说明视觉定位、物体操作和空间关系已有可用能力；Goal 仍低，说明长程目标条件、动作序列稳定性或任务语义到控制策略的绑定仍是瓶颈。它比 h4b_x_new_10000 的 Object 0.65、Spatial 0.705、LIBERO10 0.395、Goal 0.06 有整体提升，但尚未接近官方 π0.5-LIBERO。
