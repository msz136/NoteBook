3.2 OpenPI/QwenVL/PiZero VLA 的输入到输出全流程

先给一个总判断：本地 OpenPI VLA 主线不是把动作简单离散成文字 token 再让 LLM 吐出动作，而是以 PiZero/π0 风格的 flow matching 连续动作头 为主输出路径，再用 FAST action token CE 给 QwenVL 语言视觉分支提供额外动作语义监督。OpenPI 官方仓库也把 π0 标成 flow-based VLA，把 π0-FAST 标成 FAST-tokenizer autoregressive VLA；本地实现把二者揉到同一个 QwenVL/PiZero joint-mixture 训练框架里 [1][10][11]。

3.2.1 输入与输出的张量契约

单个控制时刻的输入可以写成：

$$ O_t=\{I_t^{base}, I_t^{left}, I_t^{right}, s_t, q\} $$

其中 $I$ 是多视角图像，$s_t$ 是机器人 proprioception/state，$q$ 是自然语言任务指令。模型输出不是单步动作，而是一个动作块（action chunk）：

$$ \hat A_t= [\hat a_t,\hat a_{t+1},\ldots,\hat a_{t+H-1}] \in \mathbb{R}^{H\times D} $$

$H$ 对应 action_horizon / horizon_steps，$D$ 对应 action_dim。本地 PiZero.__init__ 将 cfg.horizon_steps = pi0_config.action_horizon，并令 num_action_tokens = horizon_steps + cond_steps - 1；也就是说，action expert 里的“action token”本质上是每个未来时间步的连续动作隐状态，不是 Qwen 词表里的离散 token。

3.2.2 三条信息流：VLM、fastobs、action

本地模型有三条主要 mixture：

  1. VLM mixture：QwenVL/Qwen3-VL 处理语言和主视觉 token。代码把 pretrained_model.language_model.layers 接到 joint_model.mixtures.vlm.layers。
  2. fastobs mixture：slowfast 模式下，DINO/fast visual path 从多视角图像中抽取更紧凑的视觉 token，经 multi_modal_projector 对齐到 action expert hidden size。代码把 action expert layers 也接到 joint_model.mixtures.fastobs.layers。
  3. action mixture：把 noisy action chunk 和时间 $t$ 编码为 action tokens，经 action expert layers 后由线性 action_decoder 解成连续速度场。

抽象成公式就是：

$$ E^{vlm}=E_Q(q,I_t),\quad E^{fo}=P_{\text{fast}}(F_{\text{DINO}}(I_t)),\quad E^a_\tau=E_A(X_\tau,\gamma(\tau)) $$
$$ H^a_\theta= J_\theta^{action}\left(E^a_\tau\mid E^{vlm},E^{fo},M\right), \qquad \hat V_\theta=W_{\text{dec}}H^a_\theta $$

这里 $J_\theta$ 是 joint model，$M$ 是 causal/mixture attention mask，$\gamma(\tau)$ 是 sinusoidal time embedding。推理时 VLM/fastobs 条件会先 prefill 到 KV cache；每个 action denoising step 只更新 action mixture，同时通过 cache 读取图文条件。

3.2.3 训练侧：如何把一个 GT action chunk 变成监督信号

训练 batch 中有真实动作块 $A^\star\in\mathbb{R}^{H\times D}$。本地 collator 做两件并行的事：

  1. 连续动作监督：把完整 $A^\star$ 送入 flow matching 路径。
  2. FAST token 辅助监督：把动作按 left/right、base/camera 坐标等片段拆出来，用 UniversalActionProcessor 编成整数 token，再映射到 Qwen 词表里的 <robot_action_i>。

FAST 辅助路径在 train_acebrain.py 中大致是：

$$ A^\star \xrightarrow{\text{slice}} \{A^{left/base},A^{right/base},A^{left/cam},A^{right/cam}\} \xrightarrow{\text{FAST}} \{z^p_1,\ldots,z^p_{L_p}\} $$
$$ z_i^p\in\{0,\ldots,2047\}, \qquad \text{token\_id}(z_i^p)=151669+z_i^p $$

这些 token 被渲染成文本片段，例如 <|action_start|><robot_action_17>...<|action_end|>，再拼进 prompt。CE 标签不是全句监督，而是把非 FAST token 设成 -100；若启用 supervise_state_tokens，则额外保留 <|state_start|>...<|state_end|> span。这样做的目的不是让最终动作全靠语言 token 生成，而是强迫 QwenVL hidden states 学会“看到图像和任务时，应该在语言空间里对应哪类动作模式”。

一个关键防泄漏细节：训练 prompt 里含有 GT FAST action token，如果 action expert 可以直接 attend 到这些 token，FM 动作头就可能抄答案。本地 collator 在 use_fast 训练时对 causal mask 做了额外处理，把 action 解码位置到 GT FAST action span 的注意力屏蔽掉。抽象写成：

$$ M_{\text{action}\leftarrow \text{GT-FAST}}=-\infty $$

这让 FAST CE 可以训练 VLM 分支，同时避免连续 action decoder 直接读取标签。

3.2.4 Flow matching：action chunk 是怎样生成的

本地代码的 flow path 使用带 $\sigma_{\min}$ 的线性条件路径。令 $X_0\sim\mathcal{N}(0,I)$ 是噪声动作块，$X_1=A^\star$ 是真实动作块，采样 $\tau\in[0,1]$，本地 psi_t 实现为：

$$ X_\tau = \left(1-(1-\sigma_{\min})\tau\right)X_0+\tau X_1 $$

当 $\tau=0$ 时，$X_\tau=X_0$；当 $\tau=1$ 时，$X_\tau\approx X_1+\sigma_{\min}X_0$。这条路径的真实速度场为常量：

$$ V^\star=\frac{dX_\tau}{d\tau} =X_1-(1-\sigma_{\min})X_0 $$

模型看到的是 $O_t,q,X_\tau,\tau$，要预测 $V^\star$：

$$ \hat V_\theta = W_{\text{dec}} J_\theta^{action} \left( E_A(X_\tau,\gamma(\tau)) \mid E_Q(q,I_t), E^{fo} \right) $$

动作损失只在有效动作维度上计算。本地代码先用数值范围和可选 action_pad_mask 得到 mask $m$，再做 masked MSE：

$$ \mathcal{L}_{FM} = \frac{1}{\sum m} \sum_{b,h,d} m_{bhd} \left( \hat V_{\theta,bhd}- \left[X_{1,bhd}-(1-\sigma_{\min})X_{0,bhd}\right] \right)^2 $$

FAST CE 辅助项是标准自回归语言模型损失：

$$ \mathcal{L}_{FAST} = -\sum_{i:y_i\ne -100} \log p_\theta(y_i\mid y_{<i},O_t,q) $$

总体训练目标应理解为：

$$ \mathcal{L} = \mathcal{L}_{FM} +\lambda_{\text{fast}}\mathcal{L}_{FAST} +\lambda_{\text{vlm}}\mathcal{L}_{VLM} $$

实现注意：当前可见训练循环中，loss_action + loss_vlm * lambda_fast_ce 先被构造出来，但随后又进入额外的 VLM loss 组合分支；在部分脚本路径下，最终反传的 loss 可能退化为 loss_action 或 loss_action + lambda_vlm * loss_vlm_web。因此复现前必须审计实际 backward 的标量，确认 FAST CE 是否真的进入最终 loss。

3.2.5 推理侧：从噪声到可执行 action chunk 的解码

推理入口是 sample_actions(...)，它把 observation 和 prompt 重新送入 processor，构造 input_ids、图像张量、position ids 和 mask，然后调用 infer_action。这里没有 GT FAST action token；最终动作来自连续 flow 采样。

推理分两阶段：

  1. 条件预填充：先跑 VLM/fastobs mixture，把图像、语言、fast visual tokens 写入 KV cache。
  2. 动作积分：初始化 $A^{(0)}\sim\mathcal{N}(0,I)$，把它当作 noisy action chunk；循环 $K=\texttt{num_inference_steps}$ 次，每次预测速度并做数值积分。
$$ A^{(0)}\sim\mathcal{N}(0,I),\qquad \Delta \tau=\frac{1}{K},\qquad \tau_k=k\Delta \tau $$
$$ H_k^a= J_\theta^{action} \left( E_A(A^{(k)},\gamma(\tau_k)) \mid \text{KV}(E^{vlm},E^{fo}) \right) $$
$$ \hat V_k=W_{\text{dec}}H_k^a,\qquad A^{(k+1)}=A^{(k)}+\Delta \tau\,\hat V_k $$

代码默认用 Euler；本地也放了 Heun/RK4 的 integration_step 入口。积分结束后，模型会按 final_action_clip_value 做 clamp，并返回最后 cfg.horizon_steps 个时间步：

$$ \hat A_t= \operatorname{clip} \left(A^{(K)}_{-H:},-c,c\right) $$

这就是 action chunk 的“解码”：action_decoder 不是直接输出最终动作，而是在每个去噪步把 action hidden state 解成速度场；真正的动作值是通过 ODE/flow 积分累积出来的。若部署栈对动作做过数据归一化，还需要在模型外部按数据统计量反归一化：

$$ a_{\text{env}}=\sigma_{\text{data}}\odot \hat a+\mu_{\text{data}} $$

这一步通常属于 OpenPI policy/data transform 层，不在当前 pizero_qwenvl_fast_fortrainer.py 的核心 forward/infer 里。

3.2.6 FAST token 解码与主输出路径的关系

如果单独走 π0-FAST / fast_only 风格，动作生成可以写成：

$$ \hat z_i= \arg\max_z p_\theta(z\mid \hat z_{<i},O_t,q), \qquad \hat A_t=D_{\text{FAST}}(\hat z_{1:L}) $$

$D_{\text{FAST}}$ 是 FAST tokenizer 的 inverse decoder，把离散 action tokens 还原为连续 action chunk。但当前本地主线中，fast_only=True 会直接关闭 action expert/action decoder；而默认 VLA 路径仍是 sample_actions -> infer_action -> action_decoder -> flow integration。因此读本地代码时应把两件事分开：

  • FAST token CE：训练期辅助 QwenVL 对齐动作语义，提供离散动作语言监督。
  • FM action decoder：训练和推理期的主连续动作块生成器，负责最终 $\mathbb{R}^{H\times D}$ 输出。

2. Condition prefill
    E_vlm = QwenVL embeddings for text + image
    E_fastobs = fast visual embeddings if slowfast is enabled
    kv_cache = JointModel.prefill(E_vlm, E_fastobs)

3. Flow integration
    A = Normal(0, I)              # [B, H, D]
    delta = 1 / num_inference_steps
    tau = 0
    repeat num_inference_steps times:
        E_action = ActionEncoder(A, TimeEmbedding(tau))
        H_action = JointModel.action_step(E_action, kv_cache)
        V = ActionDecoder(H_action)[last H steps]
        A = A + delta * V          # Euler; Heun/RK4 are optional hooks
        A[invalid_action_dims] = 0
        tau = tau + delta

4. Postprocess
    A = clip(A, -final_action_clip_value, final_action_clip_value)
    A_hat = A[:, -H:, :]
    return A_hat

3.3.1 VLM-only：图像与文本到文本 token

VLM-only 模式最接近普通视觉语言模型。图像先被视觉编码器变成 patch token，文本被 tokenizer 和 embedding 表变成语言 token：

$$ E_I^{(v)}=\phi_{\mathrm{img}}(I_t^{(v)})\in\mathbb{R}^{B\times N_v\times d_\ell}, \qquad E_q=\phi_{\mathrm{text}}(P)\in\mathbb{R}^{B\times L_q\times d_\ell}. $$
$$ X_{\mathrm{vlm}}=[E_I^{(1)};\ldots;E_I^{(V)};E_q] \in\mathbb{R}^{B\times(VN_v+L_q)\times d_\ell}. $$

分号表示沿 token 维拼接。输出是词表 logits：

$$ O=\mathrm{LMHead}(\mathrm{Transformer}_\theta(X_{\mathrm{vlm}},M_{\mathrm{prefix}})) \in\mathbb{R}^{B\times L\times|\mathcal{V}|}. $$

这里 \(|\mathcal{V}|\) 是词表大小。VLM-only 没有 \(\hat A_t\)，因此不能直接执行；它在本地项目里主要用于额外 VLM batch 或图文语义保持。

3.3.2 π0 / Flow Matching：连续 action chunk 主路径

π0 模式把图文作为 prefix，把机器人 state 和 noisy action chunk 作为 action suffix。图文 prefix 为：

$$ X_{\mathrm{pre}}=[\phi_{\mathrm{img}}(I_t^{(1)});\ldots;\phi_{\mathrm{img}}(I_t^{(V)});\phi_{\mathrm{text}}(P)]. $$

连续 state 被投影成一个 state token：

$$ E_s=(W_s s_t)[:,None,:]\in\mathbb{R}^{B\times1\times d_a}. $$

训练时先从真实动作块 \(A_0\) 和高斯噪声块 \(\epsilon\) 构造 noisy action chunk：

$$ \epsilon\sim\mathcal{N}(0,I),\qquad A_\tau=\tau\epsilon+(1-\tau)A_0,\qquad u_\tau=\epsilon-A_0. $$

注意这里的 \(\epsilon\) 和 \(A_\tau\) 都是一整段未来动作，形状是 \(\mathbb{R}^{B\times H\times D_a}\)，不是单步动作。action token 和时间 token 为：

$$ E_A=W_A A_\tau\in\mathbb{R}^{B\times H\times d_a}, \qquad E_\tau=\mathrm{repeat}(\gamma(\tau),H)\in\mathbb{R}^{B\times H\times d_a}. $$
$$ X_{\mathrm{suf}}=[E_s;\mathrm{MLP}(E_A,E_\tau)]. $$

模型输出不是最终动作，而是 action tensor 空间里的 flow velocity：

$$ \hat u_\theta =W_o\,\mathrm{ActionExpert}_\theta(X_{\mathrm{suf}}\mid X_{\mathrm{pre}}) \in\mathbb{R}^{B\times H\times D_a}. $$

训练目标是让 \(\hat u_\theta\) 拟合 \(u_\tau\)：

$$ \mathcal{L}_{\mathrm{FM}} = \mathbb{E}_{A_0,\epsilon,\tau} \left[ \left\| v_\theta(A_\tau,\tau,I,q,s_t)-(\epsilon-A_0) \right\|_2^2 \right]. $$

推理时从一整块随机动作开始，并用 Euler 积分逐步更新：

$$ A^{(0)}\sim\mathcal{N}(0,I),\qquad A^{(k+1)}=A^{(k)}+\Delta\tau\,v_\theta(A^{(k)},\tau_k,I,q,s_t). $$

最后得到 \(\hat A_t=A^{(K)}\)。每个积分步是串行的，但在同一次 forward 内，\(H\) 个未来动作 token 是并行更新的；部署时通常只执行前 1 步或前几步，再重新观测并重采样。

3.3.3 π0.5：离散 state token + 连续 flow 动作头

π0.5 的关键区别是 state 不再只作为 \(W_s s_t\) 的连续 suffix，而是先离散化后写进 prompt。概念上可以写成：

$$ \tilde s_{t,j}=\mathrm{clip}\left(\frac{s_{t,j}-\mu_j}{\sigma_j},-1,1\right), \qquad b_j=\mathrm{digitize}(\tilde s_{t,j})\in\{0,\ldots,255\}. $$
$$ P_{\pi0.5}=\mathrm{Tok}(\text{Task: }q,\text{ State: }b_1,\ldots,b_{D_s},\text{ Action:}). $$

因此 prefix 变成：

$$ X_{\mathrm{pre}}=[\phi_{\mathrm{img}}(I);\phi_{\mathrm{text}}(P_{\pi0.5})]. $$

但动作输出仍是 continuous flow：模型仍接收 \(A_\tau\)，仍预测 \(\hat u_\theta\)，仍通过积分得到 \(\hat A_t\)。所以 π0.5 的“离散”主要发生在 state 承载方式上，不代表动作也一定由 FAST token 生成。

3.3.4 π0-FAST / fast_only：动作作为语言 token 自回归生成

FAST 模式把真实动作块编码成离散动作 token：

$$ Z=T_{\mathrm{FAST}}(A_0)=[z_1,\ldots,z_{L_z}], \qquad z_i\in\{0,\ldots,K_{\mathrm{fast}}-1\}. $$

这些 token 再映射到 VLM 词表中的预留动作 token 区域：

$$ \tilde z_i=\psi(z_i)\in\mathcal{V}_{\mathrm{VLM}}, \qquad P_{\mathrm{full}}=[P_{\mathrm{prefix}};\tilde z_1;\ldots;\tilde z_{L_z}]. $$

模型像语言模型一样预测下一个动作 token：

$$ p_\theta(\tilde z_i\mid I,q,s_t,\tilde z_{<i}) =\mathrm{softmax}(O_i). $$
$$ \mathcal{L}_{\mathrm{FAST}} =-\sum_{i=1}^{L_z}\log p_\theta(\tilde z_i\mid I,q,s_t,\tilde z_{<i}). $$

推理时可以 argmax，也可以按 temperature 采样：

$$ \hat z_i=\arg\max_z p_\theta(z\mid I,q,s_t,\hat z_{<i}) \quad\text{or}\quad \hat z_i\sim p_\theta(\cdot\mid I,q,s_t,\hat z_{<i}). $$

最终由 FAST decoder 反解码成连续动作块：

$$ \hat A_t=D_{\mathrm{FAST}}([\hat z_1,\ldots,\hat z_{\hat L}]) \in\mathbb{R}^{B\times H\times D_a}. $$

因此 fast_only 与 π0 flow 的区别非常清楚：fast_only 的生成顺序是 token 串行；π0 flow 的采样顺序是积分步串行、动作块内部并行。FAST token 不一定与每个原始动作维度一一对应，它是压缩后的动作序列表示。

3.3.5 FAST CE 辅助：训练期动作语义监督，不等于最终输出路径

本地主线更常见的做法不是 fast_only，而是把 FAST token 作为辅助 CE。也就是同一个真实动作块 \(A_0\) 同时产生连续 flow 监督和离散 token 监督：

$$ A_\tau=\tau\epsilon+(1-\tau)A_0,\qquad Z=T_{\mathrm{FAST}}(A_0). $$

训练 prompt 中追加动作 token span，但 labels 只在 FAST span 上保留监督，其他位置置为 ignore：

$$ \mu_i= \begin{cases} 1,& i\in\text{FAST action span}\\ 0,& \text{otherwise} \end{cases} ,\qquad \mathcal{L}_{\mathrm{FAST-CE}} =-\sum_i\mu_i\log p_\theta(y_i\mid y_{<i},I,q). $$

总损失可写为：

$$ \mathcal{L} = \mathcal{L}_{\mathrm{FM}} +\lambda_{\mathrm{fast}}\mathcal{L}_{\mathrm{FAST-CE}} +\lambda_{\mathrm{vlm}}\mathcal{L}_{\mathrm{VLM}}. $$

关键防泄漏约束是：action expert 不能 attend 到训练 prompt 里的 GT FAST token，否则 FM 动作头会抄答案：

$$ M_{\mathrm{action}\leftarrow\mathrm{GT\text{-}FAST}}=-\infty. $$

推理时若仍走默认路径，则没有 GT FAST token，最终动作仍来自 sample_actions -> infer_action -> action_decoder -> flow integration。

3.3.6 state token 监督：让 VLM 分支理解机器人状态

state token 监督解决的是 proprioception 语义对齐问题。连续 state 可以走 action suffix：

$$ E_s=(W_s s_t)[:,None,:], $$

也可以离散成语言 token span：

$$ P_{\mathrm{state}}=[\mathrm{Tok}(\text{state_start});\mathrm{Tok}(b_1),\ldots,\mathrm{Tok}(b_{D_s});\mathrm{Tok}(\text{state_end})]. $$

若启用 state token supervision，则额外对 state span 做 CE：

$$ \mathcal{L}_{\mathrm{state}} =-\sum_{j=1}^{D_s}\log p_\theta(b_j\mid I,q,b_{<j}). $$

它本身不输出可执行动作，而是让 VLM hidden state 对关节角、夹爪、末端位姿等机器人状态更敏感。最终执行动作仍由 flow action chunk 或 FAST decoder 给出。

3.3.7 slowfast / fastobs：视觉语义路径与动作视觉路径分开

slowfast/fastobs 是本地 QwenVL/PiZero 的结构性改造。slow 路径给 VLM 做图文语义理解，fastobs 路径给 action expert 更直接的视觉特征：

$$ X_{\mathrm{vlm}}=[\phi_{\mathrm{img}}^{slow}(I);\phi_{\mathrm{text}}(P)] \in\mathbb{R}^{B\times L_{\mathrm{vlm}}\times d_\ell}, $$
$$ X_{\mathrm{fastobs}}=W_f\,\phi_{\mathrm{img}}^{fast}(I) \in\mathbb{R}^{B\times N_f\times d_a}, \qquad X_{\mathrm{action}}=[W_s s_t;\mathrm{MLP}(W_AA_\tau,\gamma(\tau))]. $$

联合 mixture transformer 可抽象为：

$$ (Y_{\mathrm{vlm}},Y_{\mathrm{fastobs}},Y_{\mathrm{action}}) =J_\theta(X_{\mathrm{vlm}},X_{\mathrm{fastobs}},X_{\mathrm{action}};M_{\mathrm{mix}}). $$

最终动作仍通常来自 action path：

$$ \hat u_\theta=W_oY_{\mathrm{action},-H:}, \qquad \hat A_t=\mathrm{EulerIntegrate}(\hat u_\theta). $$

它的动机是让动作头看到更接近控制的视觉细节，而不是完全依赖 VLM 语义 token。风险是 fast visual feature 的统计分布若没有和 action expert 对齐，可能出现“视觉更丰富、动作更差”的退化。

3.3.8 VLA + VLM 混合训练：同一 backbone 上混两类任务

VLA + VLM co-train 是训练组织方式。action batch 形如 \((I,q,s_t,A_0)\)，普通 VLM batch 形如 \((I,q,Y)\)。前者监督动作，后者监督文本：

$$ \mathcal{L}_{\mathrm{total}} = \mathbf{1}_{\mathrm{action}} \left( \mathcal{L}_{\mathrm{FM}} +\lambda_{\mathrm{fast}}\mathcal{L}_{\mathrm{FAST}} +\lambda_{\mathrm{state}}\mathcal{L}_{\mathrm{state}} \right) + \mathbf{1}_{\mathrm{vlm}}\lambda_{\mathrm{vlm}}\mathcal{L}_{\mathrm{VLM}}. $$

这里 \(\mathbf{1}_{\mathrm{action}}\) 和 \(\mathbf{1}_{\mathrm{vlm}}\) 表示当前 batch 类型。这个模式的输出取决于 batch：action batch 输出 \(\hat A_t\) 或 action token，VLM batch 输出文本 logits。它不是新的动作解码器，而是防止 VLA 训练把 VLM 的图文能力冲坏。

读这些模式的最短路径:
  if mode == "VLM-only":
      images/text -> VLM tokens -> text logits
  elif mode == "pi0 / flow":
      images/text/state/noisy_action_chunk -> action velocity -> integrate -> continuous action chunk
  elif mode == "pi0-FAST / fast_only":
      images/text/state -> autoregressive FAST tokens -> FAST decoder -> continuous action chunk
  elif mode == "FAST CE auxiliary":
      use FAST tokens only as training labels; final execution usually still uses flow action chunk
  elif mode == "slowfast":
      add fast visual tokens as extra condition for the action expert

3.4.1 官方 OpenPI 原型：π0 flow 与 π0-FAST 是两条不同输出路径

官方 OpenPI 中，π0 的主干可抽象成“PaliGemma 视觉语言 prefix + action expert suffix”。输入观测（observation）包含多视角图像、图像 mask、机器人状态和 tokenized prompt；输出是未来 \(H\) 步动作块 \(A_t\in\mathbb{R}^{H\times D_a}\)。π0 训练不是直接回归动作，而是先构造 noisy action chunk：

$$ x_0\sim\mathcal{N}(0,I),\quad x_1=A^\star,\quad \tau\sim p(\tau),\quad x_\tau=\tau x_0+(1-\tau)x_1. $$

官方实现里目标速度场是从干净动作指向噪声的方向：

$$ u_\tau=x_0-x_1,\qquad \mathcal{L}_{\pi0} = \mathbb{E}_{x_0,x_1,\tau} \left[ \left\| v_\theta(x_\tau,\tau\mid I,q,s_t)-u_\tau \right\|_2^2 \right]. $$

推理时从高斯噪声开始，沿 \(\tau:1\rightarrow0\) 反向积分。若步数为 \(K\)，\(\Delta\tau=-1/K\)，则：

$$ x^{(0)}\sim\mathcal{N}(0,I),\qquad x^{(k+1)}=x^{(k)}+\Delta\tau\, v_\theta(x^{(k)},\tau_k\mid I,q,s_t). $$

因为 \(\Delta\tau<0\)，虽然 \(v_\theta\) 学的是 \(x_0-x_1\)，积分仍会把噪声推回动作。官方 pi0.py 中的 compute_loss、sample_actions、prefix/suffix mask 和 action projection 基本对应这套流程 [14]。

π0-FAST 则是另一条官方输出路径。它先把连续动作块编码成离散 token：

$$ Z=T_{\mathrm{FAST}}(A^\star)=[z_1,\ldots,z_L], \qquad z_i\in\{0,\ldots,K_{\mathrm{fast}}-1\}, $$

再把 \(z_i\) 映射到 VLM 词表的动作 token 区间，像语言模型一样自回归预测下一个动作 token：

$$ \mathcal{L}_{\pi0\text{-FAST}} =-\sum_{i=1}^{L} \log p_\theta(z_i\mid I,q,s_t,z_{<i}). $$

推理完成后再由 FAST decoder 得到连续动作 \(\hat A_t=D_{\mathrm{FAST}}(\hat Z)\)。因此官方边界非常清楚：π0 是 continuous flow action head；π0-FAST 是 autoregressive action-token head；FAST tokenizer 是官方已有组件，不应被误判为本地原创 [15][16]。

No-discrete-state / empty-action 输入官方 OpenPI observation 里保留连续 state；π0.5 可以把 state/prompt 变体作为条件，但不会在训练 prompt 里故意放入无效 action 占位再用 flow 解码。本地高分锚点启用 --model.no_discrete_state_input 与 --model.empty_action_inputs：离散 state span 不进入 VLM prompt；训练/评估 collator 用 INVALID_MIN_ACTION_VALUE 替换 action 输入占位，真实动作只作为 flow target。它改变了信息可见性：VLM 不再通过离散 state/action token 看到答案，action expert 必须从图像、任务、连续 state 与噪声动作块中恢复动作。强组合证据：224_h10_40000 与 448_wo_pretrain_15000 路径均含 no_discrete_state_input；但不能单独证明 empty-action 比非 empty 更优。
slowfast / fastobs官方 OpenPI 主要由 PaliGemma 视觉 token 条件 action head；没有本地这种 DINO fast visual mixture。本地 slowfast 下额外用 DINO 抽取多视角 fast visual tokens，经 projector 对齐到 action hidden size，作为 fastobs mixture 条件动作头。这是模型结构级改造：视觉语义理解路径和动作控制视觉路径分开，动作头可以读取更局部、更控制相关的视觉特征。中强证据：最强 LIBERO run 名包含 sf2；但需要关掉 slowfast 的 ablation 才能量化其单独贡献。
Action block 双向注意力官方 π0 的 suffix/action block 有 prefix/suffix mask；动作 token 通常按既定 mask 读取 prefix 与 action 条件。本地在 mask builder 中新增 bidirectional_action_attention，把最后 \(H\) 个 action token 的 \([action,action]\) 子块置零，使整段 action chunk 内部互相可见；还可选 bidirectional_image_action_attention 让 image/text 与 action 双向互读。这改变了 \(H\)-step chunk 的条件独立性：每个未来步不再只由历史或单步位置决定，而能显式协调整段动作轨迹。高分 224 shell 明确启用 --model.bidirectional_action_attention；448/pretrain 路径名出现 bidirectionalimage，但精确训练脚本未完整对齐，需按 serve/config 再复核。
fp32 action stream / action expert官方 OpenPI/JAX 路径对 action projection 与 flow loss 有自己的数值精度策略；普通 HF/PyTorch VLM 训练常会整体用 bf16/AMP。本地新增 action_stream_fp32 与 action_expert_fp32：action encoder、time embedding、action decoder、action expert、multi-modal projector 与部分 norm/vision embedding 在 fp32 中运行或保存梯度。这是数值设计改造，不是硬件参数：flow target 和 velocity MSE 对小量连续动作很敏感，bf16 可能让 action residual、LayerNorm 或 projector 出现精度损失。三条 serve log 都记录 action_expert_fp32 和 _ensure_action_stream_fp32；它支撑训练/评估稳定性，但仍缺少 fp32 on/off 消融。
训练混合官方训练以 OpenPI 数据 transforms、行为克隆/flow objective 和官方配置组织。本地训练脚本同时组织 action batch、FAST CE、可选 state CE、普通 VLM batch、DeepSpeed 参数组和 VLM/action 分学习率。训练目标和 batch composition 改变模型行为，因此算训练设计改造。代码证据强；但 loss 组合有覆盖风险，需复现实验中记录 loss_action、fast_ce、vlm_loss 是否都进入最终 loss.backward()。
评估/部署 harness官方提供 policy serving、数据配置和 eval 入口。本地落档包含 LIBERO batch prediction server、RoboCasa client/logs、max_batch_size=4、max_wait_time=0.030s 等部署评估流水。这是工程 pipeline/评估改造，不是模型算法本身；但它决定可复现性和吞吐。LIBERO/RoboCasa 结果是训练模型可用性的主要证据，不能当作每个子模块的消融证明。

3.4.3 改造点一：QwenVL/PiZero joint mixture 重接线

一句话直觉：官方 OpenPI/π0 的关键思想是“视觉语言模型看懂场景，action expert 生成连续动作”；本地第一大改造是把这个结构从官方 PaliGemma/OpenPI 体系重接到 QwenVL/PiZero/HF-PyTorch 体系，并显式拆成 vlm、action、fastobs 三个 mixture。它不是简单换模型名，而是改变了 hidden states 如何流动、哪些层共享、哪些层缓存、动作头从哪里读条件。

官方原型抽象。官方 π0 可被写成 prefix/suffix 两块。视觉语言 prefix 是图像和任务文本：

$$ X_{\mathrm{pre}} = \left[ \phi_{\mathrm{img}}^{\mathrm{PG}}(I_t), \phi_{\mathrm{text}}^{\mathrm{Gemma}}(q) \right] \in\mathbb{R}^{B\times L_{\mathrm{pre}}\times d_\ell}. $$

action suffix 是机器人状态、noisy action chunk 与时间嵌入：

$$ X_{\mathrm{suf}} = \left[ W_s s_t,\, E_A(x_\tau,\gamma(\tau)) \right] \in\mathbb{R}^{B\times (1+H)\times d_a}. $$

模型输出 action suffix 的最后 \(H\) 个 hidden states，并线性投影到动作速度场：

$$ Y_{\mathrm{suf}} = T_\theta(X_{\mathrm{pre}},X_{\mathrm{suf}};M)_{\mathrm{suf}}, \qquad \hat u_\theta = W_o\,Y_{\mathrm{suf},-H:}. $$

这里的 \(M\) 是 prefix/suffix attention mask。这个设计的含义是：语言视觉模型负责提供条件表示，动作 expert 负责连续控制；动作不是从普通文本 logits 里直接抽出来。

本地改造的数学形式。本地把上面的两块拆成三路 mixture：

$$ X_v=\Phi_{\mathrm{QwenVL}}(I_t,q) \in\mathbb{R}^{B\times L_v\times d_\ell}, \qquad X_f=P_f\,\Phi_{\mathrm{DINO}}(I_t) \in\mathbb{R}^{B\times N_f\times d_a}, $$
$$ X_a= \left[ E_s(s_t),\, E_A(x_\tau,\gamma(\tau)) \right] \in\mathbb{R}^{B\times (1+H)\times d_a}. $$

联合模型不再只是“一个 prefix 加一个 suffix”，而是显式维护三组 mixture：

$$ (Y_v,Y_f,Y_a) = J_\theta^{\mathrm{mix}} \left( X_v,X_f,X_a;\, M_{\mathrm{mix}} \right), \qquad \hat u_\theta=W_o\,Y_{a,-H:}. $$

其中 \(X_v\) 是语义慢路径，\(X_f\) 是动作视觉快路径，\(X_a\) 是连续动作路径。这个改造的核心不在“用了 QwenVL”这一个事实，而在于本地把不同来源的 hidden states 重新放进一个 mixture transformer，让 action path 可以同时读取 QwenVL 的任务语义和 fastobs 的视觉细节。

本地代码证据。在 pizero_qwenvl_fast_fortrainer.py:562-569，本地直接把预训练 VLM 和 action expert 的层接到 joint model 的三个 mixture 上：

# 本地核心重接线：不同 mixture 复用不同来源的层与 norm
self.joint_model.mixtures.vlm.layers = pretrained_model.language_model.layers
self.joint_model.mixtures.fastobs.layers = pretrained_model.action_expert.layers
self.joint_model.mixtures.action.layers = pretrained_model.action_expert.layers

self.joint_model.mixtures.vlm.norm = pretrained_model.language_model.norm
self.joint_model.mixtures.fastobs.norm = pretrained_model.action_expert.norm
self.joint_model.mixtures.action.norm = pretrained_model.action_expert.norm

这段代码说明两件事。第一，VLM mixture 不是新训练一个空 transformer，而是复用 Qwen/VLM 的语言层；第二，fastobs 与 action mixture 共享 action expert 的层结构，使视觉快路径和动作路径天然处在 action hidden size 的控制空间里。写成参数集合就是：

$$ \theta_{\mathrm{local}} = \left\{ \theta_{\mathrm{QwenVL}}^{\mathrm{layers}}, \theta_{\mathrm{action\_expert}}^{\mathrm{layers}}, W_f,W_A,W_o \right\}, $$

而不是官方固定的 \(\theta_{\mathrm{PaliGemma}}+\theta_{\mathrm{action}}\)。这种参数重组会影响训练的梯度路径：

$$ \nabla_{\theta_{\mathrm{QwenVL}}}\mathcal{L} \leftarrow \mathcal{L}_{\mathrm{FM}} +\lambda_{\mathrm{FAST}}\mathcal{L}_{\mathrm{FAST}} +\lambda_{\mathrm{VLM}}\mathcal{L}_{\mathrm{VLM}}, \qquad \nabla_{\theta_{\mathrm{action}}}\mathcal{L} \leftarrow \mathcal{L}_{\mathrm{FM}} +\mathcal{L}_{\mathrm{fastobs}}. $$

这里 \(\mathcal{L}_{\mathrm{fastobs}}\) 不是单独写出的 loss，而是指 fastobs hidden states 作为 action 条件参与 \(\mathcal{L}_{\mathrm{FM}}\) 的梯度链路。直观地说：QwenVL 被训练成“看懂任务并给动作头可用条件”，action expert 被训练成“读条件并输出连续动作速度”。

训练 forward 里的实际拼接。在 pizero_qwenvl_fast_fortrainer.py:2390-2447，本地训练根据 slowfast 开关决定是否把 fastobs 放进 joint model：

joint_outputs = self.joint_model(
    attention_mask=causal_mask,
    position_ids_all={
        "vlm": vlm_position_ids,
        "fastobs": img_position_ids,
        "action": action_position_ids,
    } if self.slowfast else {
        "vlm": vlm_position_ids,
        "action": action_position_ids,
    },
    embeds_all={
        "vlm": inputs_embeds,
        "fastobs": fast_obs_embeds,
        "action": action_embeds,
    } if self.slowfast else {
        "vlm": inputs_embeds,
        "action": action_embeds,
    },
    final_layer_post_attn_skip_names=["fastobs"],
    time_cond=time_cond,
    kv_caches={},
)
action_embeds = joint_outputs["action"]
v_psi = self.action_decoder(action_embeds)[:, -self.horizon_steps:, :]

这段代码给出了本地 pipeline 的“拼接点”：inputs_embeds 是 QwenVL 的图文 token，fast_obs_embeds 是 fast visual token，action_embeds 是 noisy action chunk token。三者进入同一个 JointModel 后，只取 joint_outputs["action"] 通过 action_decoder 输出速度场。因此，模型的最终动作输出仍是连续 action expert，而不是 Qwen 的 lm_head 文本 logits。

为什么要这么做。这个改造解决的是“视觉语言理解”和“连续控制精度”之间的错配：

  • 如果只用 VLM 的普通词表输出动作，动作维度、坐标系、夹爪状态和连续小数精度都会受离散 token 表达限制。
  • 如果只训练 action expert，不训练或不接入强 VLM，模型容易缺任务语义、物体语义和跨场景泛化。
  • joint mixture 把这两者分开：QwenVL 负责语义条件，action expert 负责连续控制，fastobs 负责更贴近控制的视觉细节。

形式化地说，原本希望学习的是策略分布：

$$ \pi(a_{t:t+H-1}\mid I_t,q,s_t). $$

本地把它分解成“条件编码 + 动作生成”两步：

$$ c_t=g_{\theta_v,\theta_f}(I_t,q,s_t), \qquad \pi_\theta(A_t\mid O_t) \approx \mathrm{FlowDecode}_{\theta_a}(A^{(0)},c_t), $$

其中 \(c_t\) 同时包含 QwenVL 语义条件和 fastobs 控制视觉条件。这样的好处是：可以复用强 VLM 的开放词汇理解，又不牺牲 action chunk 的连续精度。

有什么用与效果。从落档评估看，最强 224_h10_40000 在 LIBERO goal/object/spatial/libero10 达到 0.99/0.995/0.98/0.93，说明“QwenVL/PiZero joint mixture + flow action chunk + slowfast/修正配置”作为组合是有效的。严格说，这个结果不能证明 joint mixture 单独贡献多少，因为没有只替换 joint mixture 的 ablation；但它能证明本地重接线不是停留在代码层，已经支撑了可用策略。相反，448/pretrain 没有单调变好，说明 joint mixture 对 token 分布、norm stats、视觉分辨率和训练步数敏感，后续复现要优先对齐 224 高分锚点，而不是盲目放大图像分辨率。

3.4.4 改造点二：把 π0 flow action head 移植到 QwenVL/PiZero

Flow matching 不是本地原创；本地真正的改造是把官方 π0 的连续 action chunk 头移植到 QwenVL joint mixture 上，并扩展了时间采样、mask 与积分器。训练时，本地 psi_t 使用如下插值：

$$ x_\tau= \psi_\tau(x_0,x_1) = \left(1-(1-\sigma_{\min})\tau\right)x_0+\tau x_1, \qquad d_\psi=x_1-(1-\sigma_{\min})x_0. $$

模型要学习的是：

$$ \hat d_\theta = W_o\,J_\theta^{action} \left( E_A(x_\tau,\gamma(\tau)) \mid X_v,X_f \right)_{-H:}, \qquad \mathcal{L}_{\mathrm{FM}} = \left\| \hat d_\theta-d_\psi \right\|_2^2. $$

代码证据在 pizero_qwenvl_fast_fortrainer.py:2455-2461：

# action path 输出 velocity field，而不是直接输出动作 token
v_psi = self.action_decoder(action_embeds)[:, -self.horizon_steps:, :]
d_psi = x1 - (1 - self.flow_sig_min) * x0
loss_action = torch.mean((v_psi[action_mask] - d_psi[action_mask]) ** 2)

推理时，本地 infer_action 先缓存 VLM/fastobs 条件，然后只循环 action path。代码证据在 pizero_qwenvl_fast_fortrainer.py:1690-1780：

# 先用条件 mixture 建 KV cache，再从整段动作噪声开始积分
action = torch.randn((bsz, self.horizon_steps, self.action_dim), device=device, dtype=dtype)
delta_t = 1.0 / self.num_inference_steps
t = torch.zeros(bsz, device=device, dtype=dtype)

for step_idx in range(self.num_inference_steps):
    time_cond = self.time_embedding(t)
    action_embeds = self.action_encoder(action, time_cond)
    action_embeds = self.joint_model(
        attention_mask=action_mask,
        embeds_all={"action": action_embeds},
        cache_mode="append_non_active",
        kv_caches=kv_caches,
    )["action"]
    action_vel = self.action_decoder(action_embeds)
    action += delta_t * action_vel
    t += delta_t

这个设计的作用是让 \(H\) 步动作在同一次 forward 中并行更新，只在 flow 积分步上串行。它比逐 token 自回归动作生成更适合连续控制，因为模型直接在 \(\mathbb{R}^{H\times D_a}\) 空间里修正动作块。效果上，LIBERO 高分最能支撑这一点：没有连续 flow action head，就无法解释 224_h10_40000 这种默认 flow 输出路径的成功率。

3.4.5 改造点三：FAST CE 从“主输出”改成“动作语义辅助”，并加防泄漏 mask

官方 π0-FAST 是把动作 token 当主输出：预测 FAST token，再由 FAST decoder 还原动作。本地更有意思的改法是把 FAST 变成训练期辅助监督：GT action 被编码成 token span 放进 prompt，但默认最终输出仍是 flow action chunk。这相当于额外给 VLM 分支一个“动作语言对齐”目标：

$$ Z=T_{\mathrm{FAST}}(A^\star), \qquad \mathcal{L}_{\mathrm{FAST-CE}} = -\sum_i \mu_i\log p_\theta(z_i\mid I,q,z_{<i}), $$

其中 \(\mu_i=1\) 只在 FAST action span 上成立，普通 prompt token 被置为 -100 忽略。代码证据在 train_acebrain.py:349-618：动作被拆成 left/right、base/camera 多个片段，映射到 151669 + fast_token 的 Qwen action token 区间，然后只保留 FAST token 或 state token 的 labels。

FAST_TOKEN_START_ID = 151669
token_fast_token_ids = [FAST_TOKEN_START_ID + i for i in fast_tokens_single]

# 只监督 FAST token；若开启 state token，则额外保留 state span
if self.supervise_state_tokens:
    labels[(labels < FAST_TOKEN_START_ID) & ~state_supervision_mask] = -100
else:
    labels[labels < FAST_TOKEN_START_ID] = -100

为什么需要防泄漏？因为同一个训练样本里同时有：

$$ \text{GT FAST span }Z=T_{\mathrm{FAST}}(A^\star) \quad\text{和}\quad \text{flow target }A^\star. $$

如果 action mixture 可以 attend 到 \(Z\)，那 \(\mathcal{L}_{\mathrm{FM}}\) 可能学成“抄 prompt 里的 GT 动作 token”，而不是从图像和任务条件预测动作。因此本地新增 build_causal_mask_and_position_ids_fast，其语义是：

$$ M_{\mathrm{fast}\leftarrow \mathrm{text}}=0,\quad M_{\mathrm{fast}_i\leftarrow \mathrm{fast}_{\le i}}=0,\quad M_{\mathrm{action}\leftarrow \mathrm{text/proprio/action}}=0,\quad M_{\mathrm{action}\leftarrow \mathrm{GT\text{-}FAST}}=-\infty. $$

代码证据在 pizero_qwenvl_fast_fortrainer.py:302-374：

# fast rows 可以看 text 和历史 fast token
causal_mask[idx, row, :text_cnt] = 0
causal_mask[idx, row, fast_start : fast_start + fast_idx + 1] = 0

# action rows 从 proprio_start 开始可见，避开中间 GT FAST span
causal_mask[idx, action_start:, proprio_start:] = 0

这个改造的思想是“让 VLM 学动作语义，但不让 action head 抄答案”。它的作用是潜在增强 QwenVL hidden states 对动作模式的可分性，尤其是把连续轨迹压缩成可语言建模的离散结构。但效果边界必须写清楚：当前训练循环存在 loss 覆盖风险，loss_action + loss_vlm * lambda_fast_ce 在后续分支可能被 loss_action 或 loss_action + lambda_vlm * loss_vlm_web 覆盖。因此目前不能把 LIBERO 高分归因给 FAST CE；它是明确改造点，但需要单独审计和 ablation。

3.4.6 改造点四：state token 监督与 no-discrete-state 对照

state token 的目标是让 VLM 分支理解机器人状态，而不是只把 state 作为 action expert 的连续输入。数学上，连续 state \(s_t\in\mathbb{R}^{D_s}\) 先归一化再量化：

$$ \bar s_j=\mathrm{clip}\left(\frac{s_j-\mu_j}{\sigma_j},-1,1\right), \qquad b_j=\mathrm{bucketize}(\bar s_j;256)\in\{0,\ldots,255\}. $$

然后把 \(b_j\) 放进 <|state_start|>...<|state_end|>，并在 labels 中保留对应 span。代码证据在 train_acebrain.py:587-615，本地通过 state_supervision_mask 决定哪些 state token 进入 CE：

if self.supervise_state_tokens:
    state_supervision_mask = ...
    labels[(labels < FAST_TOKEN_START_ID) & ~state_supervision_mask] = -100

改造思想是：proprio/state 对机器人策略非常重要，但连续 state 只进入 action expert 时，VLM hidden states 未必知道“当前夹爪开合、末端位姿、左右臂状态”这些语义。state token 让 VLM 也被迫预测或解释状态，从而形成跨模态对齐：

$$ \mathcal{L}_{\mathrm{state}} =-\sum_{j} \log p_\theta(b_j\mid I,q,b_{<j}). $$

作用上，它可能帮助需要状态辨识的任务，比如“已经抓住物体后移动”或“双臂状态不同步”的场景。但最新效果边界很关键：当前 LIBERO 最强 run 名称包含 no_discrete_state_input，说明在该高分锚点上离散 state token 不是必要条件。更合理的结论是：state token 是一个值得做消融的设计分支，而不是已证明有效的默认配置。

3.4.7 改造点五：slowfast / fastobs 给动作头一条控制视觉快路径

slowfast 的思想是把视觉分成两类：QwenVL 的慢路径负责语义，DINO/fastobs 的快路径负责局部视觉和控制细节。数学上：

$$ X_v=\Phi_{\mathrm{QwenVL}}(I,q), \qquad X_f=P_f\,\Phi_{\mathrm{DINO}}(I), \qquad X_a=E_A(x_\tau,\tau,s_t). $$

动作输出依赖二者：

$$ \hat u_\theta = W_o\,J_\theta^{action} \left( X_a\mid X_v,X_f \right). $$

代码证据在 pizero_qwenvl_fast_fortrainer.py:704 和 1515-1595：本地加载 DINO 模型，把多视角图像 flatten 后提特征，再对 patch token 做池化和 projector 对齐到 1024 hidden size：

self.dino_model = AutoModel.from_pretrained(pretrained_model_name, dtype=self.dtype)

img_feats = self.dino_model(img_pixel_values.flatten(0, 1))["last_hidden_state"]
global_img1 = F.max_pool2d(global_img1, kernel_size=2, stride=2)
single_img_feats = torch.cat([global_img, left_img, right_img], dim=2)
img_feats_align = self.multi_modal_projector(img_feats).reshape(
    action_embeds.shape[0], self.num_image_token_fast, 1024
)

为什么这样做？VLM 图像 token 往往服务于语言理解，未必保留足够直接的位姿、边缘、局部接触几何；动作控制却非常依赖这些低层视觉细节。fastobs 相当于给 action expert 加一条更短的视觉通道，减少“语义懂了但动作不准”的问题。效果上，最强 LIBERO run 的路径中包含 sf2，这是 slowfast 组合有效的中强证据；但仍需要关掉 fastobs 的公平消融，才能定量说明它单独带来多少提升。

3.4.8 改造点六：action block 双向注意力，把 action chunk 当作一整段轨迹建模

一句话直觉：官方 π0 的 action suffix 已经能让动作 token 读取视觉语言条件；本地进一步把最后 \(H\) 个 action token 的内部 attention 改成全连接。这样每个未来步 \(a_{t+h}\) 在预测速度时，不只知道自己的 noisy token 或历史 token，还能看到同一个 action chunk 内的其他未来步，从而把“10 步动作”当成一段协同轨迹，而不是 10 个近似独立的点。

用 mask 写最清楚。设最终 joint 序列长度为 \(L\)，action block 的索引集合为

$$ \mathcal{A}=\{L-H,\ldots,L-1\}. $$

若保持普通 causal action mask，action block 内常见形式是：

$$ M^{\mathrm{causal}}_{ij}= \begin{cases} 0, & i,j\in\mathcal{A},\, j\le i,\\ -\infty, & i,j\in\mathcal{A},\, j>i. \end{cases} $$

本地 bidirectional_action_attention 做的事情是直接把 action-action 子块全部放开：

$$ M^{\mathrm{bi}}_{ij}=0,\qquad \forall i,j\in\mathcal{A}. $$

于是第 \(h\) 个动作速度不再只是

$$ \hat u_h=f_\theta(x_{\tau,h},c_t), $$

而是可以显式依赖整段 noisy action chunk：

$$ \hat u_h=f_\theta(x_{\tau,1:H},c_t,h), \qquad \hat U=\left[\hat u_1,\ldots,\hat u_H\right]. $$

这对机器人控制很关键：轨迹需要满足速度连续、夹爪开合时序、靠近-接触-抓取-抬起等跨步约束。如果每个未来步只在很弱的条件下独立预测，容易出现局部动作合理但整段轨迹不连贯的问题。

本地代码证据。pizero_qwenvl_fast_fortrainer.py:215-232 中的 helper 明确把 action 子块置零：

def _apply_bidirectional_action_attention(causal_mask, num_action_tokens):
    # action tokens occupy the last num_action_tokens rows/cols
    L = causal_mask.shape[-1]
    action_start = L - num_action_tokens
    action_end = L

    # every action token can attend to every other action token
    causal_mask[:, :, action_start:action_end, action_start:action_end] = 0

同一文件 build_causal_mask_and_position_ids 在 bidirectional_action_attention=True 时调用该 helper；sample_actions 的评估入口也把 self.bidirectional_action_attention 继续传入 mask builder，说明训练/评估使用的是同一类 action block 结构，而不是只在训练里打开。训练 shell train_sf_libero_cyx_bidirectional_fix_zero_right_wrist_no_discrete_state_vlm.sh 第 45 行显式包含 --model.bidirectional_action_attention。

Algorithm Action-Block-Bidirectional-Mask
Input:
  M                  # joint attention mask, shape [B, 1, L, L]
  H                  # action_horizon / num_action_tokens

# 1. 找到最后 H 个 action token
A = range(L - H, L)

# 2. 保持文本、图像、fastobs、proprio 的原始可见性约束
keep_existing_mask_for_non_action_blocks(M)

# 3. 只改 action-action 子块
for i in A:
    for j in A:
        M[:, :, i, j] = 0      # action chunk 内部双向可见

return M

它和官方路径的差异。这不是普通的“多跑几步推理”或“改 batch size”。它改的是 transformer 内部的可见性图 \(G=(V,E)\)：官方/基础 causal suffix 更像一条从 prefix 到 suffix 的有向图；本地 action block 在 \(\mathcal{A}\) 内形成完全图。也就是说，本地把 \(H\)-step action chunk 的建模假设从弱自回归改成了块级协同。

效果边界。224_h10_40000 的 checkpoint 名和训练 shell 都把 bidirectional 作为核心配置，同时 LIBERO 四套评估达到 0.99/0.995/0.98/0.93。因此可以说“高分组合启用了 action block 双向注意力”。但还不能说“提升全部来自双向注意力”，因为同一 run 还同时启用了 slowfast-DINO、fp32 action stream、no-discrete-state、empty-action、mask-pad-image 和 right-wrist fix。复现实验应做 bidirectional_action_attention=True/False 的单变量 ablation，并记录每个 suite 的失败类型。

3.4.9 改造点七：fp32 action stream，保护连续 flow 速度场的数值精度

一句话直觉：VLM 主干用 bf16/AMP 很常见，因为语言视觉 token 对少量舍入误差相对鲁棒；但 flow action head 学的是连续动作速度场，目标通常是很小的实数残差。把 action encoder、time embedding、action decoder、action expert 和 projector 的关键路径提升到 fp32，是为了让连续控制的误差不要被低精度吞掉。

本地训练的核心损失是：

$$ \mathcal{L}_{\mathrm{FM}} = \frac{1}{|\Omega|} \sum_{(h,d)\in\Omega} \left( \hat u_{h,d}-u_{h,d} \right)^2, \qquad \hat u=W_oY_a. $$

如果 \(u_{h,d}\) 和 \(\hat u_{h,d}\) 的差值本来就在 \(10^{-3}\sim10^{-2}\) 量级，bf16 的尾数精度可能让微小差异、LayerNorm 统计或 projector 输出变得不稳定。因此本地把 action-side dtype 设计成：

$$ \mathrm{dtype}(x_\tau,t,E_A,W_o,\hat u,u,\mathcal{L}_{\mathrm{FM}}) =\mathrm{float32}, \qquad \mathrm{dtype}(X_v)\approx\mathrm{bf16}. $$

这里不是全模型 fp32，而是“动作流 fp32、VLM 主干保持低精度”的折中：

$$ Y_a = J_\theta^{\mathrm{action}} \left( \mathrm{fp32}(E_A(x_\tau,t)), \mathrm{fp32}(X_f), \mathrm{bf16}(X_v) \right), \quad \hat u=\mathrm{fp32}(W_oY_a). $$

本地代码证据。pizero_qwenvl_fast_fortrainer.py:977-979 读取两个开关，2627-2688 定义 fp32 helper：

self.action_stream_fp32 = getattr(pi0_config, "action_stream_fp32", False)
self.action_expert_fp32 = getattr(pi0_config, "action_expert_fp32", False)

def _action_stream_torch_dtype(self):
    return torch.float32 if self.action_stream_fp32 else self.dtype

def _ensure_action_stream_fp32(self):
    # action-side MLPs and flow matching tensors run in fp32
    self._ensure_action_expert_fp32_if_configured()
    if not self.action_stream_fp32:
        return
    for mod in [self.action_encoder, self.time_embedding, self.action_decoder]:
        mod.to(torch.float32)
    self._ensure_numerics_fp32()

训练脚本 train_pytorch_qwen3_fast_zhi.py:3308-3314 还有一个容易忽略但很重要的细节：如果开了 action_stream_fp32 或 action_expert_fp32，最终反传的 scalar loss 不再被强制 cast 到 bf16，而是保持 fp32：

action_stream_fp32 = getattr(config.model, "action_stream_fp32", False)
action_expert_fp32 = getattr(config.model, "action_expert_fp32", False)
if action_stream_fp32 or action_expert_fp32:
    loss_for_backward = loss_for_backward.to(torch.float32)
else:
    loss_for_backward = loss_for_backward.to(model_train_dtype)

serve 日志给出评估侧证据：三条目标 run 都打印了 action_expert_fp32: cast pretrained_model.action_expert to float32、action_expert_fp32: cast multi_modal_projector to float32 与 Applied _ensure_action_stream_fp32 before torch.compile。这说明评估时用的不是纯 bf16 action head，而是 fp32 action/action-expert 路径。

为什么有用。连续 action chunk 的 flow 积分会累积误差：

$$ A^{(k+1)}=A^{(k)}+\Delta t\,\hat u_\theta(A^{(k)},t_k,c_t). $$

若每一步速度场都有舍入误差 \(\epsilon_k\)，则 \(K\) 步后的动作误差近似为：

$$ \Delta A^{(K)} \approx \sum_{k=0}^{K-1}\Delta t\,\epsilon_k + \text{higher-order terms}. $$

这类误差在语言生成里可能只影响一个 logit 排序，但在机器人控制里会直接变成末端位姿偏差、夹爪开合时机偏差或接触点偏差。fp32 action stream 的思想就是把数值预算优先给最接近控制输出的那条路径。

效果边界。fp32 action stream 是稳定性设计，serve 日志能证明三条目标 run 评估时启用了它；但当前报告没有发现 fp32/bf16 的单变量消融，不能定量说它提升了多少成功率。复现时建议至少记录 loss_action 是否出现 NaN/Inf、action velocity 的范数分布，以及 fp32 关闭时 LIBERO10 是否更容易退化。

3.4.10 改造点八：no-discrete-state / empty-action，训练和评估都减少“答案泄漏”

一句话直觉：这组策略的核心不是“少给模型信息”，而是“不给 VLM prompt 里那些可能让模型走捷径的信息”。真实 state 和真实 action 仍然存在：state 可以作为连续 proprio/action 条件进入模型，真实动作 \(A^\star\) 作为 flow target 训练；但离散 state token 和动作输入占位不再把答案以 token 或连续值的形式暴露给 VLM/action prompt。

先看 no-discrete-state。启用前，状态可能同时以连续向量和离散 token 两种方式进入：

$$ c_t = g_\theta(I_t,q,E_s(s_t),T_s(s_t)), $$

其中 \(T_s(s_t)\) 是 bucketized state token span。启用 no_discrete_state_input 后，条件变成：

$$ c_t = g_\theta(I_t,q,E_s(s_t)), \qquad T_s(s_t)\notin \mathrm{prompt}. $$

这让 VLM 不再通过文本 token 记忆某些状态模板，而是让状态信息走连续 proprio/action 条件通道。对 LIBERO 这种短时程操作任务，最强 run 表明这个约束没有阻碍高分。

再看 empty-action。训练 collator 仍然拿到真实动作 \(A^\star\)，但它把“作为模型输入的动作占位”替换成无效常数：

$$ \tilde A_{\mathrm{input}}= \begin{cases} A^\star, & \text{ordinary action input},\\ c_{\mathrm{invalid}}\mathbf{1}, & \text{empty-action input}. \end{cases} $$

flow matching 的 target 仍然来自 \(A^\star\)：

$$ x_1=A^\star,\quad x_\tau=\psi_\tau(x_0,x_1),\quad u_\tau=x_1-(1-\sigma_{\min})x_0. $$

也就是说，empty_action_inputs 不是“没有动作监督”，而是“不给 prompt/action input 一个可抄的真实动作”。代码证据在 train_pytorch_qwen3_fast_zhi.py:494-497：

actions_for_input = actions.clone()
if self.empty_action_inputs:
    actions_for_input = torch.ones_like(actions_for_input) * INVALID_MIN_ACTION_VALUE

评估时也保持同一思想。pizero_qwenvl_fast_fortrainer.py:4902-5017 的 sample_actions 重新构造 eval DataCollator，并固定 empty_action_inputs=True；真实动作在推理时本来不可得，dummy action 只作为形状和 mask 占位：

dummy_actions = torch.ones(batch_size, 1, self.action_dim) * INVALID_MIN_ACTION_VALUE

data_collator = DataCollatorClass(
    train=False,
    split_mask=True,
    sample_fm_time=False,
    force_fast_tokens=False,
    empty_action_inputs=True,
    discrete_state_input=getattr(self.model_config_struct, "discrete_state_input", True),
)

这组策略的 pipeline 可以写成：

Algorithm No-Discrete-State-And-Empty-Action
Input:
  observation O_t = {images, continuous_state, instruction}
  ground_truth action chunk A*              # 训练期可见，评估期不可见
  flags = {no_discrete_state_input, empty_action_inputs}

# 1. prompt 中不放离散 state span
if no_discrete_state_input:
    prompt = render(instruction, images)
else:
    prompt = render(instruction, images, bucketized_state_tokens)

if empty_action_inputs:
    action_input = INVALID_MIN_ACTION_VALUE * ones_like(A*)
else:
    action_input = A*

# 3. 真实动作只进入 flow supervision，不进入可抄的 prompt/action placeholder
x0 = Normal(0, I)
x1 = A*
x_tau = psi_t(x0, x1, tau)
target_velocity = x1 - (1 - sigma_min) * x0

# 4. 模型必须从图像、文本、连续 state 和 noisy action 中恢复速度场
condition = JointModel.prefill(vlm_tokens=prompt, proprio=continuous_state)

和官方路径的差异。官方 OpenPI 数据 transform 会把 observation/action 规范化成 policy 需要的字段；本地这里的改造不是“字段名适配”，而是改变训练时哪些信息进入 prompt、哪些信息只能作为监督目标。它更接近一种 anti-leakage / modality-isolation 设计：把答案从输入侧移走，把监督留在 loss 侧。

效果边界。224_h10_40000 的精确训练 shell 同时包含 --model.no_discrete_state_input 与 --model.empty_action_inputs，并且对应 LIBERO 平均成功率约 0.974；448_wo_pretrain_15000 serve path 也含 no_discrete_state_input。这说明 no-discrete/empty-action 至少与高分 flow 输出路径兼容。更强的结论需要四组对照：离散 state on/off \(\times\) empty-action on/off，且保持 checkpoint step、slowfast、fp32、bidirectional 和数据完全一致。

3.4.11 改造点九：VLA/VLM 混训与 IQL/offline RL 扩展

混训的目的不是改变动作解码器，而是避免 VLA 训练把 QwenVL 的图文能力冲坏，同时让 VLM hidden states 保持可解释的动作语义。理想损失应为：

$$ \mathcal{L}_{\mathrm{total}} = \mathcal{L}_{\mathrm{FM}} +\lambda_{\mathrm{fast}}\mathcal{L}_{\mathrm{FAST}} +\lambda_{\mathrm{state}}\mathcal{L}_{\mathrm{state}} +\lambda_{\mathrm{vlm}}\mathcal{L}_{\mathrm{VLM}}. $$

但当前训练循环需要重点审计。train_acebrain.py:1768-1805 显示，FAST CE 被加到 loss 后，后面又根据 use_vlm_data 重新赋值：

loss_action, loss_vlm = model_engine(**inputs)
loss = loss_action + loss_vlm * lambda_fast_ce

if use_vlm_data and loss_vlm is not None:
    loss = loss_action + vlm_loss_weight * loss_vlm
else:
    loss = loss_action

这意味着“设计上有 FAST CE 和 VLM 混训”，但“实际反传是否包含 FAST CE”需要跑时确认。复现时应打印最终 backward 标量的分解：

$$ \mathrm{log}\left( \mathcal{L}_{\mathrm{backward}}, \mathcal{L}_{\mathrm{FM}}, \mathcal{L}_{\mathrm{FAST}}, \mathcal{L}_{\mathrm{VLM}} \right), \qquad \frac{\partial \mathcal{L}_{\mathrm{backward}}} {\partial \mathcal{L}_{\mathrm{FAST}}} \stackrel{?}{=}\lambda_{\mathrm{fast}}. $$

IQL/offline RL 分支是另一条训练设计扩展：它试图用 advantage-weighted policy loss 把行为克隆改造成偏向高价值动作的离线 RL。代码证据显示 pizero_qwenvl_rl.py:309 中 final_loss = policy_loss + policy_loss，这会把预期的 value loss 丢掉。它的思想是有价值的，但当前实现更像“待修正实验分支”，不能作为可靠效果来源。

3.4.12 本地端到端 pipeline：从输入到 action chunk

本地训练时，一个样本从机器人观测到损失的完整路径可以写成：

$$ \left(I_t^{base},I_t^{left},I_t^{right},s_t,q,A^\star_{t:t+H-1}\right) \longrightarrow \left(X_{\mathrm{vlm}},X_{\mathrm{fastobs}},X_{\mathrm{action}}\right) \longrightarrow \left(\hat u_\theta,\ell_{\mathrm{FAST}},\ell_{\mathrm{VLM}}\right). $$

其中 \(X_{\mathrm{vlm}}\) 负责图文语义，\(X_{\mathrm{fastobs}}\) 负责快速视觉条件，\(X_{\mathrm{action}}\) 负责 noisy action chunk。训练伪代码如下：

Algorithm Local-OpenPI-VLA-Train-OneBatch
Input:
  images = {base, left_wrist, right_wrist}       # 多视角图像
  state s_t                                     # 机器人当前 proprio/state

  ground_truth_actions A* in R[H, D_a]          # 未来 H 步动作块
  flags = {
    use_fast, supervise_state_tokens, no_discrete_state_input,
    empty_action_inputs, slowfast, bidirectional_action_attention,
    action_stream_fp32, action_expert_fp32, use_vlm_data
  }

# 1. 构造 VLM prompt 与视觉输入

    prompt = QwenVLAProcessor.render(q, images)                 # 不拼 bucketized state span
else:
    prompt = QwenVLAProcessor.render(q, images, state_tokens)

    actions_for_input = INVALID_MIN_ACTION_VALUE * ones_like(A*)
else:
    actions_for_input = A*

tau = sample_fm_time_fn(B)                                      # uniform 或 beta

x1 = A*

# 6. slowfast 视觉路径

else:

上面第 5 步和官方公式的符号略有不同，是因为本地 psi_t 写成：

$$ \psi_\tau(x_0,x_1) =\left(1-(1-\sigma_{\min})\tau\right)x_0+\tau x_1, $$

并把监督速度写成：

$$ d_\psi=x_1-(1-\sigma_{\min})x_0. $$

若 \(\tau=0\)，\(\psi_\tau=x_0\) 接近噪声；若 \(\tau=1\)，\(\psi_\tau=\sigma_{\min}x_0+x_1\) 接近真实动作。这和官方从 \(\tau=1\) 噪声反向走到 \(\tau=0\) 动作的记号方向不同，但本质仍是在学习一条从噪声到动作的条件 vector field。读代码时要看 psi_t、d_psi 和积分器的符号是否配套，而不要只按论文符号机械代入。

kv_cache = JointModel.prefill(vlm=X_vlm, fastobs=X_fastobs, mask=M)

A = Normal(0, I).sample(shape=[B, H, D_a])
if action_stream_fp32:
    A = to_float32(A)

# 4. 数值积分生成 action chunk
for k in 1..K:
    tau = schedule(k)
    X_action = ActionEncoder(A, tau, state)
    Y_action = JointModel.decode_action(X_action, kv_cache)
    velocity = ActionDecoder(Y_action[-H:])
    if action_stream_fp32:
        velocity = to_float32(velocity)
    A = integration_step(A, tau, delta_tau, velocity, method=euler/heun/rk4)

# 5. 后处理
A = clip_or_unnormalize(A)
execute first m steps, then re-observe and replan
Output:
  action chunk A_hat in R[B, H, D_a]

这个流程解释了为什么本地 VLA 不是“LLM 输出一串动作文字”。主输出是连续 action chunk；FAST token 只有在 fast_only 模式下才变成最终动作输出，在默认 flow 路径里更像一种动作语义辅助监督。

把三条 run 的训练样本记为

$$ \mathcal{B} = \left\{ \left(I_t^{high},I_t^{left},I_t^{right},s_t,q,A^\star_{t:t+9},m_A\right)_b \right\}_{b=1}^{B}. $$

其中 \(I_t^{high},I_t^{left},I_t^{right}\) 是 high/left wrist/right wrist 多视角图像，\(s_t\) 是连续机器人状态，\(q\) 是 LIBERO 任务文本，\(A^\star_{t:t+9}\in\mathbb{R}^{10\times72}\) 是未来 10 步动作块，\(m_A\in\{0,1\}^{10\times72}\) 是由 pad/invalid action 产生的有效维度 mask。use_eef_pos_only 让数据侧更关注 end-effector pose/action 字段，但模型张量仍被 pad 到 72 维契约。

目标 run 的 DataCollator 首先做两类“不要把答案放进输入”的处理：

$$ \tilde s_t = \begin{cases} \operatorname{bucket}(s_t), & \text{if discrete-state prompt is enabled},\\ \varnothing, & \text{if no\_discrete\_state\_input is enabled}, \end{cases} \qquad A_{\mathrm{in}} = \begin{cases} A^\star, & \text{if empty\_action\_inputs is false},\\ c_{\mathrm{invalid}}\mathbf{1}, & \text{if empty\_action\_inputs is true}. \end{cases} $$

这里 \(c_{\mathrm{invalid}}\) 对应代码里的 INVALID_MIN_ACTION_VALUE。直觉上，prompt 里不再塞离散 state token，action 输入占位也不再携带真实 \(A^\star\)。真实动作只作为 flow target 进入 loss。对应代码证据是 DataCollator.__call__ 中 state_for_prompt=None 与 actions_for_input = INVALID_MIN_ACTION_VALUE，以及 eval sample_actions 里强制 empty_action_inputs=True。

在 target runs 的 flow_match_mode=default 下，训练 forward 使用本地默认参数化：

$$ x_0\sim\mathcal{N}(0,I),\qquad x_1=A^\star, $$
$$ \psi_\tau(x_0,x_1) = \left(1-(1-\sigma_{\min})\tau\right)x_0+\tau x_1, \qquad d_\psi=x_1-(1-\sigma_{\min})x_0. $$

\(\psi_\tau\) 是送入 action encoder 的 noisy action chunk，\(d_\psi\) 是要拟合的速度场。代码中对应 x0=torch.randn_like(actions)、x1=actions、psi_t=self.psi_t(x0,x1,t)、d_psi=x1-(1-self.flow_sig_min)*x0。如果后续实验改成 flow_match_mode=pi0_flowmatch，则 forward1 的公式会变成 \(x_t=t\epsilon+(1-t)A^\star\)、\(u_t=\epsilon-A^\star\)；但目前 exact 448_wo config 和 224 目标 shell 对应的是 default path。

模型前向可以写成：

$$ E_{\mathrm{vlm}} = f_{\mathrm{QwenVL}}(I_t,q;\tilde s_t),\qquad E_{\mathrm{fastobs}} = P_{\mathrm{fast}}\!\left(f_{\mathrm{DINO}}(I_t)\right), $$
$$ E_{\mathrm{act}}=\operatorname{ActionEncoder}(\psi_\tau,t), \qquad H_{\mathrm{act}} = J_\theta(E_{\mathrm{vlm}},E_{\mathrm{fastobs}},E_{\mathrm{act}};M)_{\mathrm{action}}, $$
$$ \hat v_\theta=\operatorname{ActionDecoder}(H_{\mathrm{act}})_{1:H} \in\mathbb{R}^{B\times10\times72}. $$

\(J_\theta\) 是本地 QwenVL/PiZero joint mixture，\(M\) 是包含 causal、slowfast 与 bidirectional action block 的 attention mask。若 bidirectional_action_attention=True，代码把最后 \(H\) 个 action token 的子块 mask 置零，使一个 action chunk 内部互相可见；这改变的是轨迹块建模方式，不是只改一个训练超参。

有效 flow loss 是带 mask 的 MSE：

$$ \mathcal{L}_{\mathrm{FM}} = \frac{ \sum_{b=1}^{B}\sum_{h=1}^{10}\sum_{d=1}^{72} m_{bhd}\left(\hat v_{\theta,bhd}-d_{\psi,bhd}\right)^2 }{ \max\left(1,\sum_{b,h,d}m_{bhd}\right) }. $$

这正对应代码里的 diff2 = torch.square(v_psi - d_psi)、mask_f = action_mask.to(diff2.dtype)、loss_action = (diff2 * mask_f).sum() / denom。因此训练日志里的 flow_matching_loss 就是这条动作块速度场监督，不是 rollout success，也不是 token perplexity。

完整训练脚本的反传标量可抽象为：

$$ \mathcal{L}_{\mathrm{backward}} = \mathcal{L}_{\mathrm{FM}} +\lambda_{\mathrm{fast}}\mathbf{1}[\texttt{use\_fast}=1]\mathcal{L}_{\mathrm{FAST}} +\mathbf{1}[\texttt{use\_vlm\_data}]\lambda_{\mathrm{web}}\mathcal{L}_{\mathrm{VLMweb}} +\mathbf{1}[\texttt{online\_distill}]\lambda_{\mathrm{kd}}\mathcal{L}_{\mathrm{KD}}. $$

对三条目标 run，证据给出的实际组合是 lambda_fast_ce=0、fast_only=false、use_fast=2、use_vlm_data=false、online_distill_pi05=false。因此可复现时最重要的结论是：

$$ \boxed{ \mathcal{L}_{\mathrm{backward}}=\mathcal{L}_{\mathrm{FM}} } \quad \text{for the audited target-run configurations.} $$

这不是说 FAST 相关代码没写；相反，collator、tokenizer、label mask、forward_fast_token 和 CE 分支都存在。但在这三条目标配置里，FAST token 不是最终动作输出，FAST CE 也没有有效权重。更准确的表述是：它们使用了本地 slowfast/fastobs/action-expert 结构，而不是使用 FAST-token CE 作为训练目标。

所以，三条 run 的“输出什么”可以分两层说：训练 forward 输出 \(\hat v_\theta\) 并用它计算 flow_matching_loss；serve/inference 输出积分后的 \(\hat A\)，再由 LIBERO client 逐步执行/重规划。评估表里的 0.99、0.995、0.98、0.93 等，是 rollout 成功率，不是训练 loss。

  4. 单独做 action_stream_fp32/action_expert_fp32 on/off，记录 NaN/Inf、velocity norm、action MSE 和最终 success rate。
  5. 做 no_discrete_state_input 与 empty_action_inputs 的二乘二实验，确认 anti-leakage 输入策略是否只是防止过拟合，还是确实提升评估稳定性。
  6. 最后再比较 224 vs 448、pretrain vs wo-pretrain；若这一步先做，很容易把视觉分辨率效应和前面四个结构开关混在一起。

IQL/offline RL 分支也属于明确训练设计改造。其目标应为 advantage-weighted policy loss 加 value/expectile loss：

$$ Q_{\text{target}}(s,a)=r+\gamma \mathbf{1}_{r<0} V_{\bar\phi}(s'),\qquad A=Q_{\text{target}}-V_{\bar\phi}(s), $$
$$ \mathcal{L}_{V} = \mathbb{E}\left[ |\tau-\mathbf{1}_{Q-V<0}|(Q-V)^2 \right] + \left\|V_\phi(s)-\hat V_{\text{data}}\right\|^2, \qquad \mathcal{L}_{\pi} = \mathbb{E} \left[ \exp(\beta A)\mathcal{L}_{BC} \right]. $$

预期总损失应类似：

$$ \mathcal{L}_{IQL}=\mathcal{L}_{\pi}+\lambda_V\mathcal{L}_{V}. $$

但当前实现中 final_loss = policy_loss + policy_loss，实际变成 \(2\mathcal{L}_{\pi}\)。这说明它是训练设计层改造，但复现时必须先确认这是不是 bug；在修正前，不应把该分支结果视作可靠 IQL。

4.2 Cosmos WM 主体算法

Cosmos Predict2.5 / Cosmos Policy 运行的是 video2world / policy video2world rectified-flow 风格训练。抽象如下：

给定条件视频帧 $c$、文本 embedding $e$、proprio/action 条件 $r$，目标未来视频 latent $x_1$。采样噪声 $x_0$ 与时间 $t$：

$$ x_t = (1-t)x_0 + t x_1 $$

模型：

$$ \hat v_\theta = f_\theta(x_t,t,c,e,r) $$

视频世界模型 loss：

$$ \mathcal{L}_{WM} = \mathbb{E}\left[\|\hat v_\theta - (x_1-x_0)\|^2\right] $$

Cosmos Policy 还会引入 action/value/policy 相关监督。按当前配置可以概念化为：

$$ \mathcal{L} = \mathcal{L}_{WM} + \lambda_a\mathcal{L}_{action} + \lambda_v\mathcal{L}_{value} $$

其中当前本地 run 记录 $\lambda_a=16$，p_world_model=0.5 控制世界模型样本和 policy/action 样本混合概率。由于这些是公开 Cosmos Policy 配置中的参数化训练，不构成本地算法发明。

伪代码：

Algorithm Cosmos-RoboCasa-PostTrain
Input: success demos, rollout episodes, text embeddings, video/proprio/action data
Sample mode with probability p_world_model
If world-model mode:
    build video2world latent target from frames
    sample rectified-flow time and noisy latent
    predict video latent velocity
    compute world-model loss
Else policy/action mode:
    sample action/proprio/value fields from RoboCasa rollout
    compute action/value/policy losses using Cosmos Policy recipe
L = L_world + action_loss_multiplier * L_action + ...
Update Cosmos Predict2.5 / Cosmos Policy model

5.2 GeneralVLN mixed QA + trajectory

基础 mixed 模型把多任务 batch 分成三种任务：

  • image_qa：只取当前帧 fine tokens。
  • video_qa：取历史 coarse tokens。
  • traj：历史帧 coarse tokens + 当前帧 fine tokens + action token。

序列结构：

$$ S = [V_{\text{coarse/fine}}, T_{\text{text}}, q_{\text{traj}}] $$

LLM hidden state：

$$ H = \text{LLM}(S) $$

QA 分支：

$$ \mathcal{L}_{QA} = -\sum_i \log p_\theta(y_i \mid y_{<i}, V, q) $$

轨迹分支：

$$ \hat Y = g_\theta(H_{q_{\text{traj}}}) $$

基础轨迹损失：

$$ \mathcal{L}_{traj} = \|\hat Y - Y\|_2^2 $$

可选方向/速度：

$$ \mathcal{L}_{dir}=1-\cos(\Delta \hat Y,\Delta Y) $$
$$ \mathcal{L}_{vel}=\|\Delta \hat Y-\Delta Y\|_2^2 $$

总损失：

$$ \mathcal{L}_{mixed} = \lambda_{QA}\mathcal{L}_{QA} \lambda_{traj}\mathcal{L}_{traj} \lambda_{dir}\mathcal{L}_{dir} \lambda_{vel}\mathcal{L}_{vel} $$

Project visual tokens and inject temporal/view ids
Build text tokens:
    QA -> question + answer labels

Return weighted loss graph

5.3 Flow matching trajectory head

GeneralVLN 的 flow-matching 轨迹头把轨迹从直接回归改成连续生成：

$$ x_t = (1-t)\epsilon + tY,\qquad v^\star = Y-\epsilon $$

模型：

$$ \hat v_\theta = h_\theta(c,x_t,t) $$

其中 $c$ 是 planner/action-token hidden state。训练：

$$ \mathcal{L}_{FM}^{VLN} = \|\hat v_\theta - v^\star\|_2^2 \alpha\|x_t+(1-t)\hat v_\theta-Y\|_2^2 $$

采样：

$$ x_{k+1}=x_k+\Delta t\,h_\theta(c,x_k,t_k) $$

这是一项明确训练设计改造：用生成式轨迹分布替代单点 MSE 回归，理论上更适合 VLN 中同一指令存在多条可行路径的问题。

5.4 Anchor flow matching

Anchor flow matching 更进一步：先准备 $M$ 个轨迹 anchor $A_m$，模型对每个 anchor 预测到真值轨迹的 flow，并同时打分。

训练 batch：

$$ x_{t,m}=(1-t)A_m+tY $$
$$ v^\star_m = Y-A_m $$

模型输出：

$$ (\hat v_m, s_m) = f_\theta(c, x_{t,m}, t) $$

最近 anchor 标签：

$$ m^\star = \arg\min_m \|A_m-Y\|^2 $$

score loss：

$$ \mathcal{L}_{score} = CE(s, m^\star) $$

flow loss：

$$ \mathcal{L}_{flow}^{gt} = \|\hat v_{m^\star}-v^\star_{m^\star}\|^2 $$
$$ \mathcal{L}_{flow}^{pred} = \sum_m \text{softmax}(s)_m\|\hat v_m-v^\star_m\|^2 $$

总目标：

$$ \mathcal{L}_{AFM} = \lambda_f \left( w_g\mathcal{L}_{flow}^{gt} +w_p\mathcal{L}_{flow}^{pred} \right) + \lambda_s\mathcal{L}_{score} $$

推理：

Algorithm Anchor-Flow-Infer
Input: condition c, clean anchors {A_m}
x_m = A_m
For k = 0..K-1:
    t = k / K
    v_m, score_m = f(c, x_m, t)
    x_m = x_m + (1/K) * v_m
m_best = argmax score_m
return x_m_best

为什么这样改：

  • 纯 MSE 轨迹回归会平均多模态路径，容易生成“中间路线”。
  • Diffusion/flow 直接从噪声生成轨迹更灵活，但小数据下不稳定。
  • Anchor 提供先验轨迹簇，score head 负责模式选择，flow head 负责局部修正，兼顾多模态和训练稳定性。

风险：

  • anchor 质量决定上限；如果 anchor 覆盖不到目标路径，flow 只能做大幅修正，失去 anchor 优势。
  • score CE 与 pred-score weighted flow 可能竞争：早期 score 不准时，weighted flow 会训练到错误 anchor。
  • 当前 inference top-1 选择容易忽略次优路径；可考虑 top-k 重采样或代价函数 rerank。

5.5 Anchor diffusion

Anchor diffusion 与 AFM 类似，但以 noisy anchor 到 refined trajectory 的方式训练：

$$ \tilde A_t = \sqrt{\bar\alpha_t}A+\sqrt{1-\bar\alpha_t}\epsilon $$

本地实现当前更多像“anchor + delta head + score head”：

$$ \hat Y_m = A_m + \Delta_\theta(c,A_m,t) $$

损失：

$$ \mathcal{L}_{AD} = \sum_m \text{softmax}(s)_m\|\hat Y_m-Y\|^2 +\lambda_s CE(s,m^\star) $$

本地代码里 forward/infer 有注释掉 noisy input、实际传 clean anchors 的痕迹，因此 anchor diffusion 线应判定为实验性更强、复现不确定性高于 anchor flow matching。

  2. 加 vln_qa_model_mixed_flowmatching，确认 flow_x_t/flow_t/flow_target_v batch 字段生成。
  3. 生成或复用 anchor npz，检查 scale：pos_scale=10、angle_scale=pi。
  4. 跑 vln_qa_model_mixed_anchor_flowmatching，观察 loss_afm_score、loss_afm_flow_gt、loss_afm_flow_pred。
  5. 在 eval 中对比 MSE baseline、flow、anchor flow 的 DTW/ADE/FDE/SPL/SR。

关键指标：

  • Trajectory ADE/FDE。
  • Success Rate / SPL。
  • Anchor top-1 accuracy：最近 GT anchor 是否被 score head 选中。
  • flow reconstruction loss。

7. 推荐复现路线

第一优先级：GeneralVLN anchor flow matching。

原因：本地改造边界最清晰，数学目标自洽，资源需求低于 QwenVL/PiZero 完整训练，能较快产出“改造是否有效”的可比结果。

第二优先级：OpenPI/QwenVL/PiZero Flow Matching + FAST CE。

原因：最接近 VLA 主线价值，但工程依赖多、GPU 压力大。建议先做 FM-only，再逐步打开 FAST/VLM/slowfast。

基于 2026-06-13 评估落档补充：如果目标不是“验证本地新方法”，而是“复现已经训练出来的策略效果”，OpenPI 的优先级应前移，先复现 224_h10_40000 的 LIBERO 四套评估，再做 448/pretrain/wo-pretrain 的消融对比。RoboCasa kitchen24 则适合作为第二阶段失败分析基准，用来定位 PnP、OpenDoubleDoor 和长 horizon replan 问题。

第三优先级：Cosmos RoboCasa world model official reproduction。

原因：这条线当前主要是公开方法 + 数据适配。可以复现实验稳定性和资源需求，但不应作为“本地算法创新”主结论。

第四优先级：IQL 和 VGGT-Omega action regression。

IQL 有实现疑点，VGGT-Omega 是辅助分支。两者更适合做后续探索或 ablation。

8. 主要风险清单

  1. 本地目录是整理工作区，很多代码是快照或归档，不一定能直接运行。
  2. 公开项目的许可证、权重许可、数据许可需要在复现前逐项核对。
  3. OpenPI/QwenVL 主线依赖 Qwen3-VL、OpenPI、FAST tokenizer、DeepSpeed、flash-attn、Hydra 配置路径，环境风险高。
  4. GeneralVLN 的 JanusVLN adapter 需要 Qwen2.5-VL 的 3D RoPE position_ids 严格对齐，batch padding 细节容易出错。
  5. Anchor flow/diffusion 的结论高度依赖 anchor npz 的生成方式和尺度。
  6. WM/Cosmos 的训练资源重，单 checkpoint optimizer shard 很大；当前本地只有轻量证据，没有权重。
  7. IQL 当前 final loss 疑似没有使用 value loss，需先审计再复现。

9. 结论

可以明确判定为本地方法/训练改造的项目是：

  1. OpenPI/QwenVL/PiZero VLA 主线：QwenVL + PiZero joint mixture、FAST token/state supervision、FM 动作生成、VLM/action 混合训练、IQL 实验线。
  2. GeneralVLN/VLN 主线：mixed QA+trajectory、JanusVLN/Qwen2.5-VL adapter、flow matching trajectory、anchor flow matching、anchor diffusion。
  3. WM 目录中的 VGGT-Omega action regression 辅助线：冻结 3D/几何视觉 backbone 并训练左右腕 action chunk heads。

不应判定为本地算法改造的项目是：

  1. OpenVLA-OFT：当前是官方 LoRA/OFT fine-tune、LIBERO/ALOHA eval/deploy baseline。
  2. DreamDojo/Cosmos 主世界模型：当前主要是公开方法的 RoboCasa/LeRobot 数据接入、配置和运行记录。
  3. JanusVLN/StreamVLN/Uni-NaVid/OpenTrackVLA 单独目录：多为公开 baseline 或近上游代码，本地创新主要体现在 GeneralVLN 的集成和训练目标扩展中。

最可行、最值得先做的复现是 GeneralVLN anchor flow matching；最有 VLA 价值但工程成本最高的是 OpenPI/QwenVL/PiZero + FAST/FM 主线。

结合 2026-06-13 最新落档，需要补充一条评估层结论：OpenPI VLA 已有可引用的训练模型效果，224_h10_40000 在 LIBERO goal/object/spatial/libero10 上达到 0.99/0.995/0.98/0.93，是当前最强的实证锚点；RoboCasa kitchen24 总体约 0.60，显示策略在关门/关抽屉较稳、PnP 与 OpenDoubleDoor 仍弱；Cosmos/VGGT droid sim 当前 0/5 success，DA3 3-cam action regression 的右臂误差仍显著高于 pi05 baseline；VLN 线本轮被跳过，没有新增模型评估证据。
