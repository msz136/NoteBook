背景与动机（Background & Motivation）

机器人世界模型（Robot World Model）的核心命题是：能否将大规模视频预训练的生成能力转化为机器人策略？传统方法将"感知→规划→控制"分离为独立模块；而世界模型路线试图用一个统一的生成模型同时完成未来状态预测（world model）、动作生成（policy）和价值估计（value function）。

本项目线的核心设计哲学是：将机器人策略学习重新表述为条件视频生成问题。具体而言，将动作（action）、本体感知（proprioception）、价值函数回报（value function return）统一编码为视频潜在空间中的"帧"，与视觉观测帧共享同一个扩散模型的去噪过程。这使得一个预训练好的视频生成模型可以通过后训练直接输出机器人动作。

扩散、DiT 与世界模型数学基础

符号与世界模型定义

在机器人场景中，真实环境可以看作一个部分可观测马尔可夫决策过程（POMDP）：隐藏状态 \(s_t \in \mathcal{S}\)，观测 \(o_t \in \mathcal{O}\)，动作 \(a_t \in \mathcal{A}\)，奖励 \(r_t \in \mathbb{R}\)，语言或任务条件 \(c\)。世界模型学习的是条件转移分布：

\[ p_\theta(o_{t+1:t+H}, r_{t:t+H} \mid o_{\le t}, a_{t:t+H-1}, c) \]

视频世界模型通常不直接在像素空间建模，而是先用 VAE / tokenizer 将视频帧压缩为潜在变量：

\[ z_t = E_\phi(o_t), \quad \hat{o}_t = G_\phi(z_t), \quad z_{1:T} \in \mathbb{R}^{C \times T \times H' \times W'} \]

于是 DreamDojo / Cosmos Predict2.5 的核心对象可以写成：

\[ p_\theta(z_{\text{future}} \mid z_{\text{cond}}, u, c) \]

其中 \(z_{\text{cond}}\) 是当前观测或历史帧的潜在表示，\(u\) 可以是真实机器人动作、Latent Action Model 产生的潜在动作、或 Cosmos Policy 中注入到 latent frame 的 action/proprio/value 张量。若把世界模型用于规划，则可以在模型内部做想象式优化：

\[ a^*_{t:t+H-1} = \arg\max_{a_{t:t+H-1}} \mathbb{E}_{p_\theta}\left[\sum_{k=0}^{H-1}\gamma^k r_{t+k}\right] \]
关键区分：传统 dynamics model 预测 \(s_{t+1}=f_\theta(s_t,a_t)\)；视频世界模型预测的是未来观测分布 \(p_\theta(z_{\text{future}}\mid z_{\text{cond}},a,c)\)。后者不是单点回归，而是一个多模态生成分布，因而适合用扩散 / flow 这类生成模型实现。

扩散模型具体是什么

扩散模型（Diffusion Model）是一类“先加噪、再学会逆向去噪”的生成模型。给定干净样本 \(x_0 \sim p_{\text{data}}\)，DDPM 定义一个固定前向加噪链：

\[ q(x_t \mid x_{t-1}) = \mathcal{N}(\sqrt{1-\beta_t}x_{t-1}, \beta_t I) \]

将多个时间步合并后，有闭式采样：

\[ q(x_t \mid x_0) = \mathcal{N}(\sqrt{\bar{\alpha}_t}x_0, (1-\bar{\alpha}_t)I), \quad x_t = \sqrt{\bar{\alpha}_t}x_0 + \sqrt{1-\bar{\alpha}_t}\epsilon, \quad \epsilon \sim \mathcal{N}(0,I) \]

其中 \(\beta_t\) 是每一步加入的噪声方差，\(\alpha_t=1-\beta_t\)，\(\bar{\alpha}_t=\prod_{i=1}^{t}\alpha_i\)。训练时常让网络 \(\epsilon_\theta(x_t,t,c)\) 预测噪声：

\[ \mathcal{L}_{\text{DDPM}} = \mathbb{E}_{x_0,\epsilon,t} \left[ \left\|\epsilon - \epsilon_\theta(x_t,t,c)\right\|_2^2 \right] \]

有了噪声预测后，可以恢复干净样本估计：

\[ \hat{x}_0(x_t,t,c) = \frac{x_t-\sqrt{1-\bar{\alpha}_t}\epsilon_\theta(x_t,t,c)} {\sqrt{\bar{\alpha}_t}} \]

推理时从高斯噪声 \(x_T \sim \mathcal{N}(0,I)\) 出发，反复采样 \(p_\theta(x_{t-1}\mid x_t,c)\)，逐步得到 \(x_0\)。所以扩散模型的本质不是“随机抖动图片”，而是学习数据分布在不同噪声尺度上的 score / denoiser。

EDM 与 Rectified Flow 的连续时间视角

EDM（Elucidated Diffusion Model）把离散时间 \(t\) 改写为连续噪声尺度 \(\sigma\)，直接构造：

\[ x_\sigma = x_0 + \sigma\epsilon,\quad \epsilon \sim \mathcal{N}(0,I) \]

模型学习 denoiser \(D_\theta(x_\sigma,\sigma,c)\approx x_0\)。它也等价于估计平滑后数据分布 \(p_\sigma\) 的 score：

\[ \nabla_x \log p_\sigma(x) \approx \frac{D_\theta(x,\sigma,c)-x}{\sigma^2} \]

Rectified Flow 则把生成看成在噪声点和数据点之间学习一条速度场。令 \(x_1=\epsilon\sim\mathcal{N}(0,I)\)，\(x_0\sim p_{\text{data}}\)，线性插值为：

\[ x_t = (1-t)x_0 + t x_1,\quad t\in[0,1] \]

若时间方向定义为“从数据走向噪声”，最优速度是：

\[ v^*(x_t,t) = \frac{d x_t}{dt} = x_1 - x_0 \]

训练目标为：

\[ \mathcal{L}_{\text{RF}} = \mathbb{E}_{x_0,x_1,t} \left[ \left\|v_\theta(x_t,t,c) - (x_1-x_0)\right\|_2^2 \right] \]

推理时若从噪声生成数据，则沿反方向积分：

\[ \frac{d x_t}{dt}=v_\theta(x_t,t,c),\quad t:1\rightarrow 0 \]

不同代码库会把速度目标写成 \(x_1-x_0\) 或 \(x_0-x_1\)，区别只是积分方向的符号约定。对 DreamDojo / Cosmos 这类视频世界模型来说，核心是 DiT 在每个噪声/时间尺度上预测“如何把当前 noisy latent 拉回物理合理的视频 latent”。

DiT 具体是什么：用 Transformer 做扩散去噪器

DiT（Diffusion Transformer）不是一种新的扩散目标，而是把扩散模型中的去噪网络 \(F_\theta\) 从 U-Net 换成 Transformer。输入 latent video \(x \in \mathbb{R}^{B \times C \times T \times H \times W}\) 先被 patchify：

\[ N = \frac{T}{p_t}\cdot\frac{H}{p_h}\cdot\frac{W}{p_w},\quad e_i = W_p \operatorname{vec}(x_{\text{patch }i}) + p_i \]

其中 \(p_t,p_h,p_w\) 是时间/高度/宽度 patch size，\(N\) 是 token 数，\(W_p\) 是线性投影，\(p_i\) 是 3D 位置编码。一个 DiT block 的核心是多头自注意力、交叉注意力、MLP 与噪声条件调制：

\[ \operatorname{Attn}(Q,K,V) = \operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d}}\right)V \] \[ \operatorname{AdaLN}(h;\sigma) = \gamma(\sigma)\odot \frac{h-\mu(h)}{\sqrt{\operatorname{Var}(h)+\epsilon}} + \beta(\sigma) \] \[ h \leftarrow h + g_{\text{attn}}(\sigma)\operatorname{MHA}(\operatorname{AdaLN}(h;\sigma)) \] \[ h \leftarrow h + g_{\text{cross}}(\sigma)\operatorname{CrossAttn}(h, E_{\text{text}}(c)) \] \[ h \leftarrow h + g_{\text{mlp}}(\sigma)\operatorname{MLP}(\operatorname{AdaLN}(h;\sigma)) \]

最终，Transformer token 被 unpatchify 回 latent video 形状，输出可以解释为噪声 \(\epsilon_\theta\)、速度 \(v_\theta\)、或 EDM preconditioning 中的残差 \(F_\theta\)。Cosmos / DreamDojo 的 DiT 还包含以下模块：

模块数学对象功能

核心架构设计：统一潜在序列表示

设计思想：Action-as-Latent-Frame

Cosmos Policy 的核心创新在于将机器人策略学习统一到视频扩散模型的框架中。其关键洞察是：动作、本体感知、价值回报都可以被编码为与图像潜在帧同构的张量，从而复用视频生成模型的去噪能力来同时预测未来视觉状态和机器人动作。

具体而言，一个训练样本的潜在序列 \( x_0 \in \mathbb{R}^{B \times C' \times T' \times H' \times W'} \) 由以下"帧"组成：

帧类型内容角色
Blank frame全零占位Tokenizer 对齐
Current proprio本体感知向量 → 重复填充至 \(C' \times H' \times W'\)条件输入
Current wrist image腕部相机图像（×4 复制）条件输入
Current left/right image第三人称左/右相机图像（×4 复制）条件输入
Action chunk动作序列 → 展平重复填充至潜在帧体积预测目标
Future proprio未来本体感知预测目标（world model）
Future wrist/left/right image未来视觉观测预测目标（world model）

Latent Injection 机制

非视觉模态（action、proprio、value）通过 latent injection 注入到 VAE 编码后的潜在空间中。核心函数 replace_latent_with_action_chunk 的算法如下：

  1. 将 action chunk \( a \in \mathbb{R}^{B \times \text{chunk\_size} \times \text{action\_dim}} \) 展平为 \( \mathbb{R}^{B \times (\text{chunk\_size} \cdot \text{action\_dim})} \)
  2. 重复填充至目标潜在帧体积 \( C' \times H' \times W' \)（如 \(16 \times 28 \times 28 = 12544\) 元素）
  3. 替换 \( x_0[:, :, \text{action\_idx}, :, :] \) 处的潜在帧
# cosmos_policy/models/policy_text2world_model.py:64-109
def replace_latent_with_action_chunk(x0, action_chunk, action_indices):
    batch_indices = torch.arange(x0.shape[0], device=x0.device)
    action_image_latent = x0[batch_indices, :, action_indices, :, :]
    result = torch.zeros_like(action_image_latent)
    batch_size, latent_channels, latent_h, latent_w = action_image_latent.shape
    flat_action = action_chunk.reshape(batch_size, -1)
    num_action_elements = flat_action.shape[1]
    latent_elements = latent_channels * latent_h * latent_w
    # 重复填充直到覆盖整个潜在帧体积
    num_repeats = (latent_elements + num_action_elements - 1) // num_action_elements
    repeated_action = flat_action.repeat(1, num_repeats)[:, :latent_elements]
    flat_result = result.reshape(batch_size, -1)
    flat_result[:, :] = repeated_action
    new_x0 = x0
    new_x0[batch_indices, :, action_indices, :, :] = flat_result.reshape(
        batch_size, latent_channels, latent_h, latent_w)
    return new_x0

这种设计的优势在于：动作信息直接存在于扩散模型的去噪目标 \( x_0 \) 中，模型学习的是"从噪声中恢复包含动作信息的潜在帧"，而非通过额外的 head 预测动作。这使得预训练的视频生成能力可以直接迁移到动作预测任务。

DreamDojo / Cosmos 的典型生成流程

DreamDojo：从人类视频到动作条件世界模型

DreamDojo 的标准思路是先从无动作标注的人类视频中学习潜在动作，再把这些潜在动作作为世界模型的条件。抽象地看，Latent Action Model（LAM）学习一个从相邻观测到动作因子的编码器：

\[ u_t = f_\psi(o_t,o_{t+1}), \quad u_t \in \mathbb{R}^{d_u} \]

其中 \(u_t\) 不一定对应某台机器人的关节角或末端位姿，而是“使 \(o_t\rightarrow o_{t+1}\) 成立的潜在干预变量”。随后视频世界模型学习：

\[ p_\theta(z_{t+1:t+H}\mid z_{\le t}, u_{t:t+H-1}, c) \]

若使用 Rectified Flow，训练样本为干净 future latent \(x_0=z_{t+1:t+H}\)、噪声 \(x_1\sim\mathcal{N}(0,I)\)、插值 \(x_\tau=(1-\tau)x_0+\tau x_1\)，目标速度为 \(x_1-x_0\)。条件包括历史视频 latent、LAM 动作、文本条件以及 frame mask。

def dreamdojo_pretrain_step(video_clip, text):
    # 1. 从人类视频中抽取潜在动作
    obs = sample_frames(video_clip)
    latent_action = LAM.encode_pairs(obs[:-1], obs[1:])     # u_t = f_psi(o_t, o_{t+1})

    # 2. 视频帧进入 VAE latent 空间
    z = vae.encode(obs)                                     # z = E_phi(o)
    z_cond, z_future = split_condition_and_future(z)

    # 3. Rectified Flow 加噪
    eps = torch.randn_like(z_future)
    tau = torch.rand(batch_size)
    x_tau = (1 - tau) * z_future + tau * eps
    target_v = eps - z_future

    # 4. DiT 预测速度场，条件为历史帧 + 潜在动作 + 文本
    pred_v = dit(x_tau, tau, z_cond=z_cond, action=latent_action, text=text)
    loss = mse(pred_v, target_v, mask=future_frame_mask)
    return loss

DreamDojo 后训练与推理

后训练时，真实机器人动作 \(a_t\) 被投影到统一动作空间 \(u_t=g_\eta(a_t,\text{robot\_id})\)。如果统一动作空间维度为 384，则不同机器人只占用其中一段坐标；数学上可以写成：

\[ u_t = P_{\text{robot}} a_t,\quad P_{\text{robot}}\in\mathbb{R}^{384\times d_a} \]

其中 \(P_{\text{robot}}\) 是机器人动作维度到统一 384 维空间的稀疏投影/填充算子。推理时，模型从噪声 future latent 开始，在动作条件下生成未来视频：

def dreamdojo_inference(current_frames, robot_actions, text, num_steps=35):
    z_cond = vae.encode(current_frames)
    u = robot_action_projector(robot_actions)       # a_t -> 384-d unified action
    x = torch.randn(target_latent_shape)

    for step in reversed(range(num_steps)):
        tau = step / num_steps
        v = dit(x, tau, z_cond=z_cond, action=u, text=text)
        x = flow_solver_step(x, v, tau)             # 沿噪声 -> 数据方向积分

    future_frames = vae.decode(x)
    return future_frames

Cosmos Predict2.5：条件视频生成器

Cosmos Predict2.5 的 Video2World 模型可以理解为一个条件 latent-video 生成器。输入是当前视频/图像条件、文本 prompt、可选动作条件；输出是未来视频 latent。其内部顺序为：

  1. Tokenizer：像素视频 \(o\) 经 VAE 得到 latent \(z\)
  2. Condition builder：根据 mask 把条件帧固定，把待预测帧初始化为噪声
  3. Text/action conditioning：T5 文本 embedding 和动作 embedding 进入 DiT
  4. Denoising / flow solve：DiT 在多噪声尺度上反复预测 denoised latent 或 velocity
  5. Decode：VAE decoder 将 latent 还原为未来视频帧
\[ \hat{z}_{\text{future}} = \operatorname{Solve}\left( F_\theta(x,\sigma,E_{\text{text}}(c),E_{\text{act}}(a),M), \sigma_{\max}\rightarrow\sigma_{\min} \right) \]

Cosmos Policy：把动作、世界模型和值函数统一成 latent-frame 生成

Cosmos Policy 更进一步：它不只生成未来视频，还把动作、本体感知和值函数都塞进同构 latent frame。若一个样本的 latent 序列为 \(x_0\)，其中第 \(i_a\) 帧是 action frame，第 \(i_v\) 帧是 value frame，第 \(i_f\) 组帧是 future visual/proprio frame，则三种任务共用同一个 DiT：

\[ D_\theta(x_\sigma,\sigma,c,M) \rightarrow \hat{x}_0 \]

差别只在 mask \(M\)：policy 任务只让 action frame 计算 loss；world-model 任务只让 future frame 计算 loss；value 任务只让 value frame 计算 loss。

def cosmos_policy_train_step(batch):

训练算法：Rectified Flow + Hybrid Sigma + Multi-Objective Loss

扩散过程：EDM 框架下的 Rectified Flow

模型采用 EDM（Elucidating the Design Space of Diffusion-Based Generative Models, Karras et al. 2022）框架，前向过程定义为：

\[ x_t = x_0 + \sigma \cdot \epsilon, \quad \epsilon \sim \mathcal{N}(0, I) \]

其中 \(\sigma\) 是噪声水平。模型学习去噪函数 \( D_\theta(x_t; \sigma) \) 来预测 \( x_0 \)。EDM 的 preconditioning 将网络输出 \( F_\theta \) 转换为 \( x_0 \) 预测：

\[ D_\theta(x_t; \sigma) = c_{\text{skip}}(\sigma) \cdot x_t + c_{\text{out}}(\sigma) \cdot F_\theta(c_{\text{in}}(\sigma) \cdot x_t; c_{\text{noise}}(\sigma)) \]
代码证据：cosmos_policy/models/policy_video2world_model.py:410-455 — denoise() 方法实现了完整的 EDM preconditioning 和去噪逻辑。 
# policy_video2world_model.py:410-455 (denoise 核心逻辑)

net_state_in = xt_B_C_T_H_W * c_in
# 条件帧替换：将干净的条件帧注入到噪声输入中
net_state_in = condition_state * condition_mask + net_state_in * (1 - condition_mask)
# 调整条件帧的 c_noise（因为条件帧是干净的，sigma ≈ 0.0001）

# 网络前向传播
net_output = self.net(x_B_C_T_H_W=net_state_in, timesteps_B_T=c_noise, **condition.to_dict())
# EDM preconditioning 输出
x0_pred = c_skip * xt_B_C_T_H_W + c_out * net_output

Hybrid Sigma Distribution：混合噪声水平采样

训练时的噪声水平 \(\sigma\) 采样是影响扩散模型质量的关键因素。本项目实现了 HybridEDMSDE，采用混合分布策略：

\[ \sigma \sim \begin{cases} \exp(\mathcal{N}(p_{\text{mean}}, p_{\text{std}}^2)) & \text{with probability } 0.7 \\ \text{Uniform}(\sigma_{\text{lower}}, \sigma_{\text{upper}}) & \text{with probability } 0.3 \end{cases} \]

其中 \( p_{\text{mean}} = 0.0, p_{\text{std}} = 1.0, \sigma_{\text{lower}} = 1.0, \sigma_{\text{upper}} = 85.0 \)。

代码证据：cosmos_predict2_src/cosmos_policy/modules/hybrid_edm_sde.py:48-92 — HybridEDMSDE.sample_t() 实现了 70/30 混合采样。 
# hybrid_edm_sde.py:65-89
def sample_t(self, batch_size):
    if self.hybrid_sigma_distribution:
        samples = torch.zeros(batch_size, device="cuda")
        distribution_choice = torch.rand(batch_size, device="cuda") < 0.7
        num_lognormal = distribution_choice.sum().item()
        num_uniform = batch_size - num_lognormal
        # 70% 从 log-normal 采样
        if num_lognormal > 0:
            cdf_vals = np.random.uniform(size=(num_lognormal))
            log_sigmas = torch.tensor(
                [self.gaussian_dist.inv_cdf(v) for v in cdf_vals], device="cuda")
            samples[distribution_choice] = torch.exp(log_sigmas)
        # 30% 从 uniform[1.0, 85.0] 采样
        if num_uniform > 0:
            samples[~distribution_choice] = torch.empty(
                num_uniform, device="cuda").uniform_(self.uniform_lower, self.uniform_upper)
        return samples

设计动机：标准 log-normal 分布倾向于在中等噪声水平集中采样，导致模型在高噪声（全局结构生成）和低噪声（细节精修）区域训练不足。混合分布通过 30% 的均匀采样强制模型在更宽的噪声范围内学习，特别是对视频条件生成中的"从条件帧预测未来帧"场景至关重要。

此外，Video2World 模型还支持额外的 high sigma 策略叠加（5% 概率从 [80, 2000] 均匀采样），进一步增强模型对极高噪声的鲁棒性：

Multi-Objective Loss：三重预测目标的统一训练

Cosmos Policy 的训练损失是一个多目标函数，通过 mask 机制 在同一个 batch 内同时训练三种预测能力：

\[ \mathcal{L} = \mathcal{L}_{\text{policy}} + \mathcal{L}_{\text{world model}} + \mathcal{L}_{\text{value function}} \]

每个样本根据其来源（demonstration vs. rollout）和随机采样（p_world_model = 0.5）被分配到不同的预测目标：

样本类型预测目标Loss 作用帧
Demonstration（成功演示）Policy（动作预测）仅 action latent frame
Rollout + world_model_maskWorld Model（未来状态预测）future proprio + future wrist + future images
Rollout + value_function_maskValue Function（回报预测）仅 value latent frame

EDM Loss 权重

最终的 per-sample loss 为：

\[ \mathcal{L}_{\text{EDM}} = w(\sigma) \cdot \| x_0 - D_\theta(x_t; \sigma) \|^2 \cdot M \]

其中 \( w(\sigma) \) 是 EDM 的 per-sigma loss weight，\( M \) 是上述 multi-objective mask（含 action multiplier）。

Video Conditioning：Frame Replace 策略

模型使用 Frame Replace 条件策略：将条件帧（当前观测）直接替换到噪声输入中，而非通过 concatenation 或 cross-attention 注入。

关键设计：

  • 条件帧使用极低噪声 \(\sigma_{\text{cond}} = 0.0001\)，近似干净信号
  • 通过 condition_video_input_mask_B_C_T_H_W 控制哪些帧是条件、哪些是预测目标
  • 去噪后，条件帧位置的预测被强制替换回 ground truth（denoise_replace_gt_frames=True），确保 loss 不在条件帧上计算

数据采样策略：Demo/Rollout 混合训练

训练数据由两部分组成，通过概率采样混合：

  • Demonstration data（success_only/）：成功的人类遥操作演示，用于训练 policy（动作预测）
  • Rollout data（all_episodes/）：包含成功和失败的 rollout，用于训练 world model 和 value function

采样概率链：

\[ P(\text{demo}) = 0.5, \quad P(\text{rollout}) = 0.5 \] \[ P(\text{world model} | \text{rollout}) = 0.5, \quad P(\text{value function} | \text{rollout}) = 0.5 \]

Value function 使用 Monte-Carlo 回报作为监督信号：

\[ G_t = \sum_{k=0}^{T-t-1} \gamma^k r_{t+k+1}, \quad \gamma = 0.99 \]

其中终端奖励 \( r_T = 1 \)（成功）或 \( r_T = 0 \)（失败）。

蒸馏算法：从教师到实时学生

设计动机

扩散模型的推理需要多步去噪（通常 20-50 步），无法满足机器人实时控制的需求（10 FPS）。DreamDojo 的蒸馏管线将多步教师模型压缩为单步/少步因果学生模型。

三阶段蒸馏流程

Stage 1: Teacher Generation

从教师模型在多个噪声级别生成去噪目标，作为学生训练的监督信号：

  --experiment=groot_ac_reason_embeddings_rectified_flow_2b_480_640_gr1 \
  --ckpt_path checkpoints/model/ \

query_steps = [0, 9, 18, 27, 34] 对应 35 步去噪调度中的 5 个均匀间隔点，为学生提供从高噪声到低噪声的完整去噪轨迹。

Stage 2: Warmup（知识蒸馏）

训练因果学生网络对齐教师的去噪输出。学生使用因果架构（causal），只能看到当前和过去的帧，不能看到未来帧——这是实时推理的必要条件。

Stage 3: Self-Forcing（DMD 蒸馏）

Self-Forcing 是蒸馏管线的核心创新。它解决了 autoregressive 生成中的 exposure bias 问题：warmup 阶段学生只见过教师生成的干净帧作为历史输入，但推理时必须使用自己生成的（可能有误差的）帧。

Self-Forcing 的训练方式：

  1. 让学生用自己的 autoregressive rollout 生成历史帧
  2. 教师模型对学生的输出计算 score（梯度方向）
  3. 通过 DMD（Distribution Matching Distillation）损失让学生的输出分布匹配教师的输出分布

对任意一个世界模型实验 \(e\)，可以把它拆成公开上游、局部改造、私有数据、运行配置和评估闭环五个因子：

\[ e=\operatorname{Run}\left( P_{\text{upstream}}, \Delta_{\text{code}}, D_{\text{local}}, C_{\text{train}}, H_{\text{eval}}, \theta_0 \right) \]

其中 \(P_{\text{upstream}}\) 是 GitHub/HuggingFace/论文中可公开验证的代码、模型卡与算法描述；\(\Delta_{\text{code}}\) 是远端或本地相对上游的源码差异；\(D_{\text{local}}\) 是本地生成、重采样、过滤或重新打包的数据；\(C_{\text{train}}\) 是训练命令、Hydra 配置、checkpoint 路径、日志和运行环境；\(H_{\text{eval}}\) 是 LIBERO、RoboCasa、DA3/VGGT 等评估脚本与结果；\(\theta_0\) 是公开或受许可约束的初始化权重。

本报告把“私有/改造边界”定义为：

\[ \mathcal{B}_{\text{private}} = \Delta_{\text{code}} \cup D_{\text{local}} \cup C_{\text{train}} \cup H_{\text{eval}} \cup \{\text{未公开的远端路径、日志索引、训练产物指针}\} \]

而不把以下内容算成本地私有创新：公开论文中的方法名、公开 GitHub 仓库已有代码、公开 README 中列出的训练 recipe、公开模型卡中的 checkpoint 名称、RoboCasa/LeRobot/VGGT 等公共生态组件。

def audit_world_model_boundary(projects, local_evidence_root):
    boundary_report = []
    for project in projects:
        upstream = query_public_repo(project.repo_url)
        evidence = read_local_records(local_evidence_root, project.name)

        public_surface = {
            "repo": upstream.url,
            "license": upstream.license,
            "documented_capability": upstream.readme_claims,
            "model_or_dataset_terms": upstream.model_card_terms,
        }

        private_surface = {
            "code_diff": evidence.git_status_and_diff_stat,
            "local_dataset": evidence.dataset_readme_and_stats,
            "run_config": evidence.config_yaml_and_launch_info,
            "eval_harness": evidence.eval_scripts_and_metrics,
            "remote_paths": evidence.remote_paths_without_payloads,
        }

        confidence = classify_evidence(
            confirmed_public=public_surface,
            confirmed_local=private_surface,
            skipped=evidence.explicit_skips,
        )
        boundary_report.append((project.name, public_surface, private_surface, confidence))
    return boundary_report

私有边界的数学化落地

本地 Cosmos Policy/RoboCasa 训练可以写成一个三任务采样问题。令样本类型 \(m\in\{\pi,W,V\}\)，分别对应 policy action、world model future state、value return。根据 evidence 中的采样概率，近似有：

\[ P(m=\pi)\approx 0.5,\quad P(m=W)\approx 0.25,\quad P(m=V)\approx 0.25 \]

对一个 latent 序列 \(x_0\in\mathbb{R}^{C\times T\times H'\times W'}\)，本地数据层会生成一组索引：

\[ \mathcal{I}= \{i_{\text{action}}, i_{\text{cur-proprio}}, i_{\text{future-proprio}}, i_{\text{value}}, \mathcal{I}_{\text{future-image}}\} \]

然后通过 mask \(M_m\) 只在目标帧上计算 denoising loss：

\[ \mathcal{L}(\theta)= \mathbb{E}_{m,\sigma,\epsilon} \left[ w(\sigma) \left\| M_m(\mathcal{I})\odot \left(D_\theta(x_0+\sigma\epsilon,\sigma,c)-x_0\right) \right\|_2^2 \right] \]

其中 action frame 的权重按本地配置乘以 16：

\[ M_{\pi}(i_{\text{action}})\leftarrow 16\,M_{\pi}(i_{\text{action}}) \]

这条公式正好对应本地私有边界：公开 Cosmos Policy 说明“动作/未来/价值可统一为视频 latent 预测”，但本地具体把 RoboCasa 的 7D action、9D proprio、Monte Carlo return、JPEG rollout、success-only demo 组织成什么索引、mask 和损失倍率，才是项目实际改造。

改造目标：把 Video2World 改成 Policy / World / Value 统一模型

原始 Cosmos Predict2.5 的主能力是条件视频生成：

\[ p_\theta(z_{\text{future}}\mid z_{\text{cond}},c,a) \]

本地 Cosmos Policy 改造线把它改造成三任务共享的生成式策略模型：

\[ \theta^* = \arg\min_\theta \mathbb{E}_{m,\sigma,\epsilon,x_0} \left[ \lambda_m w(\sigma) \left\|M_m \odot \left(D_\theta(x_0+\sigma\epsilon,\sigma,c)-x_0\right)\right\|_2^2 \right] \]

其中 \(m\in\{\text{policy},\text{world},\text{value}\}\) 表示当前样本的训练任务，\(M_m\) 是任务 mask，\(\lambda_m\) 是任务权重，\(w(\sigma)\) 是 EDM 噪声权重。三类 mask 的定义可以写成：

\[ M_{\text{policy}}(t)=\mathbf{1}[t=i_a] \] \[ M_{\text{world}}(t)= \mathbf{1}[t\in \mathcal{I}_{\text{future image}} \cup \mathcal{I}_{\text{future proprio}}] \] \[ M_{\text{value}}(t)=\mathbf{1}[t=i_v] \]

这意味着训练时没有新增一个独立 action head 或 value head；动作和值函数被改写为“需要被扩散模型去噪恢复的 latent frame”。

模型层改造

1. Action latent injection：RoboCasa 动作为 \(a\in\mathbb{R}^{32\times 7}\)，展平后只有 224 个数；而一个 latent frame 约为 \(16\times 28\times 28=12544\) 个数。本地实现通过重复填充算子 \(R\) 将动作放大到 latent frame：

\[ R(a) = \operatorname{reshape}\left( \operatorname{tile}(\operatorname{vec}(a)), C'H'W' \right) \]

再替换指定 action frame：

\[ x_0[:, :, i_a, :, :] \leftarrow R(a) \]

这就是“action-as-latent-frame”的工程实现。由于动作信息密度远低于图像 latent，本地配置使用 action_loss_multiplier=16，相当于把 action frame 的 mask 权重放大：

\[ M_{\text{policy}}(i_a) \leftarrow 16\cdot M_{\text{policy}}(i_a) \]

2. Frame Replace conditioning：当前观测帧不是只通过 cross-attention 输入，而是直接替换进 noisy latent。若 \(C\) 是条件 mask，则 DiT 实际看到的输入为：

\[ \tilde{x}_\sigma = C\odot x_{\text{cond}} + (1-C)\odot (x_0+\sigma\epsilon) \]

这保证条件帧在所有去噪步保持物理一致，避免模型把当前机器人位置或场景布局“改写掉”。

3. Hybrid sigma sampling：本地实现的 HybridEDMSDE 把 log-normal 噪声采样与 uniform 高噪声采样混合。config 中存在 high_sigma_ratio=0.05 字段，但当前 run 的 use_high_sigma_strategy 为 false；因此可以确认启用的是 hybrid sigma distribution，不能把 5% high-sigma strategy 写成当前已启用。它的效果是让模型同时覆盖细节修复区间和从条件帧想象未来的高噪声区间。

4. 小范围 processor/tokenizer 适配：远端仓库状态显示 liyichen/cosmos-predict2.5 在 tokenizer/processor 侧有 7 行本地改动。结合报告内证据，更大的训练逻辑改造主要落在 cosmos_policy 数据集、mask、latent injection 与 loss 计算，而非重写 Predict2.5 主干 DiT。

训练方式：从基础 checkpoint 到 RoboCasa finetune

训练从 Cosmos Predict2.5 2B 视频生成 checkpoint iter_000023000 初始化，在 RoboCasa-Cosmos-Policy 数据上进行后训练。关键配置是：FusedAdamW、学习率 \(2\times10^{-4}\)、warmup 1000 steps 后线性衰减、bfloat16、FSDP、batch size 25、chunk size 32、梯度裁剪 0.1。

def local_cosmos_finetune_loop(loader, model, optimizer):
    for batch in loader:
        # A. 数据层：拼装统一 latent 序列
        x0, indices = build_robocasa_latent_sequence(batch)

        # B. 任务层：根据 demo/rollout 随机选择 policy/world/value mask
        mode = sample_mode(batch.is_rollout, p_world_model=0.5)
        mask = build_loss_mask(mode, indices)

        # C. 噪声层：HybridEDMSDE；当前 run 未启用 high_sigma_strategy
        sigma = hybrid_edm_sde.sample_t(batch_size=len(batch))
        if config.use_high_sigma_strategy:
            sigma = maybe_replace_with_high_sigma(sigma, ratio=config.high_sigma_ratio)
        xt = x0 + sigma * torch.randn_like(x0)

        # D. 条件层：Frame Replace 当前观测
        xt = frame_replace(xt, batch.condition_latents, batch.condition_mask)

        # E. 模型层：DiT + EDM preconditioning
        x0_pred = model.denoise(xt, sigma, batch.t5_embedding, batch.condition_mask)

        # F. 损失层：只在目标帧上计算，动作帧乘以 16
        mask = apply_action_multiplier(mask, indices.action_idx, multiplier=16)
        loss = (edm_weight(sigma) * ((x0_pred - x0) ** 2) * mask).mean()

        optimizer.zero_grad()
        loss.backward()
        clip_grad_norm_(model.parameters(), 0.1)
        optimizer.step()

训练过程中遇到的关键工程问题是 DataLoader 多进程与 CUDA/pinned memory 的冲突。最终配置改为 num_workers=1, pin_memory=False，这属于“牺牲部分吞吐，换取稳定落盘”的选择。

  1. 动作信号稀释：224 维动作重复填充到 12544 维 latent frame，可能导致 denoising loss 与真实 action error 不完全一致。
  2. 多任务梯度竞争：policy/world/value 共享 DiT，mask 能隔离 loss 位置，但不能完全避免参数层面的表示冲突。
  3. 训练 loss 与控制质量脱节：低 denoising loss 不必然对应高 success rate，需要 RoboCasa/LIBERO 多 episode 评估闭环。
  4. 高噪声采样权衡：高 \(\sigma\) 有助于全局未来生成，但可能降低动作帧低噪声精修能力，需要 action error ablation。

VGG-T-Omega Action Regression：3D 几何先验注入

设计思想

Cosmos Policy 的一个潜在弱点是：它在 2D 潜在空间中预测动作，缺乏显式的 3D 几何理解。VGG-T-Omega Action Regression 分支试图通过引入预训练的 3D 视觉几何先验来弥补这一不足。

边界澄清：这里所谓“在 VGGT-Omega backbone 上加 action regression heads”，不是改写 VGGT-Omega 的 aggregator 主干，也不是 Cosmos Policy 的主模型架构改造；更准确地说，是把公开/预训练的 VGGT-Omega 视觉几何模型冻结为特征提取器，然后在它输出的 camera token 上新增机器人动作回归头，用来做一个 3D 几何先验驱动的动作预测 baseline。

架构设计

# scripts/train_vggt_action_regression.py 文档字符串
"""
Architecture (mirrors DA3 action regression):
  - VGGT-Omega Aggregator backbone (frozen) — alternating frame/inter-frame attention
  - CameraHead trunk (4-layer self-attention) — pretrained from pose estimation
  - Per-wrist action heads — new, regresses action chunks from camera tokens

Pretrained weight reuse:
  - aggregator: full pretrained weights (frozen)
  - trunk_left / trunk_right: initialized from CameraHead.trunk
  - token_norm / trunk_norm: initialized from CameraHead norms

View layout with num_history=2, num_context_views=1:
  image shape: (B, 6, 3, H, W)
  views:       [left_t0, left_t1, right_t0, right_t1, base_t0, base_t1]
  left  → camera_tokens[:, 0:2] → trunk_left → head_left → action[0:8]
  right → camera_tokens[:, 2:4] → trunk_right → head_right → action[8:16]
"""

具体改造了什么

模块来源是否训练作用是否本地改造
aggregatorVGGT-Omega VGGTOmega(...).aggregator冻结，requires_grad=False从多视角/多时刻图像中提取 camera token；保留原模型的几何时空注意力能力。不是新增架构，只是复用公开/预训练 backbone。
trunk_left / trunk_right从 VGGT-Omega CameraHead.trunk 初始化的 4 层 self-attention训练分别处理左腕、右腕的 camera token 序列，把“相机位姿估计”的中间能力迁移到动作估计。本地复制为左右腕两套 trunk，是动作回归适配的一部分。
token_norm_* / trunk_norm_*从 CameraHead norm 权重初始化训练稳定 camera token 和 trunk 输出的尺度。本地复用/分叉成左右腕 norm。
state_enc新增 MLP训练把机器人当前状态 \(s_t\in\mathbb{R}^{d_s}\) 编码到与视觉特征同维的空间。本地新增。
head_left / head_right新增 MLP heads训练分别预测左腕与右腕动作 chunk，例如 action[0:8] 和 action[8:16]。本地新增，是这条线真正的“action regression head”。

若输入图像为 \(I\in\mathbb{R}^{B\times V\times 3\times H\times W}\)，其中 \(V=(2+C)T\)，\(T\) 是历史帧数，\(C\) 是上下文视角数，则脚本中的默认例子是：

\[ I = [I^L_{t_0}, I^L_{t_1}, I^R_{t_0}, I^R_{t_1}, I^B_{t_0}, I^B_{t_1}] \]

左腕、右腕和 base 视角一起送进 frozen aggregator；base 视角不直接输出动作，但参与 backbone 的 inter-frame/inter-view attention，帮助 camera token 获得场景几何上下文。最后只取最后一层 token 的第 0 个 camera token：

\[ F=\operatorname{Aggregator}_{\text{frozen}}(I),\quad c_v=F_{\text{last}}[:,v,0,:] \]

再将左右腕 token 分开：

\[ C_L=[c_0,\ldots,c_{T-1}],\quad C_R=[c_T,\ldots,c_{2T-1}] \]

经过左右腕 trunk 和状态编码后预测动作：

\[ h_L=\operatorname{Trunk}_L(\operatorname{LN}(C_L)),\quad h_R=\operatorname{Trunk}_R(\operatorname{LN}(C_R)),\quad e_s=\operatorname{MLP}_{state}(s_t) \] \[ \hat{a}^{L}_{t:t+H-1}=\operatorname{Head}_L([h_L,e_s]),\quad \hat{a}^{R}_{t:t+H-1}=\operatorname{Head}_R([h_R,e_s]) \]

最后把左右腕预测填回完整动作张量：

\[ \hat{a}_{:,:,0:8}\leftarrow \hat{a}^{L},\quad \hat{a}_{:,:,8:16}\leftarrow \hat{a}^{R},\quad \hat{a}\in\mathbb{R}^{B\times H\times d_a} \]

训练方式

这条线不是扩散去噪训练，而是直接监督回归。脚本复用 OpenPI 的数据配置和 DA3 的 DA3ActionDataCollator，从 batch 中取 image、state、actions，将动作裁剪/补齐到 action_horizon，再用 masked MSE 训练新增头和左右 trunk：

\[ \mathcal{L}_{action} = \frac{ \sum_{b,t,k} m_{btk}\left(\hat{a}_{btk}-a_{btk}\right)^2 }{ \sum_{b,t,k}m_{btk} } \]

其中 \(m_{btk}=\mathbf{1}[|a_{btk}|<10]\)，并且训练前会把动作裁剪到 \([-5,5]\)，避免异常动作值主导损失。checkpoint 保存时也只保存非 aggregator 的 trainable state，即新增动作分支、左右 trunk/norm、state encoder 和 optimizer/EMA，而不重复保存 frozen backbone。

def vggt_action_regression_step(batch, model, optimizer):
    image = batch["image"]      # (B, (2+C)*T, 3, H, W)
    state = batch["state"]      # (B, state_dim)
    actions = batch["actions"]  # (B, horizon, action_dim)

    # Frozen VGGT-Omega aggregator extracts camera tokens under no_grad.
    pred = model(image, state)

    valid = (actions.abs() < 10.0).float()
    target = actions.clamp(-5.0, 5.0)
    loss = ((pred - target) ** 2 * valid).sum() / valid.sum().clamp(min=1.0)

    optimizer.zero_grad()
    loss.backward()
    clip_grad_norm_(trainable_parameters(model), max_norm=1.0)
    optimizer.step()

直观上，这条线等价于问一个问题：如果 VGGT-Omega 已经从多视角历史图像里学到了相机几何、物体位姿和运动线索，那么仅训练很小的动作 head，能否把这种几何线索转成机器人左右腕未来 \(H\) 步动作？

关键设计 Trade-off

1. Latent Injection vs. Separate Head

将动作编码为潜在帧（而非通过独立 MLP head 预测）的优势是复用了扩散模型的全部生成能力，但代价是动作信号被"稀释"在高维潜在空间中（7×32=224 维 action 填充到 12544 维潜在帧），需要 action_loss_multiplier=16 来补偿。

2. Multi-Objective 统一训练 vs. 分阶段训练

Cosmos Policy 选择在同一个 batch 内混合 policy/world model/value function 三种目标。优势是共享表征、减少训练成本；风险是不同目标之间可能存在梯度冲突。当前通过 mask 机制确保每个样本只对一种目标计算 loss，避免了显式的多任务梯度冲突。

3. Hybrid Sigma Distribution 的必要性

标准 log-normal 采样在中等噪声区间更集中，但视频条件生成需要模型同时覆盖低噪声细节修复和高噪声未来想象。当前 evidence 可确认启用了 hybrid_sigma_distribution=True 的混合噪声采样；虽然配置里存在 high_sigma_ratio=0.05 字段，但当前 run 的 use_high_sigma_strategy=false，因此不能把额外 high-sigma strategy 写成已启用。

4. Frame Replace vs. Cross-Attention Conditioning

Frame Replace 直接将条件帧"放入"噪声输入中，比 cross-attention 更强地约束了生成结果与条件帧的一致性。这对机器人场景至关重要——生成的未来帧必须与当前观测在物理上连续。
